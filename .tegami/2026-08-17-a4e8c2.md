## Switch the HTTP layer to better-call and Zod

Server routes and plugins now use `createS3Endpoint` (better-call) with Zod
schemas. `s3.api` is the endpoint map — call
`s3.api.download({ query: { key }, headers })` instead of
`s3.api.download(key, { headers })`. Plugin paths are absolute under
`basePath` (`/db/objects`, not `plugins/db/objects`). Client plugins use
`getActions($fetch)` and `pluginPath` in place of `createMethods` /
`createFetcher` / `pluginEndpointPath`. The Next.js adapter also exports
`PUT` and `PATCH`. Browser `createS3Client()` still returns named `S3Api`
(`api.download(key)`).

`DimahS3Error` now extends better-call `APIError`, so HTTP error JSON is
the native `{ message, code?, params? }` body. Direct `s3.api` calls throw
the same class (including Zod `VALIDATION_ERROR`). The browser client uses
better-fetch `throw: true` with `s3FetchErrorSchema` and maps non-OK
responses onto `DimahS3Error`.
