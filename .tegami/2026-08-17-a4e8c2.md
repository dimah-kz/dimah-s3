## Switch the HTTP layer to better-call and Zod

Server routes and plugins now use `createS3Endpoint` (better-call) with Zod
schemas. `s3.api` is the endpoint map — call
`s3.api.download({ query: { key }, headers })` instead of
`s3.api.download(key, { headers })`. Plugin paths are absolute under
`basePath` (`/db/objects`, not `plugins/db/objects`). Client plugins use
`getActions($fetch)` and `pluginPath` in place of `createMethods` /
`createFetcher` / `pluginEndpointPath`. The Next.js adapter also exports
`PUT` and `PATCH`. Browser `createS3Client()` still returns named `S3Api`
(`api.download(key)`).

`DimahS3Error` now extends better-call `APIError` with the same
`(status, body)` constructor (`DimahS3Error.from("FORBIDDEN",
S3_ERROR_CODES.FORBIDDEN)`). HTTP error JSON is the native
`{ message, code?, params? }` body. Detect errors with `isAPIError` /
`isDimahS3Error`. Direct `s3.api` calls throw the same class (including Zod
`VALIDATION_ERROR`). The browser client uses better-fetch `throw: true` with
`s3FetchErrorSchema`, maps non-OK responses onto `DimahS3Error` (including
`code` and `params` for client i18n), and exposes `$ERROR_CODES`. Upload XHR
failures stay `S3UploadError`; protocol errors keep their original `code`.
