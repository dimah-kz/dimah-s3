## Harden keys, sessions, and upload cancellation

Stored keys are validated on the wire (no `..` segments, S3 part numbers
1–10000, strict query objects). Routes with overlapping `keyPrefix` values
are rejected at init so one route cannot follow-up into another.

Multipart complete now runs `sessionGuard` (`action: "complete"`) before
`confirmGuard`. The `db()` plugin confirms pending rows only, binds
abort/part/complete to the pending `uploadId`, and lists `active` objects
by default. Soft-deleted keys no longer block another scope from reusing
that key.

React upload retry no longer re-presigns after bytes have landed. Cancel
aborts the in-flight run instead of marking a cancelled batch as success,
and a second `upload()` / `download()` / `confirmDelete()` no longer races
the previous request.
