## Named file routes

`dimahS3()` is route-only. Pass a `routes` map of `route()` policies; empty
or missing `routes` throws. The instance holds shared defaults (`client`,
`bucket`, `plugins`, optional `guard`). Each route nests `upload` /
`download` / `delete`. Multipart is opt-in under `upload.multipart`.
A route may override `client`, `bucket`, or `keyPrefix`.

The client sends a `route` name on every request. Unknown names return
`UNKNOWN_ROUTE`. Upload and multipart init no longer accept `key` — the
server generates it from `upload.object` (or `${routeName}/…`). Later
ops send the stored `key` with the same route.

Hooks and UI require `route`: `useUpload({ route: "uploads" })`,
`<UploadButton route="uploads" />`. Upload hooks no longer take
`objectKey`.

### Route config

```ts
uploads: route({
  upload: {
    fileTypes: ["image/*"],
    maxFileSize: 10 * 1024 * 1024,
  },
  download: true,
  delete: true,
});
```

- `fileTypes`, `maxFileSize`, `acl`, `method`, `expiresIn`, and
  `multipart` live on `upload`. Init and complete reuse `upload.guard` /
  `confirmGuard` / `onConfirmed`. Unique hooks are `upload.multipart.onInit`,
  `.sessionGuard` (part / list / abort), `.onAbort`, and `.onList`.
- `object({ file, request, clientMetadata })` returns
  `{ prefix?, key?, metadata?, acl? }`. Keys are nested under route
  `keyPrefix` (default: the route name). Default key is
  `{keyPrefix}/{uuid}/{name}`. Confirm / download / delete / multipart
  follow-ups reject keys outside that prefix. `keyPrefix: false` disables
  the bound. Client `metadata` is not written to S3 unless `object`
  copies it.
- `upload.object` maps a plain `Error` to 403, same as `guard`.
- Multipart `signPart` requires `partSize` (locked into `Content-Length`).
  When `maxFileSize` is set, signPart lists uploaded parts and rejects a
  part that would exceed the cap. Complete sums listed part sizes and
  aborts the MPU before assembly if over.
- `fileTypes` matches the S3 `Content-Type` header and filename, not file
  bytes. Persist size from `onConfirmed` (`contentLength`), not the
  presign body. Without `db()`, download can presign unconfirmed keys
  under `keyPrefix`; `db()` download requires status `active`.
- Standalone `prefix` / `KeyPrefix` and `resolveKey` are removed.
- Resolved routes keep `fileTypes`, `maxFileSize`, `object`,
  `acl`, `method`, and `expiresIn` on `upload` only — they are not copied
  onto the route root.

### Naming (aligned with the three features)

- `ResolvedRoute` is the normalized named route (was `ResolvedRoutePolicy`).
- `RouteFeature` is `upload` | `download` | `delete`. `RouteOperation`
  adds `multipart` (nested under upload). These replace `FeatureName` /
  `FeatureFlag`.
- Guard contexts match the hook names: `UploadGuardContext`,
  `DownloadGuardContext`, `DeleteGuardContext` (no leftover `Presign` in
  the guard type). `upload.object` uses `UploadObjectContext` /
  `UploadObjectInfo`. Confirm / download / delete / multipart session
  hooks share `StoredObjectContext` once a key is assigned.
- React engine options are `FileUploadConfig` / `MultiFileUploadConfig`
  so they do not collide with server `UploadConfig`.
- Disabled features are a discriminated `{ enabled: false }` — hook
  fields exist only when the feature is on. `OpenedRoute<"upload">`
  types `route.upload` as enabled.
- Plugin `init` reads user toggles with `isFeatureOn(route.upload, true)`
  (upload defaults on; download / delete default off).

Resolved routes always include `upload`, `download`, `delete`, and
`upload.multipart`, each with `enabled`. Plugin hooks merge only onto
features that are on for that route.

### Removed from the client

- `key` on upload and multipart init
- `bucket`, `acl`, and `expiresIn` on request payloads
- `allowClientBucket`, `buckets`, `allowClientAcl`
- `requireFileSize`
- Public React `multipartThreshold` / `partSize`
- `defaultObjectKey` (the server generates upload keys)
- `INVALID_BUCKET` / `errors.invalidBucket` (the client cannot pick a
  bucket)

TTL is `upload.expiresIn` for upload and multipart part URLs, and
`download.expiresIn` for download. Each falls back to the protocol
default (600s) independently. Both are clamped by instance
`maxExpiresIn`. File constraints are checked at presign, on each
multipart part, and again after HeadObject (`FILE_TYPE_NOT_ALLOWED`,
`PAYLOAD_TOO_LARGE`).

### Route rewrite hardening

- `useFileUpload().reset()` no longer fires `onCancel`. Cancel during
  `beforeUpload` now aborts instead of continuing the upload.
- Generated keys take the filename leaf only (`../secret.png` →
  `…/{uuid}/secret.png`) so a crafted name cannot fail `INVALID_KEY` or
  nest extra folders.
- POST presign rejects bodies over S3's 5 GiB POST limit. `fileSize` /
  `partSize` must be integers. Duplicate multipart complete part numbers
  are ignored.
- Plugin `init` runs after routes validate, so an empty `routes` map
  throws the route error instead of a plugin message. `isFeatureOn`
  understands resolved `{ enabled: false }` objects.
