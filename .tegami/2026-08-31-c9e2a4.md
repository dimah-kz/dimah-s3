## Named file routes

`dimahS3()` is route-only. Pass a `routes` map of `route()` policies; empty
or missing `routes` throws. The instance holds shared defaults (`client`,
`bucket`, `plugins`, optional `guard`). Each route nests `upload` /
`download` / `delete`. Multipart is opt-in under `upload.multipart`.
A route may override `client`, `bucket`, or `keyPrefix`.

The client sends a `route` name on every request. Unknown names return
`UNKNOWN_ROUTE`. Upload and multipart init no longer accept `key` — the
server generates it from `upload.object` (or `${routeName}/…`). Later
ops send the stored `key` with the same route.

Hooks and UI require `route`: `useUpload({ route: "uploads" })`,
`<UploadButton route="uploads" />`. Upload hooks no longer take
`objectKey`.

### Route config

```ts
uploads: route({
  upload: {
    fileTypes: ["image/*"],
    maxFileSize: 10 * 1024 * 1024,
  },
  download: true,
  delete: true,
});
```

- `fileTypes`, `maxFileSize`, `acl`, `method`, `expiresIn`, and
  `multipart` live on `upload`. Init and complete reuse `upload.guard` /
  `confirmGuard` / `onConfirmed`. Unique hooks are `upload.multipart.onInit`,
  `.sessionGuard` (part / list / abort), `.onAbort`, and `.onList`.
- `object({ file, request, clientMetadata })` returns
  `{ prefix?, key?, metadata?, acl? }`. Keys are nested under route
  `keyPrefix` (default: the route name). Default key is
  `{keyPrefix}/{uuid}/{name}`. Confirm / download / delete / multipart
  follow-ups reject keys outside that prefix. `keyPrefix: false` disables
  the bound. Client `metadata` is not written to S3 unless `object`
  copies it.
- `upload.object` maps a plain `Error` to 403, same as `guard`.
- Multipart `signPart` requires `partSize` (locked into `Content-Length`).
  When `maxFileSize` is set, signPart lists uploaded parts and rejects a
  part that would exceed the cap. Complete sums listed part sizes and
  aborts the MPU before assembly if over.
- `fileTypes` matches the S3 `Content-Type` header and filename, not file
  bytes. Persist size from `onConfirmed` (`contentLength`), not the
  presign body. Without `db()`, download can presign unconfirmed keys
  under `keyPrefix`; `db()` download requires status `active`.
- Standalone `prefix` / `KeyPrefix` and `resolveKey` are removed.

### Removed from the client

- `key` on upload and multipart init
- `bucket`, `acl`, and `expiresIn` on request payloads
- `allowClientBucket`, `buckets`, `allowClientAcl`
- `requireFileSize`
- Public React `multipartThreshold` / `partSize`

TTL is `upload.expiresIn` (download may override), clamped by instance
`maxExpiresIn`. File constraints are checked at presign, on each
multipart part, and again after HeadObject (`FILE_TYPE_NOT_ALLOWED`,
`PAYLOAD_TOO_LARGE`).
