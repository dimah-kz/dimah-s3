Generate the models with the package's CLI. Generating does not connect to
the database, so the script only needs the provider:

```ts title="scripts/dimah-s3.ts"
import { DimahS3DB } from "@dimah-s3/db";
import { prismaAdapter } from "@dimah-s3/db/adapters/prisma";
import { runCli } from "@dimah-s3/db/cli";

await runCli(
  DimahS3DB.client(
    prismaAdapter({ prisma: undefined, provider: "postgresql" }), // or "sqlite" | "mysql"
  ),
);
```

```bash
npx tsx scripts/dimah-s3.ts generate latest -o prisma/schema/dimah-s3.prisma
npx prisma migrate dev --name dimah-s3
```

The file holds the models only, with no generator or datasource. Keep it in
a multi-file schema folder, or paste its models into `schema.prisma`. Keep
the model names `storageObject`, `storageFolder`, and
`private_dimah_s3_settings`: the adapter calls them by name. The models
declare the indexes and the MySQL prefix lengths, so the migration creates
them too. Run `generate` again after you upgrade `@dimah-s3/db`.

Prisma has no collation attribute. On MySQL, create the migration with
`--create-only` and add `COLLATE utf8mb4_bin` to the text columns, and
`COLLATE utf8mb4_unicode_ci` to `filename`, before you apply it. Without
that, keys compare by the database's default collation, which ignores case.
