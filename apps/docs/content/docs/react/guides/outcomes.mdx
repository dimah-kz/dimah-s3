---
title: Outcomes and errors
description: What hook actions return instead of throwing, the order callbacks run in, and how to read errors and aborts.
---

Hook actions do not throw for transfer errors. An action on one key resolves
with an **outcome**, and a batch action with a **result**. Read the status,
then the data or the error.

```ts
const outcome = await download(objectKey);

if (outcome.status === "error") {
  console.log(outcome.key, outcome.error.code);
}
```

## Outcomes

`remove`, `download`, and `presign` resolve with an outcome:

```ts
type OperationOutcome<TData> =
  | { status: "success"; key: string; data: TData }
  | { status: "error"; key: string; error: APIError }
  | { status: "blocked"; key: string }
  | { status: "aborted"; key: string };
```

| Status    | Means                                                                     |
| --------- | ------------------------------------------------------------------------- |
| `success` | `data` holds the response                                                 |
| `error`   | `error` is an `APIError`                                                  |
| `blocked` | A `before*` callback returned `false`                                     |
| `aborted` | The call was cancelled. A delete has no cancel, so it never ends this way |

## Results

Batch actions resolve with one result that sorts every unit:

| Action                    | Result                                                     |
| ------------------------- | ---------------------------------------------------------- |
| `useUpload().handleFiles` | `{ uploaded, failed, rejected, blocked, aborted }` by file |
| `useDelete().removeMany`  | `{ deleted, failed, blocked }` by key                      |

Each `failed` entry pairs the unit with its `APIError`, such as
`{ key, error }`. An upload's `rejected` entries are the files the policy
refused before upload, each as `{ file, errors }`.

## Joined calls

The download and delete hooks track each key on its own. A second call for a
running key starts no new request: it joins the running call, resolves with
the same outcome, and does not run the callbacks again.

## Callback order

Every hook runs its callbacks in the same order:

1. **`before*`** (`beforeUpload`, `beforeDownload`, `beforeDelete`) runs once per call. Returning `false` blocks the call. A throw fails it with `HOOK_FAILED`.
2. **`on*Start`** (`onUploadStart`, `onDownloadStart`, `onDeleteStart`) runs once per call. A throw fails it with `HOOK_FAILED`.
3. **`onError`** runs once per failed unit, then **`onSuccess`** once per successful unit.
4. **`onSettled`** runs once per call, last.

`onError`, `onSuccess`, and `onSettled` may be async and are awaited. They
are the callbacks of the newest render, so they see current state. If one
throws, the error goes to the global `reportError` and the outcome does not
change.

## Errors

Every error is an `APIError` from `@dimah-s3/core`:

| Property     | Description                                                                  |
| ------------ | ---------------------------------------------------------------------------- |
| `code`       | Always set and stable. Branch on it with `isS3ErrorCode(error, code)`        |
| `params`     | Values for the message, such as `{ size, maxFileSize }`                      |
| `statusCode` | The HTTP status                                                              |
| `message`    | English. Show users [`useFormatError()`](/docs/react/helpers#errors) instead |

```ts
import { isS3ErrorCode } from "@dimah-s3/core";

const { failed } = await upload.handleFiles(files);
for (const { file, error } of failed) {
  if (isS3ErrorCode(error, "FILE_TOO_LARGE")) {
    console.log(`${file.name} is too large`);
  }
}
```

Server codes come from the route and your hooks. These codes are raised in
the browser only:

| Code                | When                                                            |
| ------------------- | --------------------------------------------------------------- |
| `TOO_MANY_FILES`    | A call has more valid files than `maxFiles` or the upload limit |
| `HOOK_FAILED`       | A `before*`, `on*Start`, or `uploadOptions` function threw      |
| `NETWORK_ERROR`     | A request got no response                                       |
| `UPLOAD_FAILED`     | S3 rejected an upload. `params.status` is S3's status           |
| `CHECKSUM_MISMATCH` | S3 rejected the uploaded bytes for their checksum               |
| `DOWNLOAD_FAILED`   | A fetch download got a non-2xx response                         |
| `PARTIAL_FAILURE`   | `upload.error` when two or more files failed                    |
| `UNKNOWN_ERROR`     | Anything that is not an `APIError`. The original is `cause`     |

The full list is in [Errors](/docs/server/errors#client-codes).

## Aborts

A cancel is not an error. Hooks report it as an `aborted` outcome, or in the
`aborted` list of an upload result.

Engine functions such as `uploadFile` reject with the signal's reason
instead. Upload abort reasons are `DOMException`s named `AbortError`; read
which kind with `getUploadAbortKind`:

```ts
import { getUploadAbortKind } from "@dimah-s3/react/engine";

try {
  await uploadFile(api, file, options);
} catch (error) {
  const kind = getUploadAbortKind(error); // "cancel", "detach", or null
  if (kind === null) throw error;
}
```

See [Engine](/docs/react/guides/engine#cancel-and-detach).

## API Reference

### TransferProgress

Uploads and fetch downloads report progress in this shape.

| Property  | Type                  | Description                                    |
| --------- | --------------------- | ---------------------------------------------- |
| `loaded`  | `number`              | Bytes transferred so far                       |
| `total`   | `number`              | Total bytes to transfer                        |
| `percent` | `number`              | Progress from `0` to `100`                     |
| `speed`   | `number \| undefined` | Bytes per second. `undefined` until measurable |

### KeyError

A failed key in a batch result.

| Property | Type       | Description        |
| -------- | ---------- | ------------------ |
| `key`    | `string`   | The object key     |
| `error`  | `APIError` | Why the key failed |
