An `UploadStore` keeps `uploadId`, `key`, and `fileSize` so a multipart
upload can resume after refresh. Use it only with `multipart: true`.

Prefer `createLocalStorageStore()` for same-browser resume. Use a custom
store (for example DB-backed) for cross-device resume — see
[DB hooks](/docs/db/hooks).

[Upload Button](/docs/react/ui/components/upload-button) and
[Upload Dropzone](/docs/react/ui/components/upload-dropzone) take the same
`uploadStore` prop as the hooks.

## Quick setup

```ts title="lib/upload-store.ts"
import { createLocalStorageStore } from "@dimah-s3/react";

export const localStorageStore = createLocalStorageStore();
```

```tsx title="app/uploader.tsx"
"use client";

import { useUpload } from "@dimah-s3/react";
import { localStorageStore } from "@/lib/upload-store";

export function Uploader() {
  const { getRootProps, getInputProps, isUploading } = useUpload({
    objectKey: "uploads/photo.jpg",
    multipart: true,
    uploadStore: localStorageStore,
  });

  return (
    <div {...getRootProps()}>
      <input {...getInputProps()} />
      {isUploading ? "Uploading…" : "Drop a file or click to upload"}
    </div>
  );
}
```

`objectKey` must stay the same across retries, or resume cannot match the
stored upload.

## Built-in stores

- `createLocalStorageStore()` — survives refresh and reopen
- `createMemoryStore()` — in-memory; useful for SSR and tests

```ts
import { createMemoryStore } from "@dimah-s3/react";

const uploadStore = createMemoryStore();
```

## DB-backed store

With [`@dimah-s3/db`](/docs/db) multipart hooks, `onInit` already writes
`uploadId` on the pending row. The client store only needs `get` —
`set` / `delete` can be no-ops. Server half: [DB hooks](/docs/db/hooks).

```ts title="lib/upload-store-db.ts"
import type { StoredUpload, UploadStore } from "@dimah-s3/react";

export const uploadStoreDb: UploadStore = {
  async get(key, fileSize) {
    const res = await fetch(
      `/api/upload-store?key=${encodeURIComponent(key)}&fileSize=${fileSize}`,
    );
    if (!res.ok) return null;
    return (await res.json()) as StoredUpload | null;
  },
  async set() {},
  async delete() {},
};
```

The store recovers `uploadId`. The browser still needs the same `File`
bytes. Skip `uploadStore` for small or one-shot uploads.
