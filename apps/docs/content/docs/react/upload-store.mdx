An `UploadStore` keeps what a multipart upload needs to resume, but not the
`File`. After a reload, the user selects the same local file and the upload
continues from the parts S3 already has.

```ts title="lib/upload-store.ts"
import { createLocalStorageUploadStore } from "@dimah-s3/react/engine";

export const uploadStore = createLocalStorageUploadStore();
```

```tsx title="app/video-uploader.tsx"
"use client";

import { useUpload } from "@dimah-s3/react";
import { uploadStore } from "@/lib/upload-store";

export function VideoUploader() {
  const upload = useUpload({ route: "video", uploadStore });

  return (
    <div {...upload.getRootProps()}>
      <input {...upload.getInputProps()} />
      {upload.isPending
        ? `Uploading: ${upload.progress.percent}%`
        : "Upload a large video"}
    </div>
  );
}
```

Only multipart uploads are stored: the route must allow multipart, and the
file must be at least 50 MiB (`DEFAULT_MULTIPART_THRESHOLD`). Smaller files
upload in one request and are never stored.

## How resume works

1. After `multipart.init`, the engine saves a `StoredUpload` before it sends any part.
2. `detach()`, a closed tab, or an unmount stops the upload but keeps the record and the server session.
3. When the same file is selected again, the engine finds the record, lists the parts already uploaded, and sends only the rest.
4. Once the upload completes or is cancelled, the record is deleted.

A retryable error keeps the record, and any other error deletes it; see
[Cancel, detach, and unmount](/docs/react/hooks/upload#cancel-detach-and-unmount).
If the ticket has expired or the server no longer knows the upload, the
engine aborts it, deletes the record, and starts over.

### Which file resumes

The record is looked up by `multipartResumeKey`: the route, the file's name,
size, and last-modified time, plus the request's `fileName`, `contentType`,
and `clientMetadata`. A file resumes only with the same request options, so it
never completes into another folder.

## Built-in stores

Both ship from `@dimah-s3/react/engine`:

| Store                             | Keeps records                     | Notes                                                                                   |
| --------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------- |
| `createLocalStorageUploadStore()` | In `localStorage`, across reloads | Does nothing when `localStorage` is unavailable: SSR, private browsing, or a full quota |
| `createMemoryUploadStore()`       | In memory, for the page session   | Safe for SSR and tests                                                                  |

## Custom store

Implement `UploadStore` to keep records anywhere else, such as IndexedDB or
your own API:

```ts title="lib/upload-store.ts"
import type { UploadStore } from "@dimah-s3/react/engine";

export const apiStore: UploadStore = {
  async get(resumeKey, fileSize) {
    const res = await fetch(`/api/uploads/${encodeURIComponent(resumeKey)}`);
    if (!res.ok) return null;
    const upload = await res.json();
    return upload.fileSize === fileSize ? upload : null;
  },
  async set(upload) {
    await fetch(`/api/uploads/${encodeURIComponent(upload.resumeKey)}`, {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(upload),
    });
  },
  async delete(resumeKey) {
    await fetch(`/api/uploads/${encodeURIComponent(resumeKey)}`, {
      method: "DELETE",
    });
  },
};
```

A store that throws never fails the upload: the error goes to the global
`reportError`, and a failed `get` counts as no record.

## API Reference

### UploadStore

| Method                     | Returns                                    | Description                                                     |
| -------------------------- | ------------------------------------------ | --------------------------------------------------------------- |
| `get(resumeKey, fileSize)` | `StoredUpload \| null`, or a promise of it | The pending upload for this resume key and file size            |
| `set(upload)`              | `void`, or a promise                       | Saves an upload after `multipart.init`, before any part is sent |
| `delete(resumeKey)`        | `void`, or a promise                       | Removes an upload. Does nothing when the key is unknown         |

### StoredUpload

| Property    | Type      | Description                                                              |
| ----------- | --------- | ------------------------------------------------------------------------ |
| `resumeKey` | `string`  | Resume identity from `multipartResumeKey`                                |
| `ticket`    | `string`  | Upload ticket from `multipart.init`. Every later multipart call sends it |
| `key`       | `string`  | Object key the server generated                                          |
| `uploadId`  | `string`  | S3 multipart `UploadId`                                                  |
| `fileSize`  | `number`  | Total file size in bytes, so a different file never resumes              |
| `partSize`  | `number`  | Part size the server chose, in bytes                                     |
| `partCount` | `number`  | Number of parts the server chose                                         |
| `checksum`  | `boolean` | Every part must send a SHA-256                                           |

## Frequently asked questions

<Accordions>

<Accordion title="Does @dimah-s3/db replace an upload store?">

No. [`@dimah-s3/db`](/docs/db) tracks pending uploads on the server. An
`UploadStore` maps a browser-side resume key to the ticket and upload id. Use
`createLocalStorageUploadStore()` for reloads in the same browser, or a
custom store for other devices. Either way, the user must select the same
local file.
