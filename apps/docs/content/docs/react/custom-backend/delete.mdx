---
title: Delete
description: Delete one object, or up to 100 per request, through a custom backend.
---

Deleting is a request to your backend, not a presigned transfer. Delete is
idempotent: a key that does not exist still succeeds.

```ts title="lib/s3-api/delete.ts"
import type {
  DeleteManyPayload,
  DeleteManyResponse,
  DeletePayload,
  DeleteResponse,
  S3RequestOptions,
} from "@dimah-s3/core";
import { $fetch, call } from "./fetch";

export const deleteObject = (
  payload: DeletePayload,
  options?: S3RequestOptions,
) =>
  $fetch<DeleteResponse>("/delete", {
    method: "DELETE",
    query: payload,
    ...call(options),
  });

export const deleteMany = (
  payload: DeleteManyPayload,
  options?: S3RequestOptions,
) =>
  $fetch<DeleteManyResponse>("/delete/batch", {
    method: "POST",
    body: payload,
    ...call(options),
  });
```

[`@dimah-s3/server`](/docs/server) uses `DELETE /api/s3/delete?route=…&key=…`
and `POST /api/s3/delete/batch`. `$fetch` and `call` come from the
[skeleton](/docs/react/custom-backend#skeleton).

## Delete one

`delete` receives `{ route, key }` and returns `{ key, bucket }`.

| Property | Type     | Description   |
| -------- | -------- | ------------- |
| `key`    | `string` | Object key    |
| `bucket` | `string` | Target bucket |

## Delete many

`deleteMany` receives one `route` and `keys`: between 1 and 100 keys
(`DELETE_MANY_MAX_KEYS`). `useDelete` splits larger calls into batches of that
size.

Delete each key on its own. Put it in `deleted`, or in `failed` with an error
body. A key you leave out of both fails with `UNKNOWN_ERROR`.

| Property  | Type                                           | Description                               |
| --------- | ---------------------------------------------- | ----------------------------------------- |
| `deleted` | `string[]`                                     | Keys that were deleted                    |
| `failed`  | `{ key, error: { code, message, params? } }[]` | Keys that failed, each with an error body |
