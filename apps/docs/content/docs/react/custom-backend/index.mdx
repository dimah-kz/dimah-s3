title: Bring Your Own Backend
description: Implement the complete S3Api contract for an existing backend, so the React hooks and UI run against your own endpoints.
---

Implement `S3Api` when your backend is not
[`@dimah-s3/server`](/docs/server). `defineApi` from `@dimah-s3/react/engine`
type-checks the object and returns it unchanged. Your routes, transport, and
server framework are up to you.

## Contract

- **Every method takes `(payload, options?)`.** `options` is `{ signal, headers }`. Forward `signal` to your request so cancel reaches it.
- **Every method is required**, and so is every required response field. Optional fields may be left out.
- **Every object call names a `route`.** `catalog()` is the exception. Upload and multipart init send no `key`: your backend picks it and returns it.
- **Issue a ticket.** `upload` and `multipart.init` return a `ticket`. `confirm` and every later multipart call send only the ticket (plus the part number when signing), so it must tell your backend the route, key, and upload id. Sign it, or store it server side. It may be up to 8192 characters.
- **Throw an `APIError`** with a [catalog code](/docs/server/errors). A throw that is not an `APIError` becomes `UNKNOWN_ERROR`, which is not retried.
- **Make `confirm` and `multipart.complete` safe to call twice.** The hooks retry `NETWORK_ERROR`, `S3_NETWORK_ERROR`, and any error whose status is 408, 429, or 500 and above.
- **Trust `HeadObject`, not the client.** Confirm and complete return the size and type S3 reports, not what the browser declared.

Payload and response types are exported from `@dimah-s3/core`.

## Flows

| Flow           | Methods                                                             | Page                                              |
| -------------- | ------------------------------------------------------------------- | ------------------------------------------------- |
| Route policies | `catalog`                                                           | [Route catalog](#route-catalog)                   |
| Simple upload  | `upload` → browser uploads to S3 → `confirm`                        | [Upload](/docs/react/custom-backend/upload)       |
| Download       | `download`                                                          | [Download](/docs/react/custom-backend/download)   |
| Delete         | `delete` or `deleteMany`                                            | [Delete](/docs/react/custom-backend/delete)       |
| Multipart      | `init` → `signPart` → `complete` or `abort` · `listParts` to resume | [Multipart](/docs/react/custom-backend/multipart) |

## Skeleton

`createS3Fetch` from `@dimah-s3/core` gives you a fetcher with the error rules
above: a `{ code, message, params? }` body becomes an `APIError` with that
code and status, a failed request becomes `NETWORK_ERROR`, and an aborted
signal rethrows its reason. `call` forwards the per-call signal and headers:

```ts title="lib/s3-api/fetch.ts"
import { createS3Fetch, type S3RequestOptions } from "@dimah-s3/core";

export const $fetch = createS3Fetch("/api/files");

/** Per-call signal and headers for `$fetch`. */
export const call = (options?: S3RequestOptions) => ({
  signal: options?.signal,
  headers: options?.headers ? new Headers(options.headers) : undefined,
});
```

Combine the methods from each page in one `defineApi` call:

```ts title="lib/s3-api/index.ts"
import { defineApi } from "@dimah-s3/react/engine";
import { catalog } from "./catalog";
import { deleteMany, deleteObject } from "./delete";
import { download } from "./download";
import { abort, complete, init, listParts, signPart } from "./multipart";
import { confirm, upload } from "./upload";

export const api = defineApi({
  upload,
  confirm,
  download,
  catalog,
  delete: deleteObject,
  deleteMany,
  multipart: { init, signPart, listParts, complete, abort },
});
```

Response shapes must match the [core `S3Api` protocol](/docs/core). Pass the
result to `S3Provider` in place of the [Setup](/docs/react/setup) client:

```tsx title="components/s3-provider.tsx"
"use client";

import { S3Provider } from "@dimah-s3/react";
import { api } from "@/lib/s3-api";

export function AppS3Provider({ children }: { children: React.ReactNode }) {
  return <S3Provider api={api}>{children}</S3Provider>;
}
```

## Route catalog

`catalog()` returns, for every named route, which operations are on and the
upload policy. `useUpload` checks files against it before it presigns. If it
fails, every file of that call fails with its error.

```ts title="lib/s3-api/catalog.ts"
import type { RouteCatalogResponse, S3RequestOptions } from "@dimah-s3/core";
import { $fetch, call } from "./fetch";

export const catalog = (options?: S3RequestOptions) =>
  $fetch<RouteCatalogResponse>("/routes", { method: "GET", ...call(options) });
```

The response is `{ routes: Record<routeName, RouteCatalogEntry> }`. Each
entry has `upload`, `download`, and `delete`. When `enabled` is `false`, that
operation has no other field.

| Field                   | Type                       | Description                                                 |
| ----------------------- | -------------------------- | ----------------------------------------------------------- |
| `upload.enabled`        | `boolean`                  | Uploads are on for this route                               |
| `upload.fileTypes?`     | `string[]`                 | Accepted MIME types and extensions. Omit to accept any type |
| `upload.maxFileSize?`   | `number`                   | Max bytes                                                   |
| `upload.multipart`      | `boolean`                  | Large files go through multipart                            |
| `upload.checksum`       | `boolean`                  | Single-shot uploads send a SHA-256                          |
| `download.enabled`      | `boolean`                  | Downloads are on for this route                             |
| `download.maxExpiresIn` | `number`                   | Longest URL lifetime in seconds, at most `604800`           |
| `download.disposition`  | `"inline" \| "attachment"` | Default `Content-Disposition`                               |
| `download.inlineTypes`  | `string[]`                 | Types that may open inline                                  |
| `download.mode`         | `"presign" \| "proxy"`     | Signed S3 URLs, or a same-origin URL your backend streams   |
| `delete.enabled`        | `boolean`                  | Deletes are on for this route                               |

## Upload transport

The browser sends single-shot uploads to `presign.url` itself. To replace that
transfer, for example with an in-memory backend in tests, add
`uploadTransport` to the object you pass `defineApi`:

```ts
uploadTransport: (file, presign, { onProgress, signal }) => Promise<void>;
```

- Send `presign.fields` or `presign.headers` exactly.
- Report progress through `onProgress`, and stop when `signal` aborts.
- Reject with an `APIError` so the engine can retry: `UPLOAD_FAILED` with S3's status as `params.status`, `CHECKSUM_MISMATCH` when S3 rejects the bytes' checksum (never retried), or `NETWORK_ERROR`.

Multipart parts do not use it.
