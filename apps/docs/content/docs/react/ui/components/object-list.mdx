import { ObjectListDemo } from "@/components/demos/object-list-demo";

`ObjectList` renders a folder catalog. Pass the object returned by
[`useObjectList`](/docs/react/hooks/object-list) as `list`. The component
does not fetch and does not call the hooks you give it.

## Preview

<DemoPreview name="object-list-demo.tsx">
  <ObjectListDemo />
</DemoPreview>

The preview lists records in memory with `memoryObjectSource`. Six files
load at a time. Search, sort, switch to the grid, select rows with
Shift-click or Ctrl+A, or drop a file onto the frame. Swap the source for
your API, or for `dbObjectSource`, without changing the component.

## Usage

Pass `list`, then the hooks you already have. Each one switches a feature on.

```tsx
"use client";

import {
  useDelete,
  useDownload,
  useObjectList,
  useObjectListSelection,
  useUpload,
  type ObjectListSource,
} from "@dimah-s3/react";
import { ObjectList, UploadButton } from "@dimah-s3/ui";

type LibraryFile = { id: string; key: string; name: string; size: number };

export function Library({ source }: { source: ObjectListSource<LibraryFile> }) {
  const list = useObjectList(source);
  const selection = useObjectListSelection(list);
  const upload = useUpload({
    route: "docs",
    maxFiles: 8,
    noClick: true,
    noKeyboard: true,
    getUploadOptions: () => ({
      metadata: { folderId: list.parent ?? "" },
    }),
  });
  const download = useDownload({ route: "docs" });
  const remove = useDelete({ route: "docs" });

  return (
    <ObjectList
      list={list}
      selection={selection}
      upload={upload}
      download={download}
      delete={remove}
      toolbar={
        <UploadButton upload={upload} size="sm" status={false} toast={false} />
      }
    />
  );
}
```

| Prop        | Adds                                                                          |
| ----------- | ----------------------------------------------------------------------------- |
| `selection` | Checkboxes, the selection bar, Shift ranges, Ctrl+A / Cmd+A, Escape, Space    |
| `upload`    | Drop and paste into the open folder, progress under the header                |
| `download`  | Download and Copy link in the file menu                                       |
| `share`     | Copy link through a second `useDownload`, such as `disposition: "inline"`     |
| `delete`    | Delete in the file menu with a confirmation, and bulk Delete on the selection |

Rows read `list.getFile(item)`: the name, object key, size, type, date, and
thumbnail you return from `getFile` on the source. The second line shows the
size and the date. A file with `previewUrl` shows the image; the name stays
the accessible label.

## Compose

`children` replaces the default layout. Every part reads the nearest
`ObjectList`, so you only arrange them. Props on `ObjectList` configure the
data and the entries; children arrange the frame.

```tsx
import {
  ObjectList,
  ObjectListContent,
  ObjectListHeader,
  ObjectListSearch,
  ObjectListSortMenu,
  ObjectListUploadStatus,
  ObjectListUsage,
  ObjectListViewToggle,
  UploadButton,
} from "@dimah-s3/ui";

<ObjectList
  list={list}
  selection={selection}
  upload={upload}
  delete={remove}
  height="28rem"
>
  <ObjectListHeader>
    <ObjectListSearch />
    <ObjectListSortMenu />
    <ObjectListViewToggle />
    <UploadButton upload={upload} size="sm" status={false} toast={false} />
  </ObjectListHeader>
  <ObjectListUsage />
  <ObjectListUploadStatus />
  <ObjectListContent />
</ObjectList>;
```

| Part                     | Renders                                                                                   |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| `ObjectListHeader`       | Select-all, the path, a reload spinner, and `children`. The selection bar while selecting |
| `ObjectListBreadcrumb`   | The path. Earlier folders collapse into a menu past two levels                            |
| `ObjectListSearch`       | A debounced search box for `list.search`                                                  |
| `ObjectListSortMenu`     | Name, size, and date order for `list.sort`. Pass `options` for your fields                |
| `ObjectListViewToggle`   | List and grid buttons                                                                     |
| `ObjectListSelectAll`    | The select-all checkbox                                                                   |
| `ObjectListSelectionBar` | Count, `actions`, bulk Delete, and Clear                                                  |
| `ObjectListBulkDelete`   | Bulk Delete for a bar of your own                                                         |
| `ObjectListUsage`        | Bytes and files from `list.usage`, with a meter for `usageLimits`                         |
| `ObjectListUploadStatus` | Upload progress and errors                                                                |
| `ObjectListContent`      | Rows or tiles, loading, error, and empty states, and the next page                        |
| `ObjectListEmpty`        | The empty state, with your own text or a call to action                                   |
| `ObjectListItemMenu`     | Download, Copy link, your actions, and Delete for one file                                |

`useObjectListContext()` returns the list, selection, hooks, and view, for
parts of your own. Inside an entry, `useObjectListEntry()` returns it.

## Entries

Change part of every entry with a `render*` prop. Each receives the entry:
`entry.kind` is `"file"` or `"folder"`, `entry.item` is your record, and
`entry.file` is what `getFile` returned.

```tsx
<ObjectList
  list={list}
  onOpenItem={(file) => openPreview(file)}
  renderMeta={(entry) =>
    entry.kind === "file" && entry.item.shared ? <Badge>Shared</Badge> : null
  }
  renderDescription={(entry) =>
    entry.kind === "file"
      ? `${entry.item.owner} · ${formatSize(entry.item.size)}`
      : null
  }
  renderActions={(entry) =>
    entry.kind === "file" ? (
      <ObjectListItemMenu
        actions={[{ label: "Rename", onClick: () => rename(entry.item) }]}
      />
    ) : null
  }
/>
```

- `onOpenItem` runs when a file is clicked or activated with Enter. Folders always open in place.
- `renderActions` replaces the trailing controls. Without it, files get `ObjectListItemMenu` when the list has `download`, `share`, or `delete`. Return `null` to hide it.
- `renderDescription` replaces the second line. `renderMeta` sits beside the name.
- `renderEntry` replaces the whole row or tile. Return `ObjectListRow` or `ObjectListTile` with your own `className`, `media`, or `actions` to keep selection, keyboard, and opening.

Each entry sets `data-slot="object-list-entry"`, `data-kind`, `data-view`, and `data-selected` for styling.

## Views

`defaultView="grid"` starts in the grid. Pass `view` and `onViewChange` to
keep it in your own state, for example in the URL. `ObjectListViewToggle`
switches it. The grid shows `previewUrl` thumbnails at full width and a
larger glyph for other files.

## Search and sort

`list.setSearch` and `list.setSort` reload the first page. The query receives
`search` (trimmed) and `sort`; the source decides what they mean.
`memoryObjectSource` matches names and sorts by name, size, date, or
`sortValue`. A query of your own passes them to your API. While the new page
loads, the current rows stay on screen.

```tsx
<ObjectListSortMenu
  options={[
    { field: "name", label: "Name" },
    { field: "owner", label: "Owner" },
    { field: "updatedAt", label: "Modified", direction: "desc" },
  ]}
/>
```

Opening another folder clears the search. With a search and no match, the
empty state says nothing matches.

## Selection

Pass `useObjectListSelection(list)` as `selection`. By default only files can
be selected. Click a checkbox, Shift-click to extend from the last one, or
Ctrl-click / Cmd-click a row. With focus inside the list, Space toggles the
focused entry, Ctrl+A or Cmd+A selects every loaded entry, and Escape
clears. With more pages to load, select-all takes the rows on screen and
says so.

The selection bar shows the count, `selectionActions`, bulk Delete when the
list has `delete`, and Clear. Controls in `selectionActions` read the
selection you already hold:

```tsx
const selection = useObjectListSelection(list);

<ObjectList
  list={list}
  selection={selection}
  selectionActions={
    <Button size="sm" onClick={() => share(selection.selectedItems)}>
      Share
    </Button>
  }
/>;
```

To delete folders, let them be selected and say which keys they hold.
Without `resolveFolderKeys`, selected folders stay out of the delete.

```tsx
const selection = useObjectListSelection(list, { isSelectable: () => true });

<ObjectList
  list={list}
  selection={selection}
  delete={remove}
  resolveFolderKeys={(folder) => api.keysUnder(folder.id)}
/>;
```

Deletes run in batches of 100. Deleted files leave the rows at once, then the
list reloads the pages on screen. `onDeleted` receives the object keys that
were deleted and those that failed, from the file menu and the selection
bar alike. Leave `useDelete`'s `onSuccess` for your own work.

## Keyboard

| Key                     | Action                                     |
| ----------------------- | ------------------------------------------ |
| Arrow keys, Home, End   | Move between entries (by row in the grid)  |
| Enter                   | Open the folder, or call `onOpenItem`      |
| Space                   | Toggle the focused entry. Shift: the range |
| Ctrl+A / Cmd+A          | Select every loaded entry                  |
| Escape                  | Clear the selection                        |
| Backspace / Alt+ArrowUp | Open the parent folder                     |

Fields, menus, and dialogs inside the list keep their own keys.

## Upload into the open folder

Pass the same `useUpload` to `upload` and, for the file picker, to
`UploadButton` in the header. Set `noClick` and `noKeyboard` on the hook.
The frame accepts a drop and a paste, and it does not open the picker when an
entry is clicked. The list renders the hook's file input, so `upload.open()`
from any trigger — a menu item or an empty-state button — opens the picker.

`getUploadOptions` reads `list.parent` and sends it as `metadata.folderId`.
It runs as each file starts, so it sees the folder that is open at that
moment. Read `clientMetadata.folderId` in `upload.object` or `upload.guard`
and store it on your file row. The library does not write that id into the
object key, and a drop onto a folder entry still goes to the open folder.

When a batch settles and at least one file succeeded, `ObjectList` reloads
once. Set `toast={false}` and `status={false}` on the header button so the
list owns progress.

```tsx
<ObjectList
  list={list}
  upload={upload}
  empty={
    <ObjectListEmpty>
      <Button size="sm" onClick={upload.open}>
        Upload files
      </Button>
    </ObjectListEmpty>
  }
/>
```

## File menu

`ObjectListItemMenu` downloads, copies a link, and deletes one file. Inside a
list every prop is optional: the object key, name, and size come from the
entry, and the hooks come from the list. The list draws one delete
confirmation and one set of toasts for all rows.

Copy link signs through `share` when the list has it, otherwise through
`download`, then writes the URL to the clipboard. Pass `expiresIn` to ask for
a shorter TTL than the route cap; the toast shows the TTL that was signed.
Pass `actions`, or `DropdownMenuItem` children, for rows such as rename.
They render after Copy link and before Delete.

Outside a list, pass `objectKey` and the hooks yourself:

```tsx
<ObjectListItemMenu
  objectKey={file.key}
  fileName={file.name}
  download={download}
  delete={remove}
  onDeleted={() => reload()}
/>
```

## Frame

Pass `height` to keep the header in place and scroll the entries inside a
fixed frame. A number is pixels; a string is a CSS length, such as `"18rem"`
or `"100%"`. Pass `maxHeight` when the frame should grow with the folder up
to that cap.

With `loadMore="auto"` (the default), the next page loads as the end of the
entries comes into view, and a frame that is not full keeps loading until it
is. `loadMore="button"` shows Load more instead. A failed page shows Retry,
which repeats that page.

## Storage

Return `usage` from the query and `useObjectList` keeps it on `list.usage`.
Pass your caps as `usageLimits`; those are the same numbers as
`db({ quota })` when that plugin enforces the limit. The meter follows
whichever cap is closer to full and turns destructive at the cap. Without
`usage`, nothing is shown. `dbObjectSource` forwards the scope total, not the
open folder.

## Folders

`ObjectList` does not invent folders. The first page of the query returns
them. For a tree, keep folders in your own table and return them from your
query on the first page. `memoryObjectSource` builds them from a
`/`-separated path with `getFolder`. `dbObjectSource` sends the open folder
as a key prefix; generated keys contain a uuid segment, so that prefix is not
a folder tree.
