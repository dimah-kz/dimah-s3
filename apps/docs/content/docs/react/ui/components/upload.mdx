The upload family renders one [`useUpload`](/docs/react/hooks/upload) hook.
`Upload` holds the hook, and the parts inside it read it: a trigger that opens
the file picker, a dropzone, and the status of the queue. `UploadToasts`
reports on the same hook from anywhere in the tree.

## Usage

```tsx
"use client";

import { useUpload } from "@dimah-s3/react";
import {
  Upload,
  UploadStatus,
  UploadToasts,
  UploadTrigger,
} from "@dimah-s3/ui";

export function AvatarUploader() {
  const upload = useUpload({ route: "avatar" });

  return (
    <>
      <Upload upload={upload}>
        <UploadTrigger />
        <UploadStatus />
      </Upload>
      <UploadToasts upload={upload} />
    </>
  );
}
```

`Upload` renders the hidden file input and no element of its own, so place
its parts in your own layout.

| Part             | Renders                                                                   |
| ---------------- | ------------------------------------------------------------------------- |
| `UploadTrigger`  | A `Button` that opens the file picker                                     |
| `UploadDropzone` | A drop area that also opens the picker on click, Enter, or Space          |
| `UploadStatus`   | One card for one file, or a summary above the file list for several       |
| `UploadFileList` | Every file in the queue. Pass a function as `children` to render your own |
| `UploadFileItem` | The card for one file, with its progress, error, and a cancel action      |
| `UploadToasts`   | Progress, results, and rejected files as toasts. It renders no element    |

`useUploadContext()` returns the `upload` of the nearest `Upload` and its
`isFull` flag, for parts of your own. Pass `isFull` to `Upload` (as a full
`UploadField` does) to render `UploadTrigger` and `UploadDropzone`
focusable but `aria-disabled`; it changes only how they render, so the
`upload` must take no files itself. Queued files show a per-file cancel in
`UploadStatus` and `UploadFileList`.

## Dropzone

```tsx
const upload = useUpload({ route: "gallery", maxFiles: 5, queue: true });

<Upload upload={upload}>
  <UploadDropzone />
  <UploadStatus />
</Upload>;
```

The dropzone is a button. Its default text names the action, and the route's
size and type limits describe it. A polite live region says whether the files
being dragged can be dropped. It also takes files pasted while it has focus.

Pass `children` to replace the icon and text. The limits stay attached as the
description. Do not put buttons or links inside the dropzone: render
`UploadStatus` next to it.

```tsx
<UploadDropzone className="min-h-40">
  <p className="text-sm font-medium">Drop photos here</p>
</UploadDropzone>
```

The trigger and the dropzone stay enabled while files upload. New files join
the queue when the hook has `queue: true`, and replace it otherwise. While
the root is full, "Maximum files reached." leads the dropzone's description.

## Status

`UploadStatus` renders nothing while the hook is idle. One file shows as its
own card. Several files show a summary with overall progress, "Cancel all
uploads", and a dismiss action once they settle, above `UploadFileList`.
Pause appears while files upload when the hook has an `uploadStore`, so the
uploads can [resume](/docs/react/upload-store).

When cancel, pause, dismiss, or remove takes away the card that has focus,
focus moves to the next action in the same list, then the previous one, then
the root's trigger or dropzone.

To render each file yourself, pass a function to `UploadFileList`:

```tsx
<UploadFileList>
  {(file) => <UploadFileItem file={file} className="w-32" />}
</UploadFileList>
```

## Toasts

Parts never toast. Mount `UploadToasts` once per hook, and one `<Toaster />`
in your root layout ([UI Setup](/docs/react/ui)).

- While files upload, a progress toast with a cancel action.
- Once the queue settles, the result.
- For each call that rejects files, the reason, formatted from the error code.

A second `UploadToasts` for the same hook renders nothing and warns in
development. Inside an [`ObjectList`](/docs/react/ui/components/object-list)
your `UploadToasts` replaces the list's built-in toasts.

## Paste

`usePasteFiles` uploads files pasted anywhere on the page. It leaves pastes
into form fields and editable text alone, and pastes a focused dropzone
already took. It stops listening while the hook is disabled.

```tsx
import { usePasteFiles } from "@dimah-s3/ui";

usePasteFiles(upload, { enabled: !dialogOpen });
```

## Call options

`call` on `UploadTrigger` and `UploadDropzone` applies to the files they take
in. Its `uploadOptions` merge over the hook's, and `maxFiles` lowers the
hook's limit for that call.

```tsx
<UploadTrigger
  call={{ uploadOptions: { metadata: { album: albumId } } }}
  tooltip="Add photos"
/>
```

Inside an `ObjectList` with the same hook, the source's `uploadOptions` for
the open folder apply first, so files land in that folder. Your `call` merges
over them.

## Frequently asked questions

<Accordions>

<Accordion title="How do I keep the picker closed in some cases?">

Call `event.preventDefault()` in the trigger's `onClick`:

```tsx
<UploadTrigger
  onClick={(event) => {
    if (!signedIn) event.preventDefault();
  }}
/>
```

</Accordion>

<Accordion title="How do I disable the trigger?">

Pass `disabled` to `useUpload`. Every part reads `upload.disabled`: the
trigger and the dropzone disable, and drops and pastes do nothing:

```tsx
const upload = useUpload({ route: "avatar", disabled: locked });

<Upload upload={upload}>
  <UploadTrigger />
</Upload>;
```

Pass `disabled` to `UploadTrigger` to disable only the trigger while the hook
stays enabled. While the hook is disabled, the picker stays closed whatever the
prop says:

```tsx
<UploadTrigger disabled={!canEdit} />
```

</Accordion>

<Accordion title="How do I clear the status after an upload?">

Use the dismiss action on a settled card, or call `upload.reset()`.

</Accordion>

</Accordions>
