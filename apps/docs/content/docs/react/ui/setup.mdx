[`@dimah-s3/ui`](https://www.npmjs.com/package/@dimah-s3/ui) ships shadcn-compatible
controls on top of [`@dimah-s3/react`](/docs/react) hooks. Do this once per app —
component pages only cover the import or `shadcn add` command for that item.

You need a working [`S3Provider`](/docs/react/setup) first.

## Choose an install path

<Tabs items={["npm package", "shadcn registry"]}>

<Tab value="npm package">

```npm
npm i @dimah-s3/ui shadcn
```

Import components from `@dimah-s3/ui`. Styles and the toaster come from the same
package.

</Tab>

<Tab value="shadcn registry">

```json title="components.json"
{
  "registries": {
    "@dimah-s3": "https://dimah-s3.vercel.app/r/{name}.json"
  }
}
```

Then add items as needed:

```npm
npx shadcn@latest add @dimah-s3/upload-button
```

Source lands in your app (usually under `components/`). Toast UI comes from
shadcn [toast](https://ui.shadcn.com/docs/components/base/toast).

</Tab>

</Tabs>

## Styles

Import the UI stylesheet so Tailwind can scan package classes. It also maps
`--color-dimah-s3-*` to your [shadcn theme](https://ui.shadcn.com/docs/theming)
by default — see [Theming](/docs/react/ui/customization/theming).

<include meta='title="app/globals.css"'>
  ../../../_includes/ui/globals.css
</include>

Keep the usual shadcn variables (`--primary`, `--muted`, …) in the same file.

Registry-only apps that never install `@dimah-s3/ui` should still add the
[color bridge](/docs/react/ui/customization/theming#registry-only) so
`*-dimah-s3-*` utilities resolve.

## Toaster

Mount once next to your provider. Wired upload / download / delete toasts need
it.

<Tabs items={["npm package", "shadcn registry"]}>

<Tab value="npm package">

```tsx title="app/layout.tsx"
import { Toaster } from "@dimah-s3/ui";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Toaster />
      </body>
    </html>
  );
}
```

Already using shadcn toast for your own messages? Mount both and alias one
import (`Toaster as DimahToaster`). They are independent — keep
`import { toast } from "@/components/ui/toast"` for app toasts.

</Tab>

<Tab value="shadcn registry">

```tsx title="app/layout.tsx"
import { Toaster } from "@/components/ui/toast";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Toaster />
      </body>
    </html>
  );
}
```

Use `toast.add` / `toast.update` / `toast.close` / `toast.promise` from that
module — not the old Sonner helpers (`toast.success`, `toast.error`, …).

</Tab>

</Tabs>
