---
title: useUpload
description: Upload a queue of files to a named route, with validation, progress, cancel, retries, and multipart.
---

`useUpload` takes files from a picker, a drop, a paste, or your own code. It
checks each file against the route's policy, then presigns, uploads, and
confirms it. The hook sends only the route name; the server builds the object
key.

```tsx title="components/file-uploader.tsx"
"use client";

import { useUpload } from "@dimah-s3/react";

export function FileUploader() {
  const upload = useUpload({
    route: "avatar",
    onSuccess: (result) => console.log("Uploaded:", result.key),
  });

  return (
    <div
      {...upload.getRootProps({
        className: "cursor-pointer rounded-lg border border-dashed p-6",
      })}
    >
      <input {...upload.getInputProps()} />
      {upload.isPending
        ? `Uploading: ${upload.progress.percent}%`
        : "Click or drop a file here"}
    </div>
  );
}
```

For ready-made controls, pass the return value to the
[upload components](/docs/ui/components/upload).

## Take files in

An element with `getRootProps()` takes drops, pastes, clicks, and Enter or
Space. To open the picker from your own button, call `open()`. To upload a
`File`, `File[]`, or `FileList` from your own code, such as a camera capture,
call `handleFiles(files)`.

```tsx
const upload = useUpload({ route: "avatar", noClick: true });

return (
  <div {...upload.getRootProps()}>
    <input {...upload.getInputProps()} />
    <button type="button" onClick={() => upload.open()}>
      Choose file
    </button>
  </div>
);
```

- `getDropTargetProps()` makes a drop target that keeps its own click and keyboard handlers, such as a folder row.
- `noDrag`, `noClick`, and `noKeyboard` turn off one kind of intake. `disabled` turns off all of it, including `open()`. `handleFiles` still uploads what you pass it.

## The queue

Every file of a call joins one queue. `maxFiles` caps the files per call
(default `1`), and `concurrentFiles` uploads that many at once (default `2`).
Each entry of `upload.files` is an [`UploadFileState`](#uploadfilestate).

```tsx
const upload = useUpload({
  route: "attachments",
  maxFiles: 10,
  append: true,
});

return (
  <ul>
    {upload.files.map((file) => (
      <li key={file.id}>
        {file.fileName} — {file.phase} ({file.progress.percent}%)
        {file.phase === "error" ? (
          <button type="button" onClick={() => void upload.retry(file.id)}>
            Retry
          </button>
        ) : file.phase !== "success" ? (
          <button type="button" onClick={() => upload.cancel(file.id)}>
            Cancel
          </button>
        ) : null}
      </li>
    ))}
  </ul>
);
```

- **Replace (default)** — a new call cancels the files in flight and replaces the queue once its own files start uploading. Earlier calls still preparing are cancelled at once. A call that is blocked, rejected, or fails before uploading leaves the queue alone.
- **Append** — with `append: true`, new files join the end and files in flight keep going. A call's own `append` wins, as in `handleFiles(files, { append: true })`.

### Cancel, retry, and reset

Each takes one id, an array of ids, or nothing for every file:

- **`cancel(ids?)`** — aborts the files and their multipart sessions, and removes them from the queue.
- **`retry(ids?)`** — uploads failed files again, each in its place and with its `id`. Files from one call go again as one call with that call's options, so they land in the same folder. They are validated again, and `beforeUpload` and `onUploadStart` run once for them. A retry never replaces the queue, and resolves like `handleFiles`.
- **`reset(ids?)`** — removes settled files, such as a finished row the user dismisses. With no ids it also clears `fileRejections`. Files in flight keep going.

### Limit across calls

`maxFiles` caps one call. To cap what the hook holds across calls, such as a
form field with room for five files, call `useUploadLimit` in the component
that owns that count. [`UploadField`](/docs/ui/components/upload-field) sets
one for its `maxFiles`.

```tsx
import { useUpload, useUploadLimit } from "@dimah-s3/react";

const upload = useUpload({ route: "attachments", maxFiles: 5, append: true });
// At most five files across calls: queued, in flight, or uploaded.
const remaining = useUploadLimit(upload, { available: 5 });
```

- **`available`** — files the hook may still take in. Files queued or in flight, uploaded files not in `counted`, and calls still preparing take from it. `reset()` gives the room of uploaded files back.
- **`counted`** — ids of uploaded files that take nothing from `available`. When you keep the uploaded keys yourself, as `UploadField` does, pass `available: max - keys.length` and the ids whose keys you hold, so they do not count twice.

While the component is mounted, the limit applies to every call, including
drops, pastes, and `retry`. Files past it are rejected with `TOO_MANY_FILES`,
and a retry takes only the failed files that fit. `remaining` is how many
files still fit; render your pickers disabled at `0`.

## Results

`handleFiles` does not throw for upload errors. It resolves once every file of
the call has ended:

```ts
const { uploaded, failed, rejected, blocked, aborted } =
  await upload.handleFiles(files);

for (const { file, result } of uploaded) console.log(file.name, result.key);
for (const { file, error } of failed) console.log(file.name, error.code);
for (const { file, errors } of rejected) console.log(file.name, errors[0].code);
```

`result` is the [`UploadResult`](/docs/react/custom-backend/upload#confirm)
the server verified with `HeadObject`. `upload.fileRejections` holds only the
newest call's rejections, so read `rejected` when calls overlap.

## Callbacks

Callbacks run in this order:

| Callback                         | Runs                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------- |
| `onFileReject(rejections)`       | Once per call with rejected files, before anything else                         |
| `beforeUpload(files)`            | Once per call. Return `false` to block it. A throw fails it (`HOOK_FAILED`)     |
| `onUploadStart(files)`           | Once per call, after `beforeUpload` allows it. A throw fails it (`HOOK_FAILED`) |
| `onProgress(progress, file)`     | As bytes are sent                                                               |
| `onMultipartInit(session, file)` | When a multipart upload starts or resumes. `session` is `{ uploadId, key }`     |
| `onPartUpload(part, file)`       | After each multipart part. `part` is `{ partNumber, partCount }`                |
| `onError(error, file)`           | Once per failed file, after every file of the call has ended                    |
| `onSuccess(result, file)`        | Once per uploaded file, after every `onError` of the call                       |
| `onSettled(result)`              | Once per call, last. Also runs when every file was rejected                     |

`onError`, `onSuccess`, and `onSettled` may be async and are awaited. A throw
from one never changes the result; see
[Callback order](/docs/react/guides/outcomes#callback-order).

## Request options

`uploadOptions` sets the request for each file: `clientMetadata` for the
server hooks, and `fileName` or `contentType` to override what the browser
reports. Pass an object, or a function of the file. A throw from the function
fails that file with `HOOK_FAILED`.

A call can add its own options. Call fields win, and `clientMetadata` merges
key by key:

```ts
const upload = useUpload({
  route: "attachments",
  uploadOptions: (file) => ({
    clientMetadata: { originalName: file.name },
  }),
});

await upload.handleFiles(files, {
  uploadOptions: { clientMetadata: { folderId } },
  maxFiles: 3, // lowers maxFiles for this call
});
```

`open`, `getRootProps`, and `getDropTargetProps` take the same call options.
The prop getters also take a function, read when the files arrive. A drop on
a target inside a dropzone uses the target's options:

```tsx
<li
  {...upload.getDropTargetProps({ className: "folder-row" }, () => ({
    uploadOptions: { clientMetadata: { folderId: folder.id } },
  }))}
>
  {folder.name}
</li>
```

`clientMetadata` holds at most 32 entries: keys of letters, digits, and
hyphens up to 128 characters, and values up to 2048 characters. It is never
written to S3 on its own; the route's `object` callback decides what becomes
the object's `metadata`.

## Route policy

`upload.policy` is the route's policy from the catalog (`GET /routes`),
narrowed by the hook options:

- **`accept`** and **`maxFileSize`** — the stricter of the route and the hook wins.
- **`multipart`** — on when the route allows it and the hook does not pass `multipart: false`.
- **`checksum`** — follows the route. When on, single-shot uploads send a SHA-256.
- **`status`** and **`error`** — where the catalog is in loading. Until it loads, only the hook options apply.

Files that break the policy are rejected without stopping the others. Each
rejection carries `APIError`s with the codes `FILE_TYPE_NOT_ALLOWED`,
`FILE_EMPTY`, `FILE_TOO_LARGE`, or `TOO_MANY_FILES`. Show them with
[`useFormatError`](/docs/react/helpers#errors):

```tsx
import { useFormatError, type UseUploadReturn } from "@dimah-s3/react";

export function Rejections({ upload }: { upload: UseUploadReturn }) {
  const formatError = useFormatError();

  return upload.fileRejections.map(({ file, errors }) => (
    <p key={file.name} role="alert">
      {file.name}: {errors.map(formatError).join(", ")}
    </p>
  ));
}
```

To read a route's policy without uploading, such as to label a custom picker,
call [`useRouteUploadPolicy`](#userouteuploadpolicy).

## Multipart and retries

Files of at least 50 MiB (`DEFAULT_MULTIPART_THRESHOLD`) upload in parts when
the policy allows multipart, `concurrentParts` at a time (default `4`). The
server picks the part size.

Failed requests retry with exponential backoff: `maxRetries` (default `3`)
times, starting at `baseDelayMs` (default `1000`) and doubling. These are
retried:

- `NETWORK_ERROR` and `S3_NETWORK_ERROR`.
- `UPLOAD_FAILED` when S3 answered 408, 429, or 500 and above.
- Any API response with status 408, 429, or 500 and above, such as `INTERNAL_ERROR`.
- An expired presigned URL, which is signed again first.

`HOOK_FAILED`, `CHECKSUM_MISMATCH`, and every other 4xx are not retried. Send a
file that still fails again with `upload.retry(id)`.

## Cancel, detach, and unmount

What happens to a multipart upload when it stops:

| Action          | With an `uploadStore`                                   | Without one               |
| --------------- | ------------------------------------------------------- | ------------------------- |
| `cancel(ids?)`  | Aborts the server session and deletes the stored record | Aborts the server session |
| `detach()`      | Keeps the session and the record, to resume             | Aborts the server session |
| Unmount         | Detaches                                                | Cancels                   |
| Retryable error | Keeps the session and the record                        | Aborts the server session |
| Other error     | Aborts the session and deletes the record               | Aborts the server session |

A kept upload [resumes](/docs/react/upload-store) from the parts S3 already
has when the user selects the same file again.

## API Reference

### Options

| Prop              | Type                                                     | Default                                | Description                                                                          |
| ----------------- | -------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| `route`           | `S3RouteName`                                            | required                               | Named server route. The server builds the object key                                 |
| `api`             | `S3Api`                                                  | —                                      | Replaces the `S3Provider` API. Required without a provider                           |
| `accept`          | `readonly string[]`                                      | —                                      | MIME types (`image/*`) and extensions (`.pdf`) that narrow the route's `fileTypes`   |
| `maxFileSize`     | `number`                                                 | —                                      | Max bytes. The smaller of this and the route's wins                                  |
| `maxFiles`        | `number`                                                 | `1`                                    | Max files per call                                                                   |
| `append`          | `boolean`                                                | `false`                                | Add new files to the queue instead of replacing it                                   |
| `concurrentFiles` | `number`                                                 | `2`                                    | Files uploaded at once                                                               |
| `concurrentParts` | `number`                                                 | `4`                                    | Multipart parts uploaded at once per file                                            |
| `multipart`       | `boolean`                                                | —                                      | `false` turns multipart off even when the route allows it                            |
| `retry`           | `RetryConfig`                                            | `{ maxRetries: 3, baseDelayMs: 1000 }` | Retries per request, and the first backoff delay in ms. Each retry doubles the delay |
| `uploadStore`     | `UploadStore`                                            | —                                      | Persists multipart uploads so they can [resume](/docs/react/upload-store)            |
| `uploadOptions`   | `UploadRequestOptions \| (file) => UploadRequestOptions` | —                                      | [Request options](#request-options) for every file                                   |
| `disabled`        | `boolean`                                                | `false`                                | Turns off the root, drop targets, paste, and `open()`                                |
| `noDrag`          | `boolean`                                                | `false`                                | Turns off drag and drop on the root and drop targets                                 |
| `noClick`         | `boolean`                                                | `false`                                | Turns off click-to-open on the root                                                  |
| `noKeyboard`      | `boolean`                                                | `false`                                | Turns off keyboard activation on the root                                            |
| `onFileReject`    | `(rejections) => void`                                   | —                                      | Runs with the files rejected before upload                                           |
| `beforeUpload`    | `(files) => boolean \| Promise<boolean>`                 | —                                      | Runs once per call. Return `false` to block it                                       |
| `onUploadStart`   | `(files) => void`                                        | —                                      | Runs once per call, after `beforeUpload` allows it                                   |
| `onProgress`      | `(progress, file) => void`                               | —                                      | Byte progress of one file                                                            |
| `onMultipartInit` | `(session, file) => void`                                | —                                      | Runs when a multipart upload starts or resumes                                       |
| `onPartUpload`    | `(part, file) => void`                                   | —                                      | Runs after each multipart part                                                       |
| `onError`         | `(error, file) => void \| Promise<void>`                 | —                                      | Runs once per failed file                                                            |
| `onSuccess`       | `(result, file) => void \| Promise<void>`                | —                                      | Runs once per uploaded file                                                          |
| `onSettled`       | `(result) => void \| Promise<void>`                      | —                                      | Runs once per call, with its `UploadBatchResult`                                     |

### Return

| Property             | Type                                            | Description                                                             |
| -------------------- | ----------------------------------------------- | ----------------------------------------------------------------------- |
| `files`              | `readonly UploadFileState[]`                    | Every file in the queue, in the order it was added                      |
| `file`               | `UploadFileState \| null`                       | The first file. Handy when `maxFiles` is `1`                            |
| `phase`              | `"idle" \| "uploading" \| "success" \| "error"` | Phase of the whole queue                                                |
| `progress`           | `TransferProgress`                              | Bytes across every file in the queue                                    |
| `error`              | `APIError \| null`                              | The failed file's error, or `PARTIAL_FAILURE` when several failed       |
| `isPending`          | `boolean`                                       | `true` while a call is preparing or a file is in flight                 |
| `policy`             | `UploadPolicy`                                  | The route policy narrowed by the options, plus `maxFiles`               |
| `fileRejections`     | `readonly FileRejection[]`                      | Files the newest call rejected, each as `{ file, errors }`              |
| `resumable`          | `boolean`                                       | `true` when an `uploadStore` is set                                     |
| `disabled`           | `boolean`                                       | The `disabled` option                                                   |
| `instanceId`         | `string`                                        | Stable id of the hook instance. Toast owners use it                     |
| `handleFiles`        | `(files, call?) => Promise<UploadBatchResult>`  | Validates and uploads a `File`, `File[]`, or `FileList`                 |
| `open`               | `(call?) => void`                               | Opens the file picker                                                   |
| `getRootProps`       | `(props?, call?) => props`                      | Props for a dropzone                                                    |
| `getInputProps`      | `(props?) => props`                             | Props for the hidden file input                                         |
| `getDropTargetProps` | `(props?, call?) => props`                      | Drag and drop handlers only. Sets `data-drag-active` while dragged over |
| `isDragActive`       | `boolean`                                       | Files are dragged over a dropzone or drop target                        |
| `isDragAccept`       | `boolean`                                       | The dragged files match `accept` and `maxFiles`                         |
| `isDragReject`       | `boolean`                                       | The dragged files break `accept` or `maxFiles`                          |
| `cancel`             | `(ids?) => void`                                | Cancels one file, several, or every file                                |
| `retry`              | `(ids?) => Promise<UploadBatchResult>`          | Uploads failed files again                                              |
| `reset`              | `(ids?) => void`                                | Removes settled files                                                   |
| `detach`             | `() => void`                                    | Stops every file but keeps stored multipart uploads                     |

### UploadFileState

| Property      | Type                   | Description                                                                                         |
| ------------- | ---------------------- | --------------------------------------------------------------------------------------------------- |
| `id`          | `string`               | Unique on the page. Pass it to `cancel`, `retry`, or `reset`                                        |
| `file`        | `File`                 | The browser file                                                                                    |
| `phase`       | `UploadFilePhase`      | `"queued"`, `"preparing"`, `"presigning"`, `"uploading"`, `"finalizing"`, `"success"`, or `"error"` |
| `progress`    | `TransferProgress`     | `{ loaded, total, percent, speed? }`. `speed` is bytes per second                                   |
| `error`       | `APIError \| null`     | Set when `phase` is `"error"`                                                                       |
| `result`      | `UploadResult \| null` | The verified object, set when `phase` is `"success"`                                                |
| `fileName`    | `string`               | Name from the browser `File`                                                                        |
| `fileSize`    | `number`               | Size in bytes                                                                                       |
| `contentType` | `string`               | MIME type from the browser `File`                                                                   |
| `previewUrl`  | `string \| null`       | Object URL for an image thumbnail, `null` for other files. The hook revokes it                      |

### UploadBatchResult

| Property   | Type                 | Description                                      |
| ---------- | -------------------- | ------------------------------------------------ |
| `uploaded` | `{ file, result }[]` | Files that uploaded, with the verified object    |
| `failed`   | `{ file, error }[]`  | Files that failed, with an `APIError`            |
| `rejected` | `{ file, errors }[]` | Files the policy refused before upload           |
| `blocked`  | `File[]`             | Files `beforeUpload` blocked                     |
| `aborted`  | `File[]`             | Files cancelled or detached before they finished |

### Call options

`handleFiles`, `open`, `getRootProps`, and `getDropTargetProps` take these as
`call`. The prop getters also take a function that returns them.

| Prop            | Type                                                     | Default | Description                                 |
| --------------- | -------------------------------------------------------- | ------- | ------------------------------------------- |
| `uploadOptions` | `UploadRequestOptions \| (file) => UploadRequestOptions` | —       | Merged over the hook's `uploadOptions`      |
| `maxFiles`      | `number`                                                 | —       | Lowers `maxFiles` for this call             |
| `append`        | `boolean`                                                | —       | Overrides the hook's `append` for this call |

### UploadRequestOptions

| Prop             | Type                     | Default | Description                                                                 |
| ---------------- | ------------------------ | ------- | --------------------------------------------------------------------------- |
| `clientMetadata` | `Record<string, string>` | —       | Extras for the server hooks. Not written to S3 unless the route copies them |
| `fileName`       | `string`                 | —       | Overrides the browser's file name                                           |
| `contentType`    | `string`                 | —       | Overrides the browser's content type                                        |

### UploadPolicy

| Property      | Type                              | Description                                        |
| ------------- | --------------------------------- | -------------------------------------------------- |
| `accept`      | `string[] \| undefined`           | Accepted types. Unset when any type is allowed     |
| `maxFileSize` | `number \| undefined`             | Max bytes                                          |
| `multipart`   | `boolean`                         | Large files go through multipart                   |
| `checksum`    | `boolean`                         | Single-shot uploads send a SHA-256                 |
| `maxFiles`    | `number`                          | The hook's `maxFiles`                              |
| `status`      | `"loading" \| "ready" \| "error"` | Where the catalog is in loading                    |
| `error`       | `APIError \| null`                | Why the catalog failed, when `status` is `"error"` |

### useUploadLimit

`useUploadLimit(upload, limit)` returns the files that still fit, or `null`
without a limit.

| Prop              | Type                  | Default  | Description                                              |
| ----------------- | --------------------- | -------- | -------------------------------------------------------- |
| `upload`          | `UseUploadReturn`     | required | The hook to cap                                          |
| `limit`           | `UploadLimit \| null` | required | The cap, or `null` for none                              |
| `limit.available` | `number`              | required | Files the hook may still take in                         |
| `limit.counted`   | `ReadonlySet<string>` | —        | Ids of uploaded files that take nothing from `available` |

### useRouteUploadPolicy

`useRouteUploadPolicy(options)` returns the [`UploadPolicy`](#uploadpolicy)
fields without `maxFiles`.

| Prop          | Type                | Default  | Description                    |
| ------------- | ------------------- | -------- | ------------------------------ |
| `route`       | `S3RouteName`       | required | Named server route             |
| `api`         | `S3Api`             | —        | Replaces the `S3Provider` API  |
| `accept`      | `readonly string[]` | —        | Narrows the route's types      |
| `maxFileSize` | `number`            | —        | Narrows the route's size limit |
| `multipart`   | `boolean`           | —        | `false` turns multipart off    |

## Frequently asked questions

<Accordions>

<Accordion title="What happens if the route catalog fails to load?">

Every file of that call fails with the catalog's error, and `policy.status`
is `"error"`. The next call loads the catalog again. A custom backend must
implement `catalog()`; see [Bring Your Own Backend](/docs/react/custom-backend#route-catalog).

</Accordion>

<Accordion title="How do I show a local image preview before uploading?">

Read `previewUrl` from an entry of `upload.files`, or `upload.file?.previewUrl`
for a single file. It is `null` for files that are not images. The hook
revokes it, so do not revoke it yourself.

```tsx
const preview = upload.file?.previewUrl;

return preview ? <img src={preview} alt="Selected avatar" /> : null;
```

</Accordion>

<Accordion title="Why did my earlier files stop when I picked new ones?">

Without `append: true`, a new call [replaces the queue](#the-queue) and
cancels the files in flight.

</Accordion>

<Accordion title="Can I pause and resume an upload?">

Call `detach()` to stop without aborting, then select the same file again to
resume. Resuming needs an `uploadStore` and a multipart upload; see
[Upload Store](/docs/react/upload-store).

</Accordion>

</Accordions>
