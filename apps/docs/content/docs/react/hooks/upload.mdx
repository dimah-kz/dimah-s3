---
title: Upload
description: Headless hooks for single- and multi-file uploads.
---

Pick a file (or drop one), send it to S3, track progress.

[Upload Button](/docs/react/ui/components/upload-button) and
[Upload Dropzone](/docs/react/ui/components/upload-dropzone) are built on
these hooks.

| Hook                 | Use when                      |
| -------------------- | ----------------------------- |
| `useUpload`          | One file — picker or dropzone |
| `useMultiUpload`     | Many files                    |
| `useFileUpload`      | You already have a `File`     |
| `useMultiFileUpload` | You already have `File[]`     |

`accept` and `maxFileSize` are client-side UX. When omitted, hooks fill
them from [`api.catalog()`](/docs/server/routes) (`GET /routes`). The
server still enforces [`upload.fileTypes` / `upload.maxFileSize`](/docs/server/routes).
Prefer omitting them so the catalog is the single source of truth.

`accept` is the HTML list: MIME types (`image/*`, `application/pdf`) and/or
extensions (`.pdf`). The native picker uses it as the `accept` attribute;
dropzone and `validateFile` share the same tokens.

## useUpload

```tsx
"use client";

import { useUpload } from "@dimah-s3/react";

export function Uploader() {
  const { getRootProps, getInputProps, isUploading, progress } = useUpload({
    route: "uploads",
  });

  return (
    <div {...getRootProps()}>
      <input {...getInputProps()} />
      {isUploading ? `${progress.percent}%` : "Drop a file or click to upload"}
    </div>
  );
}
```

Built on [react-dropzone](https://react-dropzone.js.org/) (already included
by `@dimah-s3/react`). Spread `getRootProps` / `getInputProps` on a wrapper
and a hidden file input.

`isUploading` is `true` while bytes are moving (`phase === "uploading"`).
`isPending` is `true` for the whole in-flight window (`validating`,
`presigning`, `uploading`, `finalizing`) — use it to disable the dropzone
or picker.

For a picker button instead of a dropzone, use
[Upload Button](/docs/react/ui/components/upload-button) — or pass
`noDrag` / `noClick` / `noKeyboard` and call `open()`.

`isDragActive` / `isDragReject` style the drop target. To map `phase` onto
status rows, see [Custom UI](/docs/react/ui/customization/custom-ui).

## useMultiUpload

Same intake, for several files. The UI components above switch to this
when `maxFiles` is greater than 1.

```tsx
"use client";

import { useMultiUpload } from "@dimah-s3/react";

export function MultiUploader() {
  const { getRootProps, getInputProps, isUploading, totalProgress } =
    useMultiUpload({
      route: "uploads",
      maxFiles: 5,
    });

  return (
    <div {...getRootProps()}>
      <input {...getInputProps()} />
      {isUploading
        ? `${totalProgress.percent}%`
        : "Drop files or click to upload"}
    </div>
  );
}
```

The server generates each object key. After success, `useUpload` exposes
`result` (`key`, `contentLength`, …). `useMultiUpload` puts the same object
on each `files[]` entry (`result`). Persist `result.key`. Enable download
or delete on that **same** route when the UI needs them
([combining features](/docs/server/routes#combining-features)).

`multipart` splits **one** large file into parts. It is not multi-file
upload. To resume after a refresh, pass an
[upload store](/docs/react/upload-store).

## Without a picker

Skip dropzone when you already have a `File`.

```tsx
import { useFileUpload } from "@dimah-s3/react";

const { upload, progress, phase, fileInfo } = useFileUpload({
  route: "uploads",
});

await upload(file);
```

```tsx
const { upload, totalProgress, phase } = useMultiFileUpload({
  route: "uploads",
});

await upload(files);
```

## Options

| Option                               | Description                                                                                                     |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `route`                              | Required. Named server route (`dimahS3({ routes })`)                                                            |
| `uploadOptions` / `getUploadOptions` | Extra presign fields (`metadata`, `contentType`, `fileName`)                                                    |
| `accept`                             | HTML tokens. Filled from `api.catalog()` when omitted                                                           |
| `maxFileSize`                        | Bytes. Filled from `api.catalog()` when omitted — server `upload.maxFileSize` still applies                     |
| `maxFiles`                           | `useMultiUpload` / `useMultiFileUpload` only                                                                    |
| `multipart`                          | Split files ≥ 50 MB into parts (fixed threshold — server route must set `upload.multipart: true`)               |
| `checksum`                           | Send SHA-256 on presign. Filled from `api.catalog()` when the route sets `upload.checksum`                      |
| `uploadStore`                        | Resume after refresh                                                                                            |
| `onSuccess`                          | Called with `{ key, contentLength, … }` — persist `key`; enable download / delete on the same route when needed |

Hook `error` is a `DimahS3Error` (or `null`). Format with
`useFormatDimahError`. `api` is optional under `s3Client.Provider`. Full
types: `UseUploadOptions`, `UseMultiUploadOptions`.

Low-level `uploadFile` / `uploadFiles` also export from
`@dimah-s3/react/engine`.
