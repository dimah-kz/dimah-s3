A **route** is a named policy, not an HTTP path. The instance holds shared
infra (`client`, `bucket`, `plugins`, optional `guard`). Each route nests
`upload` / `download` / `delete` — upload owns constraints, object
identity, and opt-in `multipart`; the other features are toggles (or hook
objects).

The client sends the route name on every request. The server generates
object keys and enforces file constraints. Protocol paths stay
`/presign/upload`, `/presign/download`, and so on — do not put the name in
the URL (that would collide with plugin paths like `/db/objects`).

Unknown names return `404` with `UNKNOWN_ROUTE`. A missing name fails
validation (`400`). A disabled operation on that route returns `404`
`FEATURE_DISABLED`.

## One job per route

Enable upload, or download, or delete — not every operation "just in
case". Unused features are still reachable by anyone who knows a key in
that `keyPrefix` unless you add `guard` or [`db()`](/docs/db).

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({/* env */});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  guard: requireAuth,
  plugins: [db({ client: dimahS3Db, resolveScope })],
  routes: {
    uploads: route({
      upload: {
        fileTypes: ["image/*", "application/pdf"],
        maxFileSize: 10 * 1024 * 1024,
      },
    }),
    avatars: route({
      client: r2,
      bucket: "cdn-bucket",
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
        object: ({ file, request }) => ({
          key: `avatars/${userId(request)}/${file.name}`,
          metadata: { userId: userId(request) },
          acl: "public-read",
        }),
      },
    }),
    invoices: route({
      download: true,
    }),
    videos: route({
      upload: {
        fileTypes: ["video/*"],
        maxFileSize: 500 * 1024 * 1024,
        multipart: true,
      },
    }),
  },
});
```

`dimahS3()` with empty or missing `routes` throws. Names match
`^[a-zA-Z][a-zA-Z0-9_-]{0,63}$`. `route()` is an identity helper for
inference — `s3.$Infer.routes` is the union of those keys.

## Combining features

Put a second (or third) feature on the **same** route when those callers
work on the **same objects**. Confirm, download, delete, and multipart
follow-ups must stay under that route's `keyPrefix`, and prefixes cannot
overlap — you cannot split `attachments/…` across two route names.

```ts
attachments: route({
  upload: {
    fileTypes: ["image/*", "application/pdf"],
    maxFileSize: 10 * 1024 * 1024,
  },
  download: true,
  delete: true,
}),
```

Typical cases: a file manager, an attachment field with view + remove.
Public-read uploads (`acl: "public-read"`) often stay upload-only — the
CDN URL does not need `download`. Multipart is not a separate job; set
`upload.multipart: true` on the upload route.

## Inheritance

- **Instance (required unless every route overrides):** `client`, `bucket`.
  Also `basePath`, `plugins`, optional instance `guard`, `logger`,
  `onError`, `maxExpiresIn` (clamp).
- **Route:** optional `client` / `bucket` / `keyPrefix` override, optional
  `guard` for every op, nested features.
- **Upload:** `fileTypes`, `maxFileSize`, `object`, `acl`, `method`,
  `expiresIn`, `checksum`, `replace: "overwrite"`, and upload hooks.
- Do not put `basePath` or `plugins` on a route. Plugin opt-out is
  `plugins: { db: false }` on the route.

If the instance omits `client` or `bucket`, every route must set the
missing field or `dimahS3()` throws.

## Defaults

`upload`, `download`, `delete`, and `upload.multipart` are **off** until
set (`true` or an options object). A route with every operation off throws
at init. Enable only the operations that route needs. Omitting `upload`
with `download: true` is a download-only route.

`upload.multipart: true` uses the same `object` / `acl` as upload. It does
not turn on automatically with upload.

## Keys and object identity

The client does not send `key` on upload or multipart init. Default:

`{keyPrefix}/{uuid}/{sanitize(fileName)}`

`keyPrefix` defaults to the route name. Confirm, download, delete, and
multipart follow-ups reject keys outside that prefix (`INVALID_KEY`). Set
`keyPrefix: "users"` to write under `users/…`, or `keyPrefix: false` to
skip the follow-up check and generate `{uuid}/{name}` (no route folder).

`object` runs on upload / init and may return:

- `folder` — extra directory under `keyPrefix`; the library still appends
  `{uuid}/{name}`
- `key` — rest of the key, nested under `keyPrefix` unless it already
  starts with that prefix
- `metadata` — S3 user metadata
- `acl` — per-object override

A plain `Error` from `object` is **403**, same as `guard`.

```ts
route({
  upload: {
    object: ({ request, clientMetadata }) => ({
      folder: `users/${userId(request)}`,
      // uploads/users/{id}/{uuid}/{name}
      metadata: { author: userId(request), title: clientMetadata?.title ?? "" },
    }),
  },
});
```

Client `metadata` on the request is **not** written to S3 unless `object`
copies it.

Confirm, multipart follow-ups, download, and delete send the **stored**
key from the presign response, plus the same route name. `object` is not
re-run. `keyPrefix` only bounds the folder — authorize with route `guard`
or [`db()`](/docs/db) for ownership.

## Constraints

`fileTypes` and `maxFileSize` live on `upload`.

- `fileTypes` — same tokens as HTML `accept`. Checked at presign (declared
  type / name) and again at confirm / multipart complete (HeadObject +
  filename). Matches the S3 `Content-Type` header and name, not file bytes.
- `maxFileSize` — presign `fileSize`, each multipart `partSize`, listed
  uploaded parts + the part being signed, and HeadObject `contentLength`.
  Oversize after landing rejects confirm and best-effort `DeleteObject`.
  Oversize at multipart complete aborts the in-progress upload.

Upload and multipart init always require `fileName` + `fileSize`.

## Client

```ts
useUpload({ route: "uploads" })
useDownload({ route: "invoices" })  // download(storedKey)

const upload = useUpload({ route: "uploads" })
<UploadButton upload={upload} />
```

Download or delete of keys created by `uploads` belongs on that same route
— enable the extra feature there, do not add a second route for the same
prefix.

Client `accept` / `maxFileSize` are filled from `GET /routes` when omitted
(`api.catalog()`). The server still enforces `upload.fileTypes` /
`upload.maxFileSize`. Multi-file limits (`maxFiles`) stay on the client —
each request is one file.

`GET /routes` is the route catalog: which features are on, plus
`fileTypes`, `maxFileSize`, `multipart`, `checksum`, `replace`, and
download `disposition` / `mode`.

To replace an existing key (avatars), set `upload.replace: "overwrite"`
and return a stable `key` from `object`. `object` may also return
`previousKey` — after confirm, that object is deleted.

Lock a SHA-256 into the signed PUT/POST with `upload.checksum: true`. The
React engine sends `sha256File` when the catalog reports checksum.

Download `disposition` defaults to `"attachment"`. `"inline"` is for
preview. `download.mode: "proxy"` returns a same-origin `/file` URL that
streams through your server instead of a bucket URL. `download.resolve`
can override `fileName`, `disposition`, and `expiresIn` per request.
