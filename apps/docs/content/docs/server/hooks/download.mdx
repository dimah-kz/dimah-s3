---
title: Download Hooks
description: Authorize downloads, set the file name, disposition, and link lifetime per request, and control which types open in the browser.
---

Download hooks run each time a client asks for a download URL on a
[route](/docs/server/routes) with `download` turned on. Use them to authorize
the key and to shape the URL.

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";
import { awsS3 } from "./aws-s3";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      download: {
        disposition: "inline",
        guard: async ({ key, locals }) => {
          if (!(await ownsAvatar(locals.userId, key)))
            throw s3Error("FORBIDDEN");
        },
      },
    }),
  },
});
```

The key must sit under the route's `keyPrefix`, or the call returns
`KEY_INVALID`. That is not ownership: a guard that only checks for a session
lets any signed-in user download any key they know. See
[Security](/docs/server/security#route-namespace-vs-ownership).

## Download lifecycle

<Flow
  label="Download flow"
  steps={[

    { name: "download.guard", kind: "hook" },
    { name: "HeadObject", kind: "s3" },
    { name: "onPresigned", kind: "hook" },
    { name: "Fetch from S3", kind: "client" },
  ]}
/>

1. **`resolve`** can replace the download `name`, the `disposition`, the
   `expiresIn`, and, in proxy mode, `cacheControl`.
2. **`guard`** authorizes the request with the values that will be used.
   `expiresIn` is the TTL that will be signed, or `undefined` in proxy mode.
3. **HeadObject** reads the stored type, to decide whether `inline` is
   allowed. A missing object returns `OBJECT_NOT_FOUND`.
4. **`onPresigned`** receives the URL and the disposition that was signed.

The response is `{ key, bucket, url, disposition, mode, expiresIn }`. In
proxy mode (`mode: "proxy"`), the URL points to
[`GET /file`](/docs/server/file-proxy), `expiresIn` is left out, and every
request to that URL runs the guards again.

## Link lifetime

A client may send `expiresIn` with the download request:

- The signed TTL is the shorter of that value and `download.maxExpiresIn`
  (600 seconds by default). Without one, it is `download.maxExpiresIn`.
- An `expiresIn` returned from `resolve` replaces both, including with a value
  above the route cap. It is still capped by the instance `maxExpiresIn`
  (7 days at most).
- `GET /routes` reports the cap as `download.maxExpiresIn`.

```ts
files: route({
  download: {
    maxExpiresIn: 60 * 60 * 24,
  },
}),
```

## Open in the browser only for known types

A client can ask for `disposition: "inline"`. The server keeps it only for
types on the route's allow-list, and signs everything else as `attachment`.
The default list is `DEFAULT_INLINE_TYPES` from `@dimah-s3/core`:

- `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/avif`,
  `image/bmp`
- `application/pdf` (presign mode only)
- `audio/*`, `video/*`
- `text/plain`

Set `inlineTypes` to change it, or `false` to never open inline:

```ts title="lib/s3.ts"
files: route({
  download: {
    inlineTypes: ["image/*", "application/pdf", "video/mp4"],
  },
}),
```

The server checks the type HeadObject reports:

- On the list, the requested `inline` is kept. `image/*` matches the same way
  as `upload.fileTypes`.
- Anything else is signed as `attachment`, whatever the client asked for.
- A wildcard never matches types that run as a page: HTML, any XML (including
  `image/svg+xml`), and JavaScript. List one exactly to allow it.
- An object stored as `application/octet-stream` is typed from its file name.
  When that type is allowed, it is signed as `ResponseContentType` so the
  browser renders it.

`GET /routes` returns the effective list as `download.inlineTypes`. Pass it to
`resolveInlineDisposition` from `@dimah-s3/core` to choose Preview or Download
on the client with the server's rule. The same helper works inside `resolve`.

## Set the file name

Return `name` from `resolve` to set the downloaded file name per request:

```ts
avatar: route({
  download: {
    resolve: async ({ key }) => {
      const user = await getUserByAvatarKey(key);
      return { name: `${user.username}-avatar.png`, disposition: "attachment" };
    },
  },
}),
```

## API Reference

Every context has `request`, `operation`, `locals`, and `route` from the
[guard context](/docs/server/hooks/global-guard#api-reference), plus `key`
and `bucket`. The route options are in
[Routes](/docs/server/routes#download).

### download.resolve

Receives a `DownloadResolveContext`:

| Property      | Type                       | Description                                 |
| ------------- | -------------------------- | ------------------------------------------- |
| `mode`        | `"presign" \| "proxy"`     | The route's download mode                   |
| `name`        | `string`                   | File name the client asked for              |
| `disposition` | `"inline" \| "attachment"` | Requested disposition, or the route default |
| `expiresIn`   | `number`                   | TTL the client asked for. Presign mode only |

Returns a `DownloadResolveInfo`, or nothing:

| Property       | Type                       | Description                                                                          |
| -------------- | -------------------------- | ------------------------------------------------------------------------------------ |
| `name`         | `string`                   | Download file name                                                                   |
| `disposition`  | `"inline" \| "attachment"` | Requested disposition. The inline allow-list still applies                           |
| `expiresIn`    | `number`                   | Signed TTL in seconds, capped by the instance `maxExpiresIn`. Presign mode only      |
| `cacheControl` | `string`                   | `Cache-Control` on `/file` responses. Proxy mode only. Default `"private, no-cache"` |

### download.guard

`DownloadGuardContext`, with the values that will be used:

| Property      | Type                       | Description                           |
| ------------- | -------------------------- | ------------------------------------- |
| `mode`        | `"presign" \| "proxy"`     | The route's download mode             |
| `name`        | `string`                   | Download file name                    |
| `disposition` | `"inline" \| "attachment"` | Requested disposition                 |
| `expiresIn`   | `number`                   | Signed TTL. `undefined` in proxy mode |

### download.onPresigned

`DownloadOnPresignedContext`: everything in `download.guard`, with the
disposition that was signed, plus:

| Property | Type     | Description                                         |
| -------- | -------- | --------------------------------------------------- |
| `url`    | `string` | Presigned GET URL, or the `/file` URL in proxy mode |
