---
title: Upload Hooks
description: Authorize uploads, track them from presign to confirm, persist the verified object, and undo work when an upload is rejected.
---

Upload hooks run around each upload on a [route](/docs/server/routes) with
`upload` turned on. Use them to authorize the upload, record it, and save the
object S3 verified.

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";
import { awsS3 } from "./aws-s3";

declare module "@dimah-s3/server" {
  interface DimahS3Locals {
    userId?: string;
  }
}

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  guard: async ({ request }) => {
    const session = await getSession(request);
    if (!session) throw s3Error("UNAUTHORIZED");
    return { locals: { userId: session.userId } };
  },
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
        onConfirmed: async ({ key, object, locals }) => {
          // object.size comes from HeadObject, not from the browser.
          await db.user.update({
            where: { id: locals.userId },
            data: { avatarKey: key, avatarSize: object.size },
          });
        },
      },
    }),
  },
});
```

Presign and confirm are separate calls, so `locals` from `upload.guard` do not
reach `onConfirmed`. Set values both need in the instance or route guard, as
above: they run on every call.

## Upload lifecycle

<Flow
  label="Upload lifecycle"
  steps={[
    { name: "route.guard", kind: "hook" },
    { name: "object", kind: "hook" },
    { name: "upload.guard", kind: "hook" },
    { name: "onStart", kind: "hook" },
    { name: "Upload to S3", kind: "client" },
    { name: "HeadObject", kind: "s3" },
    { name: "confirmGuard", kind: "hook" },
    { name: "onConfirmed", kind: "hook" },
  ]}
/>

1. **`route.guard`** runs after the instance guard, before the key is chosen.
   The declared file is then checked against `fileTypes` and `maxFileSize`.
2. **`upload.object`** chooses the key and object settings. It runs before
   `upload.guard`, so read the caller from `locals` set by an earlier guard.
3. **`upload.guard`** authorizes the upload with the server-owned key.
4. **`onStart`** runs once the upload can begin, with its `uploadToken` and
   confirm deadline. The presign response, with its
   [upload ticket](/docs/server/upload-tickets), is returned after it.
5. **Confirm** reads the stored object with HeadObject. It checks the upload
   marker, the stored size against the declared size
   (`UPLOAD_SIZE_MISMATCH`), and the route limits. With `verifyContent`, it
   checks the first bytes too.
6. **`confirmGuard`** authorizes the stored object. Check `object`, the
   verified values, not `file`, the declared ones. A rejection deletes the
   object.
7. **`onConfirmed`** receives the verified `object` and the `previousKey` the
   server deletes next. Persist your record here.

When step 5 or 6 refuses the upload, the object is deleted and
[`onRejected`](#when-an-upload-is-rejected) runs instead of `onConfirmed`.

`upload.guard` and `onStart` also run for multipart init and `s3.put`. `kind`
tells them apart:

| `kind`            | Upload                                           |
| ----------------- | ------------------------------------------------ |
| `"presignedPut"`  | Presigned PUT from the browser                   |
| `"presignedPost"` | Presigned POST form from the browser             |
| `"multipart"`     | [Multipart](/docs/server/hooks/multipart) upload |
| `"server"`        | `s3.put`. Skips `confirmGuard`                   |

`kind` is not `operation`: `s3.put` runs with `operation: "put"` and
`kind: "server"`.

## Track an upload

Record a pending upload in `onStart`. Its `expiresAt` is the deadline after
which the upload can never be confirmed:

```ts
upload: {
  onStart: async ({ uploadToken, key, file, expiresAt, locals }) => {
    await db.upload.create({
      data: { token: uploadToken, key, name: file.name, userId: locals.userId, expiresAt },
    });
  },
  onConfirmed: async ({ uploadToken, object }) => {
    await db.upload.updateMany({
      where: { token: uploadToken, status: "pending" },
      data: { status: "active", size: object.size },
    });
  },
},
```

`expiresAt` is the ticket expiry, or 15 minutes from now for `s3.put`.
Presigned uploads also get `url` and `urlExpiresAt`; multipart uploads get
`uploadId`.

## When an upload is rejected

`onRejected` runs after confirm, multipart complete, or `s3.put` refused an
upload and deleted its object. That happens when the stored size, type, or
content does not match, when `confirmGuard` rejects, or when a plugin rejects
the object. Undo what `onStart` recorded:

```ts
upload: {
  onStart: async ({ uploadToken, key }) => {
    await db.upload.create({ data: { token: uploadToken, key } });
  },
  onRejected: async ({ uploadToken, error }) => {
    await db.upload.deleteMany({ where: { token: uploadToken } });
    console.log("Upload refused:", error.code);
  },
},
```

- `error` is the `APIError` the client receives.
- A throw from `onRejected` is logged and passed to `onError`. It never
  replaces the rejection, and the hooks after it still run.
- It does not run when the object is kept (an infrastructure failure, or a
  throw from your own `onConfirmed`), or for an upload that was never
  confirmed. Expire those pending records on `onStart`'s `expiresAt`.

## Failure rules

| Hook                  | When it throws                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| `upload.guard`        | The error is returned. Nothing exists in S3                                                        |
| `onStart`             | The error is returned. A multipart upload is aborted; `s3.put` skips PutObject                     |
| `confirmGuard`        | A rejection (`4xx`) deletes the object and runs `onRejected`                                       |
| `onConfirmed`, plugin | A rejection (`4xx`) deletes the object and runs `onRejected`. Any other throw keeps it for a retry |
| `onConfirmed`, yours  | The object is kept, and the call returns `500 INTERNAL_ERROR`                                      |
| `onRejected`          | Logged and passed to `onError`. The client still gets the rejection                                |

A confirm that fails for an infrastructure reason, such as an S3 network
error or a guard whose database is down, keeps the object so the client can
retry.

`onConfirmed` runs **at least once** per upload. Confirm is stateless, so a
retried confirm runs every check and hook again with the same `uploadToken`.
Make the hook safe to replay, and reject content in `confirmGuard`, not in
`onConfirmed`.

## API Reference

Every context has `request`, `operation`, `locals`, and `route` from the
[guard context](/docs/server/hooks/global-guard#api-reference). The tables
list what each one adds. `UploadFile` is `{ name, size, type? }`, the file the
client declared.

### upload.object

`UploadObjectContext`. It returns the
[`upload.object` result](/docs/server/routes#api-reference).

| Property         | Type                     | Description                                                             |
| ---------------- | ------------------------ | ----------------------------------------------------------------------- |
| `file`           | `UploadFile`             | The declared file                                                       |
| `bucket`         | `string`                 | Target bucket                                                           |
| `keyPrefix`      | `string \| false`        | The route namespace. With `false`, the default key is `{uuid}/{name}`   |
| `clientMetadata` | `Record<string, string>` | What the client sent. Written to S3 only if you copy it into `metadata` |

### upload.guard

`UploadGuardContext`.

| Property                                  | Type                         | Description                                      |
| ----------------------------------------- | ---------------------------- | ------------------------------------------------ |
| `key`                                     | `string`                     | The key that will be written                     |
| `bucket`                                  | `string`                     | Target bucket                                    |
| `kind`                                    | `UploadKind`                 | How the bytes reach S3                           |
| `file`                                    | `UploadFile`                 | The declared file                                |
| `acl`                                     | `"private" \| "public-read"` | Effective ACL                                    |
| `metadata`                                | `Record<string, string>`     | S3 metadata from `upload.object`                 |
| `clientMetadata`                          | `Record<string, string>`     | Client extras. Never written to S3 automatically |
| `storageClass`, `cacheControl`, `tagging` | from `upload.object`         | Object settings that will be signed              |

### upload.onStart

`UploadOnStartContext`: everything in `upload.guard`, plus:

| Property       | Type     | Description                                                             |
| -------------- | -------- | ----------------------------------------------------------------------- |
| `uploadToken`  | `string` | Stable id of this upload. Dedupe `onConfirmed` replays on it            |
| `expiresAt`    | `Date`   | Confirm deadline: the ticket expiry, or 15 minutes for `s3.put`         |
| `url`          | `string` | Presigned URL. `presignedPut` and `presignedPost` only                  |
| `urlExpiresAt` | `Date`   | When the presigned URL expires. `presignedPut` and `presignedPost` only |
| `uploadId`     | `string` | Multipart only                                                          |

### upload.confirmGuard

`UploadConfirmGuardContext`. Runs on confirm and multipart complete, after
HeadObject and the size, type, and content checks.

| Property      | Type                         | Description                               |
| ------------- | ---------------------------- | ----------------------------------------- |
| `key`         | `string`                     | The uploaded key                          |
| `bucket`      | `string`                     | Target bucket                             |
| `kind`        | `UploadKind`                 | Never `"server"`                          |
| `uploadToken` | `string`                     | Stable id of this upload                  |
| `object`      | `VerifiedObject`             | The object as HeadObject reports it       |
| `file`        | `UploadFile`                 | The declared file. Check `object` instead |
| `acl`         | `"private" \| "public-read"` | ACL from the upload policy                |
| `uploadId`    | `string`                     | Multipart only                            |

### upload.onConfirmed

`UploadOnConfirmedContext`: everything in `confirmGuard`, with `kind` that can
be `"server"`, plus:

| Property      | Type     | Description                                                                   |
| ------------- | -------- | ----------------------------------------------------------------------------- |
| `previousKey` | `string` | `upload.object().previousKey`, deleted once every `onConfirmed` hook succeeds |

### upload.onRejected

`UploadOnRejectedContext`.

| Property      | Type                         | Description                                          |
| ------------- | ---------------------------- | ---------------------------------------------------- |
| `key`         | `string`                     | The deleted key                                      |
| `bucket`      | `string`                     | Target bucket                                        |
| `kind`        | `UploadKind`                 | How the bytes reached S3                             |
| `uploadToken` | `string`                     | Stable id of this upload                             |
| `error`       | `APIError`                   | Why the upload was refused. The client gets the same |
| `file`        | `UploadFile`                 | The declared file                                    |
| `acl`         | `"private" \| "public-read"` | ACL from the upload policy                           |
| `uploadId`    | `string`                     | Multipart only                                       |

### VerifiedObject

The `object` in `confirmGuard` and `onConfirmed`. Trust these values, not the
declared `file`.

| Property       | Type                     | Description                                   |
| -------------- | ------------------------ | --------------------------------------------- |
| `size`         | `number`                 | Stored size in bytes                          |
| `type`         | `string`                 | Stored content type                           |
| `name`         | `string`                 | Stored file name                              |
| `eTag`         | `string`                 | ETag, without quotes                          |
| `versionId`    | `string`                 | Version id on a versioned bucket              |
| `lastModified` | `string`                 | ISO 8601 timestamp                            |
| `metadata`     | `Record<string, string>` | User metadata, decoded, without internal keys |

## Frequently asked questions

<Accordions>

<Accordion title="Why record the file size in onConfirmed, not at presign?">

In `onConfirmed`, `object.size` comes from S3 HeadObject. `file` in the
earlier hooks holds what the browser declared. Confirm also rejects an object
whose stored size differs from the declared one.

</Accordion>

<Accordion title="How do I attach custom S3 user metadata?">

Return `metadata` from `upload.object`. What the client sends is
`clientMetadata`, and it is never written to S3 unless you copy it:

```ts
avatar: route({
  upload: {
    object: ({ file, clientMetadata }) => ({
      metadata: {
        "original-name": file.name,
        album: clientMetadata?.album ?? "default",
      },
    }),
  },
}),
```

Keys and values share a 2 KB budget, and non-ASCII values are encoded for
you. In `onConfirmed`, `object.metadata` returns them decoded.

</Accordion>

</Accordions>
