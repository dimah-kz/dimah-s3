---
title: Delete Hooks
description: Authorize deletes, clean up your records after S3 removes an object, and delete up to 100 keys of one route in one call.
---

Delete hooks run when a client deletes an object on a
[route](/docs/server/routes) with `delete` turned on. Deletes run on your
server with `DeleteObject` after the guards pass; the client never deletes
from S3 directly.

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";
import { awsS3 } from "./aws-s3";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      delete: {
        guard: async ({ key, locals }) => {
          if (!(await ownsAvatar(locals.userId, key)))
            throw s3Error("FORBIDDEN");
        },
        onDeleted: async ({ locals }) => {
          await db.user.update({
            where: { id: locals.userId },
            data: { avatarKey: null },
          });
        },
      },
    }),
  },
});
```

<Callout type="warn" title="delete: true is not an ownership check">
  `delete: true` turns the endpoint on. Anyone who can call it can delete any
  key they know under the route's `keyPrefix`; keys outside it always return
  `KEY_INVALID`. Check ownership in `delete.guard`, or use [`db()`](/docs/db).
  See [Security](/docs/server/security#route-namespace-vs-ownership).
</Callout>

## Delete lifecycle

<Flow
  label="Delete flow"
  steps={[
    { name: "route.guard", kind: "hook" },
    { name: "delete.guard", kind: "hook" },
    { name: "DeleteObject", kind: "s3" },
    { name: "onDeleted", kind: "hook", note: "Database cleanup" },
  ]}
/>

- Before `delete.guard`, the server rejects keys outside the route's
  `keyPrefix` with `KEY_INVALID`.
- Delete is idempotent. A key that never landed, or one already gone,
  succeeds and still runs `onDeleted`, so the records of a pending or expired
  upload are cleaned up.
- The S3 call does not stop when the client disconnects, so `onDeleted` runs
  for every delete that happened.
- The response is `{ key, bucket }`.

## Delete many keys

`deleteMany` (`POST /delete/batch`) deletes up to 100 keys of one route
(`DELETE_MANY_MAX_KEYS`) in one DeleteObjects request:

```ts
const { deleted, failed } = await s3.api.deleteMany(
  { route: "avatar", keys: [key1, key2] },
  { headers: await headers() },
);
// failed: [{ key, error: { code, message, params? } }]
```

- The route guard runs once for the call.
- Each key is checked against the route namespace and `delete.guard`, with
  its own copy of `locals`.
- `onDeleted` runs for each deleted key.
- A per-key failure (an invalid key, a guard, an S3 error, or an `onDeleted`
  throw) goes into `failed` and does not fail the other keys.
- A route error, such as `ROUTE_NOT_FOUND` or a route guard rejection, fails
  the whole call. So does a DeleteObjects request that fails as a whole.

In React, `removeMany` from [`useDelete`](/docs/react/hooks/delete) calls
`deleteMany`:

```ts
const { removeMany } = useDelete({ route: "avatar" });
const { deleted, failed } = await removeMany([key1, key2]);
```

## When S3 fails

`onDeleted` does not run for a delete S3 refused. A single delete returns an
error such as `502 S3_NETWORK_ERROR` or `500 INTERNAL_ERROR`. In
`deleteMany`, a key S3 refused is reported in `failed` with `INTERNAL_ERROR`;
the S3 error itself is logged and passed to `onError`.

## API Reference

`delete.guard` and `delete.onDeleted` receive the same context
(`DeleteGuardContext`, `DeleteOnDeletedContext`): `request`, `operation`,
`locals`, and `route` from the
[guard context](/docs/server/hooks/global-guard#api-reference), plus:

| Property | Type     | Description              |
| -------- | -------- | ------------------------ |
| `key`    | `string` | The object key to delete |
| `bucket` | `string` | The route's bucket       |

`operation` is `"delete"` for a single delete and `"deleteMany"` in a batch.
The route options are in [Routes](/docs/server/routes#delete).
