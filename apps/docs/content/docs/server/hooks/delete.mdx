---
title: Delete Hooks
description: Authorize deletion and execute cleanup after S3 removes the object.
---

Enable object deletion with `delete: true` or a `DeleteConfig` object on a [named route](/docs/server/routes).

<Callout>
  Unlike upload and download, object deletion is executed directly on your
  server using `DeleteObjectCommand` after passing `guard` checks. The client
  never deletes from S3 directly.
</Callout>

<Callout type="warn">
  `delete: true` turns the endpoint on. It does not check who owns the object.
  The key must still sit under this route's `keyPrefix` (the route name by
  default) — that check always runs, with or without [`db()`](/docs/db).
  Ownership is `delete.guard` or the db plugin. See
  [Security](/docs/server/security#route-namespace-vs-ownership).
</Callout>

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, errors, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({/* env */});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      delete: {
        guard: async ({ key, request }) => {
          const session = await getSession(request);
          if (!session) throw errors.unauthorized();

          const isOwner = await checkAvatarOwnership(session.userId, key);
          if (!isOwner) throw errors.forbidden();
        },
        onDeleted: async ({ key, request }) => {
          const session = await getSession(request);
          await db.user.update({
            where: { id: session.userId },
            data: { avatarKey: null },
          });
        },
      },
    }),
  },
});
```

## Delete lifecycle flow

Before `delete.guard`, the server resolves the named route and rejects keys
outside its `keyPrefix` (`INVALID_KEY`).

## Frequently asked questions

<Accordions>

<Accordion title="Can anyone delete any object if I enable delete without a guard?">

Anyone who can call the endpoint can delete any **in-namespace** key they
know — not the whole bucket, and not keys on other routes. A UUID in the path
is not an access check. Ownership is `delete.guard` or [`db()`](/docs/db). See
[Security](/docs/server/security#route-namespace-vs-ownership).

</Accordion>

<Accordion title="How do I delete multiple files at once?">

Use `deleteMany` on the server API or `removeMany` in the React client. Batch
deletion runs `delete.guard` and S3 `DeleteObject` for each key, then
triggers `onDeleted` for each successfully removed key:

```ts title="Client usage"
const { removeMany } = useDelete({ route: "avatar" });
await removeMany([key1, key2]);
```

</Accordion>

<Accordion title="What happens if S3 deletion fails?">

`onDeleted` does not run for a failed S3 deletion. The endpoint returns an
error response such as `502 S3_NETWORK_ERROR` or `INTERNAL_ERROR`.

</Accordion>

</Accordions>
