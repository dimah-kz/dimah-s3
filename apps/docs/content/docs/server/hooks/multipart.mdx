---
title: Multipart
description: Lifecycle hooks for large-file uploads.
---

Enable with `multipart: true` on a [named route](/docs/server/routes).
Default is **off** — it does not turn on with upload. Pair it with client
`multipart: true` — see [Upload](/docs/react/hooks/upload).

Multipart **complete** is the confirmation step (HeadObject after S3
assembles the parts). There is no extra `confirm` call. Persist in
`onComplete` the same way you persist in `upload.onConfirmed`.

<Flow
  label="Multipart complete"
  steps={[
    { name: "initGuard", kind: "hook" },
    { name: "onInit", kind: "hook" },
    { name: "partGuard", kind: "hook", note: "each part" },
    { name: "completeGuard", kind: "hook" },
    { name: "HeadObject", kind: "server" },
    { name: "onComplete", kind: "hook" },
  ]}
/>

Abort is a separate path: `abortGuard` → `onAbort`. Listing parts:
`listGuard` → `onList`.

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, errors, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({/* env */});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    videos: route({
      multipart: true,
    }),
  },
});
```

<Callout>
  `fileSize` on init is what the client sent. `contentLength` on `onComplete`
  comes from `HeadObject`.
</Callout>

Set `multipart: true` on the route. Multipart uses the same `object`
and `acl` as upload. Plugins still receive the granular
`initGuard` / `onComplete` / … hooks.

The complete body only sends `partNumber`s. The server lists parts from S3
for ETags and rejects a missing part with `MULTIPART_PART_MISSING`.
