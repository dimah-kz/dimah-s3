title: Multipart
description: Lifecycle hooks for large-file uploads.
---

Enable with `multipart: { enabled: true }`. Pair it with client
`multipart` options — see [Upload](/docs/react/hooks/upload).

Abort is a separate path: `abortGuard` → `onAbort`. Listing parts:
`listGuard` → `onList`.

```ts title="lib/s3.ts"
import { dimahS3, DimahS3Error } from "@dimah-s3/server";
import { s3Client, defaultBucket } from "@/lib/s3-client";

export const s3 = dimahS3({
  s3: s3Client,
  defaultBucket,
  multipart: {
    enabled: true,
    initGuard: async ({ fileSize }) => {
      if (fileSize && fileSize > 5 * 1024 * 1024 * 1024) {
        throw new DimahS3Error("File too large", 413);
      }
    },
    onComplete: async ({ key, contentLength }) => {
      // persist { key, size: contentLength }
    },
    onAbort: async ({ key, uploadId }) => {
      // drop any pending row for `{ key, uploadId }`
    },
  },
});
```

<Callout>
  `fileSize` on init is what the client sent. `contentLength` on `onComplete`
  comes from `HeadObject`.
</Callout>

Set `requireFileSize: true` to reject init without `fileSize`.

<Accordion title="Other hooks">

| Hook            | When                 | Extra                     |
| --------------- | -------------------- | ------------------------- |
| `onInit`        | After init           | `uploadId`                |
| `partGuard`     | Before each part URL | `partNumber`, `partSize?` |
| `completeGuard` | Before complete      | `parts`                   |
| `abortGuard`    | Before abort         | `uploadId`                |
| `onAbort`       | After abort          | `uploadId`                |
| `listGuard`     | Before listing parts | `uploadId`                |
| `onList`        | After listing parts  | `parts`                   |

</Accordion>
