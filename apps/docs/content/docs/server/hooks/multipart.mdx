---
title: Multipart
description: Large-file uploads as an opt-in under upload.
---

Enable with `upload.multipart: true` on a [named route](/docs/server/routes).
Default is **off** — it does not turn on with upload. Pair it with client
`multipart: true` — see [Upload](/docs/react/hooks/upload).

Init and complete reuse upload hooks. Persist in `upload.onConfirmed` for
both simple confirm and multipart complete — there is no second `confirm`
call.

Abort and list are the remaining unique steps: `sessionGuard` (`action:
"abort"` / `"list"`) → `onAbort` / `onList`. Complete also runs
`sessionGuard` (`action: "complete"`) before `confirmGuard`.

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({/* env */});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    videos: route({
      upload: {
        fileTypes: ["video/*"],
        maxFileSize: 500 * 1024 * 1024,
        multipart: true,
        onConfirmed: async ({ key, contentLength }) => {
          // persist { key, size: contentLength }
        },
      },
    }),
  },
});
```

<Callout>
  `fileSize` on init is what the client sent. `contentLength` on `onConfirmed`
  comes from `HeadObject`.
</Callout>

Multipart uses the same `object` and `acl` as upload. Most apps only set
`multipart: true`. Unique hooks live on the same object when you need
resume cleanup or per-part checks.

The complete body only sends `partNumber`s. The server lists parts from S3
for ETags and rejects a missing part with `MULTIPART_PART_MISSING`.
`signPart` requires `partSize`; that byte length is locked into the
presigned URL. When `maxFileSize` is set, a part that is itself over the
cap — or that would push **already uploaded** parts over it — is rejected
with `PAYLOAD_TOO_LARGE`. Complete sums listed part sizes and aborts the
MPU if over, before assembly.

## On init

Runs after `CreateMultipartUpload`. Use this to store `uploadId` for
resume. Init authorization is `upload.guard`.

## Session guard

Runs before each part URL, list, abort, and complete — an in-progress
upload, not the start. Branch on `action` if you need different rules.
Complete also runs `upload.confirmGuard`.
