dimah-s3 follows a **presign-first** security model: AWS credentials remain on the server, while clients upload directly to storage via short-lived signed URLs.

<Callout type="warn">
  Never expose S3 credentials in the browser or client bundles. S3 clients must
  always run server-side.
</Callout>

## Security model

1. **Server owns keys** — The client requests an upload for a named `route`. The server decides the destination key path (`avatar/{uuid}/{fileName}` or customized via `object`).
2. **Namespace isolation** — With the default `keyPrefix`, confirm, download, and delete follow-ups are restricted to the route namespace. Requests outside it fail with `INVALID_KEY`.
3. **Verified metadata via `HeadObject`** — Presign payloads (size/type) are untrusted. Stored byte length and `Content-Type` metadata are read server-side via `HeadObject` in `upload.onConfirmed`.
4. **Guards and authorization** — Route `guard` and feature guards (`upload.guard`, `download.guard`, `delete.guard`) control per-user authorization.

<Callout type="warn" title="Disabling keyPrefix removes route isolation">
  `keyPrefix: false` allows follow-up operations to target any safe key in the
  bucket. Use it only when strict route or operation guards enforce the complete
  ownership policy.
</Callout>

## Scoping objects & user tenancy

Use `upload.object` to isolate files by tenant or user ID:

```ts title="lib/s3.ts"
import { dimahS3, errors, route } from "@dimah-s3/server";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      guard: async ({ request }) => {
        const session = await getSession(request);
        if (!session) throw errors.unauthorized();
      },
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
        object: async ({ request }) => {
          const session = await getSession(request);
          return {
            folder: `users/${session.userId}`,
            // Generates: avatar/users/{userId}/{uuid}/{fileName}
          };
        },
        onConfirmed: async ({ key, contentLength, request }) => {
          // Trusted stored size and server-owned key from S3 HeadObject
          const session = await getSession(request);
          await db.user.update({
            where: { id: session.userId },
            data: { avatarKey: key, avatarSize: contentLength },
          });
        },
      },
      download: true,
      delete: true,
    }),
  },
});
```

## Object ACL

Uploads are `private` by default. Set `acl` on the route or return it dynamically from `upload.object`:

```ts
avatar: route({
  upload: {
    acl: "public-read",
    fileTypes: ["image/*"],
    maxFileSize: 2 * 1024 * 1024,
  },
}),
```

## Hook error mapping

| Hook Location                                      | Plain `Error` Thrown   | `errors.*` / `APIError` |
| -------------------------------------------------- | ---------------------- | ----------------------- |
| `guard` / `*Guard` / `object`                      | **403 Forbidden**      | Custom status & code    |
| `on*` lifecycle hooks (`onConfirmed`, `onDeleted`) | **500 Internal Error** | Custom status & code    |

<Accordion title="How do I verify the true MIME type (magic bytes) of an uploaded file?">

Read the object header with your configured, server-only S3 client and inspect it
in `onConfirmed`. The hook context contains the bucket and key, but not an S3
client:

```ts title="lib/s3.ts"
import { GetObjectCommand } from "@aws-sdk/client-s3";
import { sniffContentType } from "@dimah-s3/core";
import { dimahS3, errors, route } from "@dimah-s3/server";
import { awsS3 } from "./aws-s3";

const bucket = process.env.S3_BUCKET!;
const allowedTypes = new Set(["image/png", "image/jpeg", "image/webp"]);

export const s3 = dimahS3({
  client: awsS3,
  bucket,
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/png", "image/jpeg", "image/webp"],
        onConfirmed: async ({ key, fileName }) => {
          const response = await awsS3.send(
            new GetObjectCommand({
              Bucket: bucket,
              Key: key,
              Range: "bytes=0-15",
            }),
          );
          if (!response.Body) throw errors.objectNotFound();

          const bytes = await response.Body.transformToByteArray();
          const detectedType = sniffContentType(bytes);
          if (!detectedType || !allowedTypes.has(detectedType)) {
            throw errors.fileTypeNotAllowed(fileName ?? key, detectedType);
          }
        },
      },
    }),
  },
});
```

The normal presign and `HeadObject` checks still run. If this stricter check
throws, dimah-s3 performs a compensating delete so the rejected object is not
left in S3.

</Accordion>

<Accordion title="How do I prevent users from deleting or downloading other users' files?">

Use `guard` on download/delete or use the [`@dimah-s3/db`](/docs/db) plugin for automatic scope isolation:

```ts
avatar: route({
  delete: {
    guard: async ({ key, request }) => {
      const session = await getSession(request);
      const isOwner = await checkAvatarOwnership(session.userId, key);
      if (!isOwner) throw errors.forbidden();
    },
  },
}),
```
