dimah-s3 signs URLs. It does not authenticate users, enforce quotas, or pick
object keys. Those stay in your `guard` and `object` hooks.

<Callout type="warn">
  Never put S3 credentials in the browser. Keep the AWS SDK `S3Client` on the
  server and pass it into `dimahS3({client})`.
</Callout>

## Untrusted input

The client sends a **route name**, plus `fileName` / `fileSize` /
`contentType` / `metadata` on upload. After upload, later ops send the
**stored** `key` from the presign response. Treat all of them as untrusted.

| Field                          | Default                              | How to scope it                                                                                      |
| ------------------------------ | ------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `route`                        | required                             | Must match a name in `routes` (`UNKNOWN_ROUTE` otherwise)                                            |
| `key` (upload / init)          | **not sent** — server generates it   | `upload.object` (`folder` / `key`) nested under `keyPrefix` (default `{route}/{uuid}/{name}`)        |
| `key` (confirm / later)        | stored key from the presign response | Must stay under route `keyPrefix`; then `guard` / db — `object` is not re-run                        |
| `bucket` / `acl` / `expiresIn` | never accepted from the client       | Route `bucket` / `upload.acl` / `upload.expiresIn` / `download.expiresIn`                            |
| `fileSize` / `contentType`     | required on upload / init            | Also enforce `fileTypes` / `maxFileSize`; trust HeadObject                                           |
| `partSize`                     | required on `multipart.signPart`     | Locked into the part URL `Content-Length`; capped by `maxFileSize` (including listed uploaded parts) |

## Keys

The server generates keys on upload and multipart init. Confirm, download,
and delete reuse the stored key — they do not re-run `object`. Follow-up
keys must stay under the route **`keyPrefix`** (default: the route name) or
the request fails with `INVALID_KEY`. That stops `uploads` from targeting
`avatars/…` on the same bucket. Nested prefixes (`media` vs
`media/private`) are rejected at init. `keyPrefix: false` turns the
follow-up check off and generates `{uuid}/{name}` (no route folder).

- Default key is `{keyPrefix}/{uuid}/{sanitize(fileName)}`.
- `object` returns `{ folder?, key?, metadata?, acl? }` on upload / init
  only. `folder` and `key` are nested under `keyPrefix` unless they already
  sit inside it. Store and send back the `key` from the response. Client
  `metadata` is not written to S3 unless `object` copies it.
- A plain `Error` from `object` is **403**, same as `guard`.
- Unsafe keys fail with `INVALID_KEY`: empty, backslash, NUL, `.` / `..`
  segments, empty path segments, or outside `keyPrefix`.

`keyPrefix` is a folder bound, not per-user ownership. Enabling
`download: true` / `delete: true` still means anyone who knows a key in
that prefix can presign it unless you add `guard` or [`db()`](/docs/db).

Put `object` on **upload**. See [Routes](/docs/server/routes).

```ts title="lib/s3.ts"
export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    uploads: route({
      download: true,
      delete: true,
    }),
  },
});
```

Per-user (or per-tenant) folders:

```ts title="lib/s3.ts"
import { dimahS3, errors, route } from "@dimah-s3/server";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    uploads: route({
      upload: {
        object: async ({ request }) => {
          const session = await getSession(request); // your auth
          if (!session) throw errors.unauthorized();
          return { folder: `users/${session.userId}` };
          // key: uploads/users/{userId}/{uuid}/{name}
        },
      },
      download: true,
      delete: true,
    }),
  },
});
```

## Bucket and ACL

The client cannot pick a bucket or ACL. Each route uses the instance
`bucket` unless the route sets its own. Uploads are `private` unless the
route sets `upload.acl` (or `object` returns one):

```ts
uploads: route({
  upload: { acl: "public-read" },
});
```

## Trust HeadObject, not the presign body

Simple uploads call `confirm` after the bytes land. Multipart calls
`multipart.complete` instead — there is no second `confirm`. Persist records
in `upload.onConfirmed` (simple confirm and multipart complete). Both see
size and type from `HeadObject`.

Set `fileTypes` and `maxFileSize` on `upload`. The server
checks them at presign and again after HeadObject. Oversize after landing
rejects confirm and best-effort `DeleteObject`. Multipart also checks
`maxFileSize` when signing each part (listed uploaded bytes + this
`partSize`) and **before** `CompleteMultipartUpload` — oversize aborts
the in-progress upload instead of assembling it.

```ts
import { dimahS3, errors, route } from "@dimah-s3/server";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    uploads: route({
      upload: {
        fileTypes: ["image/*", "application/pdf"],
        maxFileSize: 10 * 1024 * 1024,
        onConfirmed: async ({ key, contentLength }) => {
          // persist { key, size: contentLength }
        },
      },
    }),
  },
});
```

`fileTypes` matches the **S3 `Content-Type` header** and the filename
(extension tokens like `.pdf`). It does not sniff bytes. A client can
declare `image/png` and upload other content under that header. If you
need the real type, `GetObject` after confirm in your app (or a worker),
check magic bytes, and `DeleteObject` on mismatch. Throw from
`onConfirmed` only after you have cleaned up — a throw there does not
delete the object.

Until `onConfirmed` runs, do not treat the object as trusted. Without
[`db()`](/docs/db), `download` will presign any key that exists under
the route `keyPrefix`. `db()` download requires status `active`
(confirmed).

## Hook throws

| Where                         | Plain `Error`                            | `errors.*` / `DimahS3Error`     |
| ----------------------------- | ---------------------------------------- | ------------------------------- |
| `guard` / `*Guard` / `object` | **403**, message kept, no library `code` | the status and `code` you chose |
| `on*` hooks                   | **500**                                  | the status and `code` you chose |

Order: instance `guard` → lookup route → route `guard` → feature `guard`.

Full catalog: [Errors](/docs/server/errors).
