dimah-s3 signs URLs. It does not authenticate users, enforce quotas, or pick
object keys. Those stay in your `guard`, `prefix`, and `resolveKey` hooks.

<Callout type="warn">
  Never put S3 credentials in the browser. Keep the AWS SDK `S3Client` on the
  server and pass it into `dimahS3({client})`.
</Callout>

## Untrusted input

The client proposes `key` and may send `bucket`, `fileSize`, `contentType`,
`metadata`, `acl`, and `expiresIn`. Treat all of them as untrusted.

| Field                      | Default                                | How to scope it                                             |
| -------------------------- | -------------------------------------- | ----------------------------------------------------------- |
| `key`                      | used as-is after safety checks         | `prefix` or `resolveKey` on each feature, then `guard`      |
| `bucket`                   | ignored; `dimahS3({ bucket })` is used | `buckets` (allowlist) **or** `allowClientBucket` — not both |
| `acl`                      | always `private`                       | `upload.acl` (server-forced) or `upload.allowClientAcl`     |
| `fileSize` / `contentType` | declared by the client                 | Trust `onConfirmed` / `multipart.onComplete` (`HeadObject`) |
| `expiresIn`                | clamped to `maxExpiresIn` (7 days)     | Clients cannot exceed the SigV4 maximum                     |

## Keys

Rewrite `key` with `prefix` or `resolveKey` on each feature, then reject
unauthorized work in `guard`. Both run before feature guards.

- A key that already has the prefix is left as-is, so confirm and download of
  a stored key still work. That is not authorization — `guard` still has to
  reject the request.
- `resolveKey` must be **deterministic**. Confirm, complete, download, and
  delete run the same policy again. A new key each time misses the object.
  Store and send back the `key` and `bucket` from the response.
- Unsafe keys fail with `INVALID_KEY`: empty, backslash, NUL, `.` / `..`
  segments, or empty path segments.
- Give `download` and `delete` the same `prefix` (or an equivalent
  `resolveKey`) if they should only see keys under that prefix.

When omitted, multipart inherits `prefix`, `resolveKey`, `acl`,
`allowClientAcl`, and `requireFileSize` from upload.

```ts title="lib/s3.ts"
export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  upload: { prefix: "uploads" },
  download: { prefix: "uploads" },
  delete: { prefix: "uploads" },
});
```

## Bucket flags

- Omit both: client `bucket` is ignored.
- `buckets: ["app", "cdn"]`: client may send a bucket on that list; anything
  else is `INVALID_BUCKET`.
- `allowClientBucket: true`: any client bucket is accepted.

Setting both throws when `dimahS3()` runs.

## ACL

Uploads are `private` unless you opt in:

```ts
upload: {
  prefix: "uploads",
  // Force every object:
  acl: "public-read",
  // Or let the client choose private | public-read:
  allowClientAcl: true,
}
```

## Trust HeadObject, not the presign body

Simple uploads call `confirm` after the bytes land. Multipart calls
`multipart.complete` instead — there is no second `confirm`. Persist records
in `upload.onConfirmed` **and** `multipart.onComplete`. Both see size and
type from `HeadObject`.

Quota and max size belong in your hooks, not in library config:

```ts
import { dimahS3, errors } from "@dimah-s3/server";

const MAX = 10 * 1024 * 1024;

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  upload: {
    prefix: "uploads",
    requireFileSize: true,
    guard: async ({ fileSize }) => {
      if (fileSize && fileSize > MAX) {
        throw errors.payloadTooLarge("File too large");
      }
    },
    onConfirmed: async ({ key, contentLength }) => {
      if (contentLength > MAX) {
        throw errors.payloadTooLarge("File too large");
      }
      // persist { key, size: contentLength }
    },
  },
});
```

`requireFileSize` rejects presign when the client omits `fileSize` (POST and
PUT). It does not verify the bytes — that is `onConfirmed`. Unsigned POST
uploads without `fileSize` are still capped at 5 GB (the S3 POST object
limit).

## Hook throws

| Where              | Plain `Error`                            | `errors.*` / `DimahS3Error`     |
| ------------------ | ---------------------------------------- | ------------------------------- |
| `guard` / `*Guard` | **403**, message kept, no library `code` | the status and `code` you chose |
| `on*` hooks        | **500**                                  | the status and `code` you chose |

Full catalog: [Errors](/docs/server/errors).
