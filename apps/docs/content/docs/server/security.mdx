dimah-s3 is presign-first: S3 credentials stay on the server, and the browser
reaches storage only through short-lived signed URLs. This page covers what
the server enforces for you, and what your guards must add.

<Callout type="warn">
  Never expose S3 credentials in the browser or a client bundle. Create the
  `S3Client` on the server only.
</Callout>

`NEXT_PUBLIC_` keys in a browser bundle are a leak, not a shortcut:

```ts
export const awsS3 = new S3Client({
  credentials: {
    accessKeyId: process.env.NEXT_PUBLIC_S3_ACCESS_KEY_ID!, // [!code --]
    secretAccessKey: process.env.NEXT_PUBLIC_S3_SECRET_ACCESS_KEY!, // [!code --]
  },
});
```

## Security model

1. **The server owns keys.** The client asks to upload to a named `route`. The
   server picks the key: `avatar/{uuid}/{name}`, or what `upload.object`
   returns.
2. **Uploads carry signed tickets.** Presign returns an HMAC-signed
   [ticket](/docs/server/upload-tickets) naming the route, key, and declared
   file. Confirm and later multipart calls send only the ticket, so a client
   cannot point them at another key. A ticket can be bound to a user.
3. **Routes are isolated.** `keyPrefix` defaults to the route name. Upload
   generates keys under it; download and delete reject keys outside it with
   `KEY_INVALID`. This check always runs.
4. **Confirm trusts S3, not the browser.** The declared size and type are
   untrusted. Confirm reads the stored object with HeadObject and checks it
   against the ticket and the route limits before `onConfirmed` runs.
5. **Guards decide who may act.** The instance `guard`, route `guard`, and
   feature guards (`upload.guard`, `download.guard`, `delete.guard`) are where
   you authorize each caller.

## Route namespace vs ownership

`keyPrefix` and a guard answer different questions:

| Check                        | Runs                          | Answers                                 | Typical failure       |
| ---------------------------- | ----------------------------- | --------------------------------------- | --------------------- |
| `keyPrefix`                  | Always, in `@dimah-s3/server` | Is this key inside this route's folder? | `KEY_INVALID`         |
| Guards or [`db()`](/docs/db) | Only if you add them          | May this caller touch this object?      | `401` / `403` / `404` |

With these two routes:

```ts
avatar: route({ upload: { fileTypes: ["image/*"] }, delete: true }),
document: route({ upload: { fileTypes: ["application/pdf"] }, delete: true }),
```

- An upload on `avatar` creates `avatar/{uuid}/photo.jpg`. The client sends no
  key.
- `DELETE ?route=avatar&key=avatar/{uuid}/photo.jpg` is in the namespace.
- `DELETE ?route=avatar&key=document/{uuid}/cv.pdf` returns `KEY_INVALID`.

[`db()`](/docs/db) does not replace the prefix check. Its guards look up the
object by bucket and key and compare its scope; a key from another route is
rejected before they run.

<Callout type="warn" title="An enabled operation is not an ownership check">
  `delete: true` or `download: true` with no ownership guard lets anyone who can
  call the endpoint, and knows a key in that namespace, delete or download the
  object. A UUID in the key makes it hard to guess; it is not an access check. A
  guard that only checks for a session lets any signed-in user target any key
  they know.
</Callout>

## Scope objects to a user

Resolve the user once in the instance guard, and pass it on as
[`locals`](/docs/server/hooks/global-guard#locals) to shape keys and bind
tickets:

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";
import { awsS3 } from "./aws-s3";

declare module "@dimah-s3/server" {
  interface DimahS3Locals {
    userId?: string;
  }
}

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  guard: async ({ request }) => {
    const session = await getSession(request);
    if (!session) throw s3Error("UNAUTHORIZED");
    return { locals: { userId: session.userId } }; // [!code ++]
  },
  ticketSubject: ({ locals }) => locals.userId, // [!code ++]
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
        object: ({ locals }) => ({
          keyFolder: `users/${locals.userId}`, // avatar/users/{userId}/{uuid}/{name}
        }),
        onConfirmed: async ({ key, object, locals }) => {
          // object.size comes from HeadObject, not from the browser.
          await db.user.update({
            where: { id: locals.userId },
            data: { avatarKey: key, avatarSize: object.size },
          });
        },
      },
      download: true,
      delete: true,
    }),
  },
});
```

- `ticketSubject` binds each ticket to the user who started the upload. A
  leaked ticket cannot confirm or continue that upload for anyone else.
- `onConfirmed` runs at least once per upload, so keep it safe to replay, as
  this update is.
- `keyFolder` only shapes the key. It does not stop one signed-in user from
  targeting another user's key. Add the ownership guards below.

## Enforce ownership

Check ownership in `download.guard` and `delete.guard`, or attach
[`@dimah-s3/db`](/docs/db), which scopes every object for you:

```ts
avatar: route({
  delete: true, // [!code --]
  delete: { // [!code ++]
    guard: async ({ key, locals }) => { // [!code ++]
      if (!(await ownsAvatar(locals.userId, key))) throw s3Error("FORBIDDEN"); // [!code ++]
    }, // [!code ++]
  }, // [!code ++]
}),
```

## Verify file content

The declared type is untrusted. Set `verifyContent: true` on the route's
`upload` to check the object's first bytes against it after confirm. A
mismatch deletes the object and returns `FILE_CONTENT_MISMATCH`. See
[Routes](/docs/server/routes#content-verification).

For a stricter rule, inspect the object yourself in `confirmGuard`: a
rejection there deletes the object too. `sniffContentType` from
`@dimah-s3/core` returns the detected type of a byte prefix.

## Object ACL

Uploads are `private` by default. Set `acl` on the route, or return it from
`upload.object` per object:

```ts
avatar: route({
  upload: {
    acl: "public-read", // [!code ++]
    fileTypes: ["image/*"],
  },
}),
```

## Request hardening

- **JSON only.** Every body endpoint, plugin endpoints included, accepts
  `application/json` only. A cross-site HTML form cannot send it, so a form
  post returns `415 UNSUPPORTED_MEDIA_TYPE`.
- **Body cap.** `maxRequestBodySize` (1 MiB by default) is counted on the
  stream before parsing.
- **Signed headers.** A presigned PUT signs every header the server returns in
  `headers`: type, disposition, metadata, ACL, tags, storage class, and
  checksum. A custom client must send exactly those headers.
- **Inline allow-list.** Downloads open in the browser only for raster images,
  PDF, audio, video, and plain text, unless you set `download.inlineTypes`.
  HTML, SVG, and other types that run as a page download as attachments.
- **Hardened proxy.** [`GET /file`](/docs/server/file-proxy) sends a sandbox
  CSP, `nosniff`, and `Cross-Origin-Resource-Policy` on every response.

## Hook errors

| Thrown                                   | Result                                            |
| ---------------------------------------- | ------------------------------------------------- |
| `s3Error(code)` or another `APIError`    | Its own status and `code`                         |
| A plain `Error`, anywhere                | `500 INTERNAL_ERROR`, logged, passed to `onError` |
| Any throw from your `upload.onConfirmed` | `500 INTERNAL_ERROR`; the object is kept          |

A guard that returns anything other than nothing or `{ locals }`, such as
`true` or `false`, is a config error: it is logged and returns `500`. It never
allows the call. See [Errors](/docs/server/errors).
