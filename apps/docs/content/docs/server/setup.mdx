Set up the server once per app: install the package, set a ticket secret,
create one `dimahS3()` instance, and mount its handler under `/api/s3`.

## Installation

```npm
npm i @dimah-s3/server@beta @aws-sdk/client-s3
```

The server runs on Node.js 22 or newer, and on any runtime with the Fetch API
and Web Crypto.

## Set the ticket secret

Presign returns an [upload ticket](/docs/server/upload-tickets) signed with a
secret. Set `DIMAH_S3_SECRET` to a random value of at least 32 characters, the
same on every instance:

```bash title=".env"
# openssl rand -base64 32
DIMAH_S3_SECRET="…"
```

The secret is read on the first upload, not at startup. Without one, uploads
return `500 INTERNAL_ERROR`. When `NODE_ENV` is `development` or `test`, a
random secret is used instead and a warning is logged.

## Configure S3 and routes

Pass your `S3Client` and define named [routes](/docs/server/routes). Every
operation (`upload`, `download`, `delete`, `upload.multipart`) is off until
you turn it on.

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  region: process.env.S3_REGION,
  endpoint: process.env.S3_ENDPOINT,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
  },
  requestChecksumCalculation: "WHEN_REQUIRED", // [!code ++]
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024, // 2 MB
      },
      download: true,
      delete: true,
    }),
  },
});
```

<Callout type="warn" title="requestChecksumCalculation">
  Recent AWS SDK versions default to `"WHEN_SUPPORTED"`, which adds checksum
  parameters that a presigned browser upload cannot match. The server checks
  each client before its first presign. Any value other than `"WHEN_REQUIRED"`
  is logged as a config error, and the request returns `500 INTERNAL_ERROR`.
</Callout>

<Callout title="Files over 5 GiB">
  A single presigned PUT or POST cannot exceed 5 GiB, so larger files return
  `FILE_TOO_LARGE`. Turn on [`upload.multipart`](/docs/server/hooks/multipart)
  for them. The route's `maxFileSize` still applies.
</Callout>

## Mount the handler

Mount the handler at the `basePath` the client uses, `/api/s3` by default.

<Tabs items={["Next.js", "Express", "Hono", "SvelteKit", "Fastify", "Elysia", "Node", "Web"]}>

<Tab value="Next.js">

```ts title="app/api/s3/[...s3]/route.ts"
import { toNextJsHandler } from "@dimah-s3/server/next";
import { s3 } from "@/lib/s3";

export const { GET, POST, PUT, PATCH, DELETE } = toNextJsHandler(s3);
```

<Callout title="Cache Components">
  Next.js 16.4 enables Cache Components on new apps. Leave this handler
  uncached: it reads the request, so presign, download, and delete must run on
  each request. A `use cache` wrapper would reuse one presign across requests.
</Callout>

</Tab>

<Tab value="Express">

```ts title="server.ts"
import express from "express";
import { toExpressHandler } from "@dimah-s3/server/express";
import { s3 } from "./s3";

const app = express();
// The adapter reads the raw stream, so mount it before JSON middleware.
app.use("/api/s3", toExpressHandler(s3));
app.use(express.json());
```

A mount (`app.use`) and a route (`app.all("/api/s3/*", …)`, or
`"/api/s3/*splat"` on Express 5) both work. The adapter reads
`req.originalUrl`, which keeps the mount path.

</Tab>

<Tab value="Hono">

```ts title="src/index.ts"
import { Hono } from "hono";
import { toHonoHandler } from "@dimah-s3/server/hono";
import { s3 } from "./s3";

const app = new Hono();
app.on(
  ["GET", "POST", "PUT", "PATCH", "DELETE"],
  "/api/s3/*",
  toHonoHandler(s3),
);
```

</Tab>

<Tab value="SvelteKit">

```ts title="src/routes/api/s3/[...path]/+server.ts"
import { toSvelteKitHandler } from "@dimah-s3/server/svelte-kit";
import { s3 } from "$lib/s3";

const handler = toSvelteKitHandler(s3);
export const GET = handler;
export const POST = handler;
export const PUT = handler;
export const PATCH = handler;
export const DELETE = handler;
```

</Tab>

<Tab value="Fastify">

```ts title="server.ts"
import Fastify from "fastify";
import { toFastifyHandler } from "@dimah-s3/server/fastify";
import { s3 } from "./s3";

const app = Fastify();

app.register(async (scope) => {
  // Leave the body unread: the adapter streams it from the raw request.
  scope.removeAllContentTypeParsers();
  scope.addContentTypeParser("*", (_request, _payload, done) => done(null));
  scope.all("/api/s3/*", toFastifyHandler(s3));
});
```

Fastify parses JSON bodies before the handler runs. Turn parsing off for the
dimah-s3 routes, as above, so the adapter can read the body.

</Tab>

<Tab value="Elysia">

```ts title="src/index.ts"
import { Elysia } from "elysia";
import { toElysiaHandler } from "@dimah-s3/server/elysia";
import { s3 } from "./s3";

new Elysia().all("/api/s3/*", toElysiaHandler(s3)).listen(3000);
```

<Tab value="Node">

```ts title="server.ts"
import { createServer } from "node:http";
import { toNodeHandler } from "@dimah-s3/server/node";
import { s3 } from "./s3";

const handler = toNodeHandler(s3);

createServer((req, res) => {

  res.end("Not found");

```

### Node, Express, and Fastify

These adapters stream the request body from `req`, so the body cap is counted
as bytes arrive. They stream response bodies, such as a
[`/file`](/docs/server/file-proxy) download, to `res`. When the client
disconnects, the request signal aborts, and so does the S3 call behind it.

Behind a proxy that sets `X-Forwarded-Proto` and `X-Forwarded-Host`, pass
`trustProxy` so the request URL uses them. Turn it on only behind such a
proxy, since clients can send those headers too.

```ts
toNodeHandler(s3, { trustProxy: true });
toExpressHandler(s3, { trustProxy: true });
toFastifyHandler(s3, { trustProxy: true });
```

### Custom base path or API origin

Set `basePath` to serve the API somewhere else, or `baseURL` when it has its
own origin. With `baseURL`, proxy download URLs are absolute. Configure the
client to match:

```ts title="lib/s3.ts"
export const s3 = dimahS3({
  basePath: "/api/storage", // [!code ++]
  // ...
});
```

```ts title="lib/s3-client.ts"
export const s3Client = createS3Client({
  baseURL: "https://api.example.com/api/storage", // [!code ++]
});
```

## Server-side API (`s3.api`)

`s3.api` has the browser client's methods and payloads, and runs them in
process with the same guards and hooks. Pass the caller's headers so guards
can read cookies and auth headers:

```ts title="app/actions.ts"
"use server";

import { headers } from "next/headers";
import { s3 } from "@/lib/s3";

export async function getAvatarDownloadUrl(key: string) {
  return s3.api.download(
    { route: "avatar", key },
    { headers: await headers() }, // [!code ++]
  );
}
```

In a Node or Express handler, convert `req.headers` with `fromNodeHeaders`
from `@dimah-s3/server/node` (also exported by `@dimah-s3/server/express`):

```ts title="server.ts"
import { fromNodeHeaders } from "@dimah-s3/server/node";

app.get("/avatar-url", async (req, res) => {
  const { url } = await s3.api.download(
    { route: "avatar", key: String(req.query.key) },
    { headers: fromNodeHeaders(req.headers) }, // [!code ++]
  );
  res.json({ url });
});
```

For jobs with no request, seed trusted [`locals`](/docs/server/hooks/global-guard#locals)
instead. HTTP requests can never set them.

```ts title="jobs/cleanup.ts"
await s3.api.deleteMany(
  { route: "files", keys },
  { locals: { userId: job.ownerId } }, // [!code ++]
);
```

Plugin endpoints, such as the `db()` list, are HTTP only. Plugins expose their
server-side API on the instance instead (`s3.db`).

## Server-side uploads (`s3.put`)

`s3.put` uploads from your server through the route's upload policy:

```ts
const object = await s3.put(
  {
    route: "avatar",
    name: "profile.png",
    type: "image/png",
    body: imageBuffer,
  },
  { headers: await headers() },
);
// object: { key, bucket, name, size, type, eTag, metadata, acl, … }
```

- It runs `upload.object`, `upload.guard`, `upload.onStart` with
  `kind: "server"`, the PutObject, and `upload.onConfirmed`.
  `upload.confirmGuard` does not run.
- The object gets a `Content-Disposition` with the file name.
- `metadata` is written to S3 on top of `upload.object().metadata`.
  `clientMetadata` reaches the hooks and is never written.

## Logging

The server logs config errors, unexpected failures, and warnings with
`console.error` and `console.warn`, prefixed with `[dimah-s3]`. Rejections you
throw with `s3Error` are not logged. Pass `logger` to send logs elsewhere, or
`false` to silence them:

```ts
export const s3 = dimahS3({
  logger: {
    warn: (message, ...args) => log.warn({ args }, message), // [!code ++]
    error: (message, ...args) => log.error({ args }, message), // [!code ++]
  },
  // ...
});
```

Every logger method is optional (`debug`, `info`, `warn`, `error`). To send
failures to an error tracker, use [`onError`](/docs/server/errors#reporting-errors).

## API Reference

### dimahS3()

`dimahS3(config)` checks the config and throws at startup on a mistake. The
ticket secret is the exception: `DIMAH_S3_SECRET` is read on the first upload.

| Prop                 | Type                                        | Default     | Description                                                                                                                                                    |
| -------------------- | ------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `routes`             | `Record<string, DimahS3RouteConfig>`        | required    | Named file [routes](/docs/server/routes#api-reference). At least one                                                                                           |
| `client`             | `S3Client`                                  | —           | Default AWS SDK v3 client. Required unless every route sets one. Must set `requestChecksumCalculation: "WHEN_REQUIRED"`                                        |
| `bucket`             | `string`                                    | —           | Default bucket. Required unless every route sets one                                                                                                           |
| `basePath`           | `string`                                    | `"/api/s3"` | API path prefix. Must match `createS3Client({ basePath })`                                                                                                     |
| `baseURL`            | `string`                                    | —           | Absolute `http(s)` API URL with no query or hash. Its path must equal `basePath` when both are set. Proxy download URLs use it                                 |
| `secret`             | `string \| readonly string[]`               | —           | Ticket secret, at least 32 characters. Defaults to the `DIMAH_S3_SECRET` environment variable. An array rotates secrets: the first signs, every one verifies   |
| `ticketSubject`      | `TicketSubject`                             | —           | Binds [upload tickets](/docs/server/upload-tickets#binding-a-ticket-to-a-user) to a subject, such as a user id. Defaults to the first plugin that provides one |
| `guard`              | `Guard<GuardContext>`                       | —           | Runs before every operation, before route lookup. See [Guards](/docs/server/hooks/global-guard)                                                                |
| `maxExpiresIn`       | `number`                                    | `604800`    | Largest presign TTL in seconds for any route. 7 days is also the maximum                                                                                       |
| `maxRequestBodySize` | `number`                                    | `1048576`   | Largest JSON request body in bytes, counted on the stream                                                                                                      |
| `logger`             | `DimahS3Logger \| false`                    | —           | Receives config errors, unexpected failures, and warnings. Defaults to `console`. `false` silences it                                                          |
| `onError`            | `(error, context) => void \| Promise<void>` | —           | Receives every unexpected failure with `{ request, operation? }`. See [Reporting errors](/docs/server/errors#reporting-errors)                                 |
| `plugins`            | `readonly DimahS3Plugin[]`                  | —           | Server [plugins](/docs/server/plugins), such as `db()`                                                                                                         |

### Instance

| Property       | Type                                                    | Description                                                               |
| -------------- | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| `handler`      | `(request: Request) => Promise<Response>`               | The HTTP handler every adapter wraps                                      |
| `api`          | `DimahS3Api`                                            | The browser client's methods, run in process                              |
| `put`          | `(input, options?) => Promise<ConfirmedObjectResponse>` | Uploads from the server through a route's policy                          |
| `context`      | `PluginContextMap`                                      | Plugin contexts by plugin id. Each one is on the instance too, as `s3.db` |
| `getPlugin`    | `(id) => DimahS3Plugin \| undefined`                    | Returns a registered plugin                                               |
| `$ERROR_CODES` | `typeof S3_ERROR_CODES`                                 | The [error catalog](/docs/server/errors)                                  |
| `$Infer`       | type only                                               | `typeof s3.$Infer.routes` is the union of your route names                |

`InferS3Routes<typeof s3>` from `@dimah-s3/core` reads `$Infer.routes` to
[type route names](/docs/react/setup#typescript-route-inference) on the client.

### Call options

The last argument of every `s3.api` method and of `s3.put`
(`S3ServerCallOptions`).

| Prop      | Type                     | Default | Description                                                                                                                                    |
| --------- | ------------------------ | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `headers` | `HeadersInit`            | —       | Headers of the synthetic `GET` request to `baseURL`, or to `http://localhost` plus `basePath`. It has no query or body. Ignored with `request` |
| `signal`  | `AbortSignal`            | —       | Aborts the call and its S3 requests. Ignored with `request`, whose own signal is used                                                          |
| `request` | `Request`                | —       | The request hooks see. Pass the incoming one when you have it                                                                                  |
| `locals`  | `Partial<DimahS3Locals>` | —       | Trusted values that seed `locals` before any guard runs. Never read from HTTP                                                                  |

### s3.put input

| Prop             | Type                                                                        | Default  | Description                                                               |
| ---------------- | --------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------- |
| `route`          | `string`                                                                    | required | Route name                                                                |
| `name`           | `string`                                                                    | required | File name                                                                 |
| `body`           | `Blob \| ReadableStream<Uint8Array> \| Uint8Array \| ArrayBuffer \| string` | required | File content                                                              |
| `type`           | `string`                                                                    | —        | MIME type                                                                 |
| `size`           | `number`                                                                    | —        | Byte size. Required for a `ReadableStream`, and must match any other body |
| `metadata`       | `Record<string, string>`                                                    | —        | S3 user metadata written on the object                                    |
| `clientMetadata` | `Record<string, string>`                                                    | —        | Visible to hooks. Never written to S3                                     |

### Adapter options

`toNodeHandler`, `toExpressHandler`, and `toFastifyHandler` take
`NodeHandlerOptions` as a second argument.

| Prop         | Type      | Default | Description                                                            |
| ------------ | --------- | ------- | ---------------------------------------------------------------------- |
| `trustProxy` | `boolean` | `false` | Builds the request URL from `X-Forwarded-Proto` and `X-Forwarded-Host` |

## Frequently asked questions

<Accordions>

<Accordion title="How large can a request body be?">

`maxRequestBodySize` caps every request body, 1 MiB by default. It is counted
on the stream before parsing, so a chunked body cannot get around it. Going
over returns `413 REQUEST_TOO_LARGE`. Body endpoints accept `application/json`
only and return `415 UNSUPPORTED_MEDIA_TYPE` for anything else.

</Accordion>

<Accordion title="How do I reject a call, and what status does it return?">

Throw `s3Error("FORBIDDEN")`, or another catalog code, from a guard or hook.
A plain `Error` thrown anywhere is logged, passed to `onError`, and returns
`500 INTERNAL_ERROR`. See [Errors](/docs/server/errors).

</Accordion>

</Accordions>
