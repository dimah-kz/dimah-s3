## Install

```npm
npm i @dimah-s3/server @aws-sdk/client-s3
```

### Config [step]

Pass an AWS SDK `S3Client` as `client` (export it as `awsS3` so jobs and a
custom backend can reuse it) and a `bucket`. That `bucket` is the default:
used when the request omits one, and whenever a client-sent bucket is
ignored. Enable a feature with `true` or an options object (omit `enabled` —
the object itself means on). Multipart turns on with upload unless you set
`multipart: false`. Disabled features return `404` with code
`FEATURE_DISABLED`.

Provider-specific wiring (POST vs PUT, ACL, path-style):
[Providers](/docs/providers).

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3 } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  region: process.env.S3_REGION,
  endpoint: process.env.S3_ENDPOINT,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
  },
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  upload: { prefix: "uploads" },
});
```

R2 and similar providers need `upload: { method: "PUT", prefix: "uploads" }` —
see [Cloudflare R2](/docs/providers/cloudflare-r2).

| Option                                         | Default   | Role                                              |
| ---------------------------------------------- | --------- | ------------------------------------------------- |
| `client`                                       | required  | AWS SDK `S3Client` (`awsS3`)                      |
| `bucket`                                       | required  | Default bucket                                    |
| `allowClientBucket` / `buckets`                | off       | Honor a client-sent `bucket`                      |
| `basePath`                                     | `/api/s3` | Must match `createS3Client({ basePath })`         |
| `resolveObjectAcl`                             | `false`   | Extra `GetObjectAcl` on confirm / complete        |
| `guard`                                        | —         | [Global Guard](/docs/server/hooks/global-guard)   |
| `upload` / `download` / `delete` / `multipart` | off       | Feature flag + [hooks](/docs/server/hooks/upload) |
| `plugins`                                      | —         | e.g. [`db()`](/docs/db)                           |

`prefix` and `resolveKey` on each feature rewrite the object key before
presign. Hooks may send `bucket`; without `allowClientBucket` or `buckets`
the server keeps using config `bucket`.

A plain `Error` in `guard` / `*Guard` becomes **403**. The same throw in
`onPresigned` / `onConfirmed` / `onDeleted` / other `on*` hooks becomes
**500**. Throw `DimahS3Error` when you need a specific status and `code`.

### Route handler [step]

Mount at `/api/s3` by default. Adapters are subpath exports — no framework
peer dependencies. Any Fetch runtime can call `s3.handler(request)` instead.

<Tabs items={["Next.js", "Express", "Hono", "SvelteKit", "Fastify", "Elysia", "Node", "Web"]}>

<Tab value="Next.js">

```ts title="app/api/s3/[...s3]/route.ts"
import { toNextJsHandler } from "@dimah-s3/server/next";
import { s3 } from "@/lib/s3";

export const { GET, POST, PUT, PATCH, DELETE } = toNextJsHandler(s3);
```

</Tab>

<Tab value="Express">

Mount **before** `express.json()` so the body is not consumed early.

```ts title="server.ts"
import express from "express";
import { toExpressHandler } from "@dimah-s3/server/express";
import { s3 } from "./s3";

const app = express();
app.all("/api/s3/*", toExpressHandler(s3)); // Express 5: "/api/s3/*splat"
app.use(express.json());
```

</Tab>

<Tab value="Hono">

```ts title="src/index.ts"
import { Hono } from "hono";

import { s3 } from "./s3";

const app = new Hono();
app.on(
  ["GET", "POST", "PUT", "PATCH", "DELETE"],
  "/api/s3/*",
```

<Tab value="Node">

```ts title="server.ts"
import { createServer } from "node:http";
import { toNodeHandler } from "@dimah-s3/server/node";
import { s3 } from "./s3";

const handler = toNodeHandler(s3);

createServer((req, res) => {
  if (req.url?.startsWith("/api/s3")) return handler(req, res);
  res.statusCode = 404;
  res.end("Not found");
}).listen(3000);
```

<Tab value="Web">

```ts
export default {
  fetch(request: Request) {
    const url = new URL(request.url);
    if (url.pathname.startsWith("/api/s3")) {
      return s3.handler(request);
    }
    return new Response("Not found", { status: 404 });
  },
};
```

Custom base path: set `basePath` on `dimahS3()` and the same value on
`createS3Client({ basePath })`. Cross-origin apps can pass `baseURL` instead
(absolute origin + path).

### Server `api` [step]

Same protocol as the browser client, without HTTP. Pass `headers` so
`guard` still sees the request.

```ts title="app/actions.ts"
"use server";

import { headers } from "next/headers";
import { s3 } from "@/lib/s3";

export async function getDownloadUrl(key: string) {
  return s3.api.download({
    query: { key },
    headers: await headers(),
  });
}
```

On Node / Express, convert headers with `fromNodeHeaders` from
`@dimah-s3/server/node` (re-exported from `@dimah-s3/server/express`).

`s3.api` is the better-call endpoint map (`upload`, `confirm`, `download`,
`delete`, `multipartInit`, … plus plugin endpoints). Nested aliases exist for
multipart: `s3.api.multipart.init` is the same as `s3.api.multipartInit`. The
browser client (`createS3Client`) still exposes nested `S3Api`
(`s3Client.download(key)`, `s3Client.multipart.init`). Failures throw
`DimahS3Error` (a better-call `APIError`) with named `.status` (`"FORBIDDEN"`),
numeric `.statusCode`, and `.code`. Catch with `isAPIError` / `isDimahS3Error`
/ `isS3ErrorCode`. The instance also exposes `$ERROR_CODES` and `$Infer`.
