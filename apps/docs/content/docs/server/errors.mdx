Failed requests return JSON `{ message, code?, params? }` and an HTTP status.
Throw with the `errors` helper so the `code` stays in the catalog.

```ts
import { errors, isDimahS3Error, isS3ErrorCode } from "@dimah-s3/server";

throw errors.forbidden();
throw errors.objectNotFound();
throw errors.payloadTooLarge();
throw errors.featureDisabled("download");
throw errors.unknownRoute("avatars");
throw errors.fileTypeNotAllowed("application/zip");

if (isS3ErrorCode(err, "OBJECT_NOT_FOUND")) {
  // ...
}
```

`DimahS3Error` extends better-call `APIError`. Detect it with `isAPIError`,
`isDimahS3Error`, or `isS3ErrorCode`. The catalog is `S3_ERROR_CODES` in
`@dimah-s3/core` — re-exported from `@dimah-s3/server`, and also on
`s3.$ERROR_CODES`. On the client, `useFormatDimahError` maps each `code` to a
localized string.

## Catalog

| `code`                         | HTTP | When                                                                |
| ------------------------------ | ---- | ------------------------------------------------------------------- |
| `NOT_FOUND`                    | 404  | Unknown HTTP path (empty better-call 404 rewritten to JSON)         |
| `UNKNOWN_ROUTE`                | 404  | `route` is not in `dimahS3({ routes })` (`params.route`)            |
| `FEATURE_DISABLED`             | 404  | That operation is off on the named route (`params.feature`)         |
| `OBJECT_NOT_FOUND`             | 404  | Missing object or multipart upload                                  |
| `UNAUTHORIZED`                 | 401  | Helper for your auth hooks                                          |
| `FORBIDDEN`                    | 403  | Guard rejection (`errors.forbidden()` / a plain `Error` in a guard) |
| `CONFLICT`                     | 409  | Helper for your hooks                                               |
| `PAYLOAD_TOO_LARGE`            | 413  | Oversize vs `upload.maxFileSize`, or `errors.payloadTooLarge()`     |
| `FILE_TYPE_NOT_ALLOWED`        | 400  | Declared or HeadObject type not in `upload.fileTypes`               |
| `VALIDATION_ERROR`             | 400  | Zod / request shape                                                 |
| `INVALID_KEY`                  | 400  | Unsafe object key (empty, `\`, NUL, `.` / `..` / empty segments)    |
| `INVALID_BUCKET`               | 403  | Route has no bucket (internal misconfig)                            |
| `MULTIPART_PART_MISSING`       | 400  | Complete referenced a part S3 does not have (`params.partNumber`)   |
| `S3_NETWORK_ERROR`             | 502  | Unreachable S3 endpoint (`params.code`)                             |
| `INTERNAL_ERROR`               | 500  | Unexpected throw; failed `on*` hook                                 |

Disabled features stay registered and return `FEATURE_DISABLED`, not an empty 404.

A plain `Error` in a guard is **403**. The same throw in an `on*` hook is
**500**. See [Security](/docs/server/security#hook-throws).
