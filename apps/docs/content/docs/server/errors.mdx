Every failed request returns an HTTP status and a JSON body with a stable
`code`. Throw catalog errors with `s3Error` on the server, and narrow them by
`code` on the client.

```json
{
  "code": "FILE_TOO_LARGE",
  "message": "File is 5242880 bytes; the limit is 2097152 bytes",
  "params": { "size": 5242880, "maxFileSize": 2097152 }
}
```

`message` is English, filled from `params`. To show users your own text, map
`code` and `params`, as [`useFormatError`](/docs/react/helpers#errors) does.

Server code imports the helpers (`APIError`, `s3Error`, `isAPIError`,
`isS3ErrorCode`, `S3_ERROR_CODES`) from `@dimah-s3/server`. Browser code
imports them from `@dimah-s3/core`.

## Throwing errors

Throw `s3Error` with a catalog code to reject a call from a guard or hook.
Codes that have `params` require them:

```ts
import { s3Error } from "@dimah-s3/server";

throw new Error("Not allowed"); // [!code --]
throw s3Error("UNAUTHORIZED"); // [!code ++]
throw s3Error("FORBIDDEN");
throw s3Error("QUOTA_EXCEEDED", { limit: "bytes" });
throw s3Error("FILE_TOO_LARGE", { size: file.size, maxFileSize });
```

A plain `Error` thrown anywhere is logged, passed to `onError`, and returns
`500 INTERNAL_ERROR`. Its message never reaches the client.

For your own codes, define them once with `defineErrorCodes` and pass the
entry to `s3Error`. Its `params` are typed by the message's placeholders:

```ts
import { defineErrorCodes } from "@dimah-s3/core";
import { s3Error } from "@dimah-s3/server";

const BILLING_ERROR_CODES = defineErrorCodes({
  PLAN_REQUIRED: { status: 402, message: "Upgrade to {plan} to upload videos" },
});

throw s3Error(BILLING_ERROR_CODES.PLAN_REQUIRED, { plan: "Pro" });
```

A plugin sets them as `$ERROR_CODES`, and they join `s3.$ERROR_CODES`: see
[Plugins](/docs/server/plugins#error-codes). `APIError.from(status, body)`
still builds a one-off error with any `{ code, message, params? }`.

A throw from `upload.onConfirmed` or `upload.onRejected` has its own rules:
see [Failure rules](/docs/server/hooks/upload#failure-rules).

## Handling errors

`createS3Client` and the React hooks reject with an `APIError`. Narrow it with
`isS3ErrorCode`, which also types its `params`:

```ts title="Browser"
import { isAPIError, isS3ErrorCode } from "@dimah-s3/core";

try {
  await api.download({ route: "avatar", key });
} catch (error) {
  if (isS3ErrorCode(error, "OBJECT_NOT_FOUND")) {
    // Handle the missing object
  } else if (isAPIError(error)) {
    console.log(error.statusCode, error.code, error.message, error.params);
  }
}
```

The client turns every failure into an `APIError`:

| Failure                                                                           | Result                                                                          |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| JSON error body                                                                   | Keeps its `code`, `params`, and HTTP status                                     |
| Any other error response                                                          | `INTERNAL_ERROR` (status 500 or above) or `UNKNOWN_ERROR`, with the real status |
| `2xx` whose body is not a JSON object or array, such as an SPA `index.html`       | `UNKNOWN_ERROR`. Usually the client's `basePath` misses the handler             |
| S3 rejects a checksummed PUT or part (`BadDigest`, `XAmzContentChecksumMismatch`) | `CHECKSUM_MISMATCH`                                                             |
| No response at all                                                                | `NETWORK_ERROR`                                                                 |
| Aborted request                                                                   | The signal's abort reason, not an `APIError`                                    |

`deleteMany` reports per-key failures as wire bodies in `failed[].error`.
Rebuild one with `APIError.fromShape(error)`.

## Reporting errors

`onError` receives every failure that is not an `APIError`: plain errors,
config errors, and S3 network errors. They are logged too, and answered with
`500 INTERNAL_ERROR` or `502 S3_NETWORK_ERROR`.

```ts title="lib/s3.ts"
export const s3 = dimahS3({
  onError: async (error, { request, operation }) => {
    Sentry.captureException(error, { extra: { url: request.url, operation } }); // [!code ++]
  },
  // ...
});
```

- Rejections you throw with `s3Error` never reach it. Neither does a failure
  after the client disconnected.
- A throw from your `upload.onConfirmed` or `upload.onRejected`, even an
  `APIError`, reaches it wrapped in an `Error`, with the original as `cause`.
- It may be async. A throw from it is logged, never sent to the client.

## API Reference

| Export                                 | Description                                                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `s3Error(code, params?, options?)`     | Builds a catalog `APIError`. `options.status` overrides the status; `options.cause` stays on the server |
| `APIError.from(status, body)`          | Builds an `APIError` with any `{ code, message, params? }`                                              |
| `APIError.fromShape(shape, status?)`   | Rebuilds an `APIError` from a wire body. The status defaults to the catalog's, else `500`               |
| `isAPIError(error)`                    | True for an `APIError`, also one from another copy of the package                                       |
| `isS3ErrorCode(error, code)`           | True for an `APIError` with that `code`, and types its `params`                                         |
| `S3_ERROR_CODES`                       | The catalog: each code's `status`, `message` template, and `client` flag                                |
| `formatErrorMessage(template, params)` | Fills `{name}` placeholders in a template. `@dimah-s3/core` only                                        |

### APIError

| Property     | Type                                            | Description                        |
| ------------ | ----------------------------------------------- | ---------------------------------- |
| `code`       | `string`                                        | Stable machine-readable code       |
| `message`    | `string`                                        | English message                    |
| `params`     | `Record<string, string \| number> \| undefined` | Values the message was filled from |
| `statusCode` | `number`                                        | HTTP status                        |

<Accordion title="Where do I find the message template for a code?">

`S3_ERROR_CODES[code].message`. `formatErrorMessage` fills it:

```ts
import { formatErrorMessage, S3_ERROR_CODES } from "@dimah-s3/core";

formatErrorMessage(S3_ERROR_CODES.UPLOAD_FAILED.message, { status: 403 });
// "Upload failed with HTTP 403"
```
