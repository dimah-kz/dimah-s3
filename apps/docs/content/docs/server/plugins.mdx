Official plugins ship in their own packages — start with
[`db()`](/docs/db) for object tracking. This page is for plugins you write
with `definePlugin`.

A plugin can add lifecycle hooks, HTTP routes under paths it owns (for
example `/audit/recent`), and typed context on the `dimahS3()` instance
(`s3[id]`).

Keep the plugin **inline** (or `as const`) in `plugins` so `s3.audit` stays
narrowed. A widened `DimahS3Plugin[]` variable drops the id.

`definePlugin`, `createS3Endpoint`, and `chainHooks` export from
`@dimah-s3/server`. Hook context types and `applyPlugins` also live on
`@dimah-s3/server/plugins`.

```ts
import { definePlugin, dimahS3, route } from "@dimah-s3/server";

const audit = definePlugin({
  id: "audit",
  hooks: {
    upload: {
      onConfirmed: async ({ key }) => {
        console.log("uploaded", key);
      },
    },
  },
  context: {
    log: (message: string) => console.log("[audit]", message),
  },
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  plugins: [audit],
  routes: {
    uploads: route({ upload: true }),
  },
});

s3.audit.log("ready");
```

`method` / `object` / `acl` stay on the route **`upload`** feature —
plugins cannot override them. You still turn features on and set key
policy yourself. Hook context types import from
`@dimah-s3/server/plugins`.

Plugin hooks are the same slots as `FEATURE_HOOK_KEYS` (plus nested
`upload.multipart` via `MULTIPART_HOOK_KEYS`): feature `guard` / `on*`
functions only.

## Hook order

Guards (`guard` / `*Guard`) run **plugins first**, then your config — so
[`db()`](/docs/db) ownership runs before a quota check.

Lifecycle `on*` hooks run **your config first**, then plugins — so a throw
from `upload.onConfirmed` can `DeleteObject` before `db()` marks the row
active.

Stack several **user** hooks on one slot with `chainHooks`:

```ts
import { chainHooks, dimahS3, route } from "@dimah-s3/server";
import { db } from "@dimah-s3/db";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  plugins: [db({ client: dimahS3Db, resolveScope })],
  routes: {
    uploads: route({
      upload: {
        guard: chainHooks(quotaGuard, rateLimitGuard),
      },
    }),
  },
});
```

## Endpoints

```ts
import { definePlugin, createS3Endpoint } from "@dimah-s3/server";

definePlugin({
  id: "audit",
  endpoints: {
    recent: createS3Endpoint("/audit/recent", { method: "GET" }, async () => ({
      events: [],
    })),
  },
});

// GET /api/s3/audit/recent
```

- Path: the plugin owns the full path under `basePath` (`pluginPath` in `@dimah-s3/core`)
- Global `guard` runs first (HTTP and `s3.api`)
- Paths must start with `/` and must not collide with core routes or another plugin

Use `context` for server-side access; endpoints are the HTTP surface for
browsers. The same handlers are on `s3.api` (here `s3.api.recent()`).

## Client plugin

```ts
import { defineClientPlugin, pluginPath } from "@dimah-s3/core";

export function auditClient() {
  return defineClientPlugin({
    id: "audit",
    getActions: ($fetch) => ({
      recent: () => $fetch(pluginPath("audit", "recent"), { method: "GET" }),
    }),
  });
}
```

Register with `createS3Client({ plugins: [auditClient()] })` — see
[Client setup](/docs/react/setup). Official packages use a light entry
(e.g. `@dimah-s3/db/client`) so ORM deps stay server-only.

## `dependsOn` and `init`

```ts
import { definePlugin, isFeatureOn } from "@dimah-s3/server";

const quota = definePlugin({
  id: "quota",
  dependsOn: ["db"],
  init({ config }) {
    const hasUpload = Object.values(config.routes).some((r) =>
      isFeatureOn(r.upload),
    );
    if (!hasUpload) {
      throw new Error("quota plugin requires upload enabled on a route");
    }
  },
  hooks: { upload: { guard: quotaGuard } },
});
```

List dependencies before dependents in the `plugins` array. Merge order
follows that array — it is not topological.
