Official plugins ship in their own packages — start with
[`db()`](/docs/db) for object tracking. This page is for plugins you write
with `definePlugin`.

A plugin can add lifecycle hooks, HTTP routes under `plugins/{id}/…`, and
typed context on the `dimahS3()` instance (`s3[id]`). Pair server endpoints
with a client plugin when the browser needs them.

```ts
import { dimahS3, definePlugin, createEndpoint } from "@dimah-s3/server";
import { s3Client, defaultBucket } from "@/lib/s3-client";

const audit = definePlugin({
  id: "audit",
  hooks: {
    upload: {
      onConfirmed: async ({ key, bucket }) => {
        console.log("uploaded", bucket, key);
      },
    },
  },
  endpoints: {
    recent: createEndpoint("recent", { method: "GET" }, async () => ({
      events: [],
    })),
  },
  context: {
    log: (message: string) => console.log("[audit]", message),
  },
});

export const s3 = dimahS3({
  s3: s3Client,
  defaultBucket,
  upload: { enabled: true },
  plugins: [audit],
});

s3.audit.log("ready");
// GET /api/s3/plugins/audit/recent
```

## Contract

| Field        | Purpose                                                            |
| ------------ | ------------------------------------------------------------------ |
| `id`         | Unique string (reserved: `handler`, `api`, `context`, `getPlugin`) |
| `hooks?`     | Lifecycle hooks — merged **before** your config hooks              |
| `endpoints?` | Routes under `plugins/{id}/{path}` via `createEndpoint`            |
| `context?`   | Data exposed as `s3[id]` and `s3.context[id]`                      |
| `dependsOn?` | Plugin ids that must be registered first                           |
| `init?`      | Sync validation after the context map is built                     |

`enabled` / `method` stay on `DimahS3Config` — plugins cannot override them.
You still turn features on yourself.

## Hook order

1. Plugin hooks — **first**, in `plugins` array order
2. Your hooks on `dimahS3()` — **last**

With [`db()`](/docs/db) registered, its ownership guard runs before your
quota check.

Stack several **user** hooks on one slot with `chainHooks`:

```ts
import { dimahS3, chainHooks } from "@dimah-s3/server";
import { db } from "@dimah-s3/db";

export const s3 = dimahS3({
  s3: s3Client,
  defaultBucket,
  plugins: [db({ client: dimahS3Db, resolveScope })],
  upload: {
    enabled: true,
    presignGuard: chainHooks(quotaGuard, rateLimitGuard),
  },
});
```

## Endpoints

```ts
endpoints: {
  ping: createEndpoint("ping", { method: "GET" }, async ({ request }) => {
    return { ok: true };
  }),
},
```

- Path: `plugins/{pluginId}/{path}` (`pluginEndpointPath` in `@dimah-s3/core`)
- Global `guard` runs first
- Paths must not collide with core routes or another plugin

Use `context` for server-side access; endpoints are the HTTP surface for
browsers.

## Client plugin

```ts
import { defineClientPlugin, pluginEndpointPath } from "@dimah-s3/core";

export function auditClient() {
  return defineClientPlugin({
    id: "audit",
    createMethods: (fetcher) => ({
      recent: () => fetcher.get(pluginEndpointPath("audit", "recent")),
    }),
  });
}
```

Register with `createS3Client({ plugins: [auditClient()] })` — see
[Client setup](/docs/react/setup). Official packages use a light entry
(e.g. `@dimah-s3/db/client`) so ORM deps stay server-only.

## `dependsOn` and `init`

```ts
const quota = definePlugin({
  id: "quota",
  dependsOn: ["db"],
  init({ config }) {
    if (!config.upload?.enabled) {
      throw new Error("quota plugin requires upload enabled");
    }
  },
  hooks: { upload: { presignGuard: quotaGuard } },
});
```

List dependencies before dependents in the `plugins` array. Merge order
follows that array — it is not topological.
