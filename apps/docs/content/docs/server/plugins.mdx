A plugin packages hooks, HTTP endpoints under your `basePath`, a typed
context on the instance (`s3[id]`), and its own error codes. A matching
client plugin calls those endpoints with types read from the server.
[`db()`](/docs/db) is built this way, and
[`examples/plugin-audit`](https://github.com/dimah-kz/dimah-s3/tree/main/examples/plugin-audit)
is a complete plugin to copy.

```ts title="audit/index.ts"
import { pluginPath, s3Error } from "@dimah-s3/core";
import {
  createS3Endpoint,
  definePlugin,
  type PluginInitEnv,
} from "@dimah-s3/server/plugins";
import * as z from "zod";
import { AUDIT_ERROR_CODES } from "./error-codes";

export function audit(store: AuditStore) {
  let env: PluginInitEnv<"audit"> | undefined;

  return definePlugin({
    id: "audit",
    $ERROR_CODES: AUDIT_ERROR_CODES,
    init(initEnv) {
      env = initEnv;
    },
    hooks: {
      upload: {
        onConfirmed: async ({ route, key, object }) => {
          await store.add({ type: "upload", route, key, size: object.size });
        },
      },
    },
    endpoints: {
      listEvents: createS3Endpoint(
        pluginPath("audit", "events"),
        { method: "GET", query: z.object({ route: z.string().optional() }) },
        async (ctx) => ({ events: await store.list(ctx.query.route) }),
      ),
    },
    context: {
      events: (route?: string) => store.list(route),
    },
  });
}
```

Register it on the instance:

```ts title="lib/s3.ts"
import { dimahS3, route } from "@dimah-s3/server";
import { audit } from "./audit";

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  plugins: [audit(store)], // [!code ++]
  routes: {
    invoices: route({ upload: true }),
  },
});

await s3.audit.events("invoices"); // [!code ++]
```

`definePlugin`, `createS3Endpoint`, `createS3Middleware`, and the
[helpers](#helpers) come from `@dimah-s3/server/plugins`. `defineErrorCodes`,
`defineClientPlugin`, `pluginPath`, and `s3Error` come from
`@dimah-s3/core`. `chainHooks` comes from `@dimah-s3/server`.

## Hook execution order

- **Guards** run instance, then route, then feature (`upload.guard`,
  `download.guard`, …). At each level, plugin guards run first in plugin
  order, and your guard runs last.
- **Lifecycle hooks** (`onStart`, `onConfirmed`, `onRejected`, `onPresigned`,
  `onDeleted`, `onAbort`) also run plugins first, then yours. Your hook sees
  what the plugins already wrote, such as the `db()` row.
- A route with `plugins: { [id]: false }` skips that plugin's route hooks.

Unlike the user hook, a plugin's `upload.onConfirmed` can refuse an object
with a `4xx` rejection, which deletes it. A plugin that records an upload in
`onStart` should undo it in `upload.onRejected`. See
[Failure rules](/docs/server/hooks/upload#failure-rules).

### Binding tickets

A plugin can provide `hooks.ticketSubject` to bind
[upload tickets](/docs/server/upload-tickets#binding-a-ticket-to-a-user) when
the config sets none. The first plugin that has one is used. `db()` binds
tickets to the scope this way.

## Guards see plugin calls

Every plugin call runs the instance guards with `operation: "plugin"`: an
endpoint, and an in-process call made with
[`runOperation`](#calls-from-the-server). The context's `plugin` names it,
so an app can allow or refuse one plugin action:

```ts title="lib/s3.ts"
guard: ({ operation, plugin, locals }) => {
  if (operation !== "plugin") return;
  if (plugin?.id === "audit" && plugin.action === "listEvents" && !locals.isAdmin) {
    throw s3Error("FORBIDDEN");
  }
},
```

`plugin.action` is the endpoint's key in `endpoints` (`"listEvents"`), or
the action an in-process call names (`"record"` for `s3.db.record`). Name
endpoints after the client actions that call them, so both read the same.

## Endpoints

`createS3Endpoint(path, options, handler)` builds a plugin endpoint.

- The path sits under the plugin id: `/{id}` or `/{id}/…`, so plugins never
  collide. Build it with `pluginPath(id, path)`, which the client plugin
  uses too. Any other path throws at `dimahS3()`.
- `GET` and `DELETE` read the `query`. `POST`, `PUT`, and `PATCH` read a JSON
  `body`; any other content type returns `415 UNSUPPORTED_MEDIA_TYPE`.
- The instance guards run first. The handler reads `ctx.context.request`,
  `ctx.context.locals` (what those guards returned), and
  `ctx.context.config`.
- A schema failure returns `400 VALIDATION_ERROR`. An `APIError` passes
  through. Anything else is logged, passed to `onError`, and returns
  `500 INTERNAL_ERROR`.
- Return JSON values: the client receives the JSON body, and its types are
  the handler's return type. Send a `Date` as an ISO string.
- Endpoints are HTTP only and are not added to `s3.api`. Expose server-side
  functions through `context`.

`createS3Middleware` builds a middleware with the same context, for checks
that several endpoints share:

```ts
import { createS3Endpoint, createS3Middleware } from "@dimah-s3/server/plugins";
import { s3Error } from "@dimah-s3/server";

const requireUser = createS3Middleware(async (ctx) => {
  if (!ctx.context.locals.userId) throw s3Error("UNAUTHORIZED");
});

createS3Endpoint(
  pluginPath("audit", "export"),
  { method: "POST", use: [requireUser] },
  async (ctx) => ({ url: await exportEvents(ctx.context.locals) }),
);
```

`locals.userId` is typed by a [`DimahS3Locals`](/docs/server/hooks/global-guard#locals)
augmentation.

## Routes and route options

`init` runs once at `dimahS3()`, in plugin order, after the routes are
validated. Keep its env: `env.routes` has every route as `dimahS3()`
resolved it, with the client and bucket it inherits, its `keyPrefix`, which
features are on, and this plugin's options. Throw in `init` to reject the
config. It must be synchronous: a returned promise throws.

Declare your route options by augmenting `DimahS3RoutePluginOptions` with
your id. Routes then set them under `plugins`, typed, and `false` opts a route
out:

```ts title="audit/index.ts"
declare module "@dimah-s3/server" {
  interface DimahS3RoutePluginOptions {
    audit?: false | { downloads?: boolean };
  }
}

definePlugin({
  id: "audit",
  init(env) {
    for (const route of Object.values(env.routes)) {
      // `{ downloads?: boolean } | false | undefined`, no type argument needed
      if (route.options === false)
        env.logger.info?.(`audit is off for ${route.name}`);
    }
  },
});
```

```ts title="lib/s3.ts"
invoices: route({
  upload: true,
  plugins: { audit: { downloads: true } }, // [!code ++]
}),
```

`env.routeOptions(name)` reads the same options for one route. Check a key
against a route with `assertStoredKey(key, env.routes[name].keyPrefix)`.

## Calls from the server

A context method that acts for a caller, such as `s3.db.record`, runs
through `env.runOperation`. It treats the call like `s3.api` does: the
instance guards run (every plugin's, then the user's) with
`plugin: { id, action }`, then the route guard when you name a route. Any
failure leaves as an `APIError`, and an unexpected one is logged and passed
to `onError`.

```ts title="audit/index.ts"
context: {
  note: (input: { route: string; key: string; message: string }, call?: S3ServerCallOptions) =>
    env!.runOperation({ action: "note", route: input.route }, call, async (context) => {
      // context.request, context.locals, context.route
      return store.add({ type: "note", ...input });
    }),
},
```

The app passes `call` the way it calls `s3.api`: `{ headers }`, `{ request }`,
or trusted `{ locals }`.

```ts
await s3.audit.note(
  { route: "invoices", key, message: "Approved" },
  { headers: await headers() },
);
```

## Serving objects a plugin authorized

A plugin that grants access by other means than a session, such as a share
link, still sends the bytes the way the route does. `env.download` presigns
or streams a stored object with the route's `inlineTypes` and lifetime
cap. No guard, `download.resolve`, or download hook runs: your plugin is the
access check, so make it before you call these.

```ts
const route = env.routes[object.route];
if (!route?.download.enabled)
  throw s3Error("FEATURE_DISABLED", { feature: "download" });

if (route.download.mode === "presign") {
  const { url, expiresIn } = await env.download.presign({
    route: route.name,
    key: object.key,
    name: object.name,
    expiresIn: 300,
  });
} else {
  // Inside your own GET endpoint: Range, conditional headers, and the
  // /file hardening headers are handled.
  return env.download.serve(
    { route: route.name, key: object.key },
    ctx.context.request,
  );
}
```

Pick the method by `route.download.mode`: calling `presign` on a route in
proxy mode, or `serve` on one in presign mode, throws a `TypeError`.
`env.url(path)` builds the absolute URL of one of your endpoints under
`baseURL` (or `basePath`), the way proxy download URLs are built.

## Signed tokens

`env.tokens(purpose)` signs short-lived tokens with the instance secret
(`secret` or `DIMAH_S3_SECRET`), under a key derived for your plugin and
that purpose. Use it for a URL that carries a grant, such as a proxied
download. A token of one purpose never verifies for another.

```ts
const grants = env.tokens("grant");
const token = await grants.sign({ link: link.id }, { expiresIn: 300 });
const payload = await grants.verify(token); // `null` when forged or expired
```

The payload is readable by anyone who holds the token: sign ids and flags,
never secrets. Every rotation secret verifies, so rotating keeps tokens
valid until they expire.

## Error codes

Give each failure a stable code with `defineErrorCodes`, and throw it with
`s3Error`. `params` are typed by the `{placeholders}` in the message:

```ts title="audit/error-codes.ts"
import { defineErrorCodes } from "@dimah-s3/core";

export const AUDIT_ERROR_CODES = defineErrorCodes({
  AUDIT_ROUTE_UNTRACKED: {
    status: 400,
    message: 'Route "{route}" is not audited',
  },
});
```

```ts
throw s3Error(AUDIT_ERROR_CODES.AUDIT_ROUTE_UNTRACKED, { route });
```

Set them as `$ERROR_CODES` on the server plugin and the client plugin. They
are merged into `s3.$ERROR_CODES` and the client's `$ERROR_CODES`. A code the
core catalog or another plugin already has throws at startup, so prefix
yours with your id. Match one with `isS3ErrorCode(error, entry)`. React
apps word them with the provider's
[`formatError`](/docs/react/setup#plugin-error-messages); without it, the
English message is shown.

## Client plugin

`defineClientPlugin` adds methods on `api[id]`. Point `$InferServerPlugin` at
the server plugin's type, and the `$fetch` your actions receive is typed by
its endpoints: the path and method pick one, its schema types `query` and
`body`, and the result is what its handler returns. A path, method, or body
the server does not accept fails to compile.

```ts title="audit/client.ts"
import { defineClientPlugin, pluginPath } from "@dimah-s3/core";
import { AUDIT_ERROR_CODES } from "./error-codes";
import type { audit } from "./index";

export function auditClient() {
  return defineClientPlugin({
    id: "audit",
    $InferServerPlugin: {} as ReturnType<typeof audit>,
    $ERROR_CODES: AUDIT_ERROR_CODES,
    getActions: ($fetch) => ({
      listEvents: (route?: string) =>
        $fetch(pluginPath("audit", "events"), {
          method: "GET",
          query: { route },
        }),
    }),
  });
}
```

```ts
const s3Client = createS3Client({ plugins: [auditClient()] });
const { events } = await s3Client.audit.listEvents("invoices");
```

Import the server plugin as a type only, so it never reaches the browser
bundle. Core method names such as `upload` and `delete` are reserved
(`RESERVED_CLIENT_KEYS`).

## Publishing

- **Name.** `dimah-s3-<name>` or `@scope/dimah-s3-<name>`, with the npm
  keyword `dimah-s3-plugin`. Then list it on
  [Community plugins](/docs/server/community-plugins).
- **Entries.** `.` for the server plugin and `./client` for the client
  plugin.
- **Peers.** `@dimah-s3/server` and `@dimah-s3/core` as `peerDependencies`
  (`"^2.0.0"`), never `dependencies`, so the app keeps one copy.
- **Stability.** `@dimah-s3/server/plugins`, `@dimah-s3/server/testing`, and
  the plugin exports of `@dimah-s3/core` follow semver with the packages.
  Anything else under `@dimah-s3/server` is internal.

## Cleaning up uploads

A plugin that tracks uploads, like `db()`, may need to remove an object an
upload left behind. Delete it only while it is still the object that upload
wrote, since another upload may have replaced it at the same key:

```ts
import { HeadObjectCommand } from "@aws-sdk/client-s3";
import {
  deleteObjectIfMatch,
  isAwsNotFound,
  readUploadMarker,
} from "@dimah-s3/server/plugins";

async function removeUpload(client: S3Client, row: TrackedUpload) {
  const head = await client
    .send(new HeadObjectCommand({ Bucket: row.bucket, Key: row.key }))
    .catch((error: unknown) => {
      if (isAwsNotFound(error)) return null;
      throw error;
    });
  if (!head || readUploadMarker(head.Metadata) !== row.uploadToken) return;
  await deleteObjectIfMatch(client, {
    bucket: row.bucket,
    key: row.key,
    eTag: head.ETag,
  });
}
```

## API Reference

### definePlugin()

`definePlugin(plugin)` returns the plugin with its literal `id`, `context`,
`endpoints`, and `$ERROR_CODES` types kept (`DimahS3Plugin`).

| Prop           | Type                           | Default  | Description                                                                                                     |
| -------------- | ------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------- |
| `id`           | `string`                       | required | A letter, then up to 63 letters, digits, `_`, or `-`. Keys `s3[id]`, and every endpoint path sits under `/{id}` |
| `hooks`        | `DimahS3PluginHooks`           | —        | Guards and lifecycle hooks, below                                                                               |
| `endpoints`    | `Record<string, Endpoint>`     | —        | HTTP endpoints built with `createS3Endpoint`. A key is the `plugin.action` guards see                           |
| `$ERROR_CODES` | `S3ErrorCatalog`               | —        | Codes built with `defineErrorCodes`, merged into `s3.$ERROR_CODES`                                              |
| `context`      | `Record<string, unknown>`      | —        | Exposed on `s3.context[id]` and `s3[id]`                                                                        |
| `init`         | `(env: PluginInitEnv) => void` | —        | Runs once at `dimahS3()`, after route validation. Must be synchronous                                           |
| `dependsOn`    | `readonly string[]`            | —        | Plugin ids that must be registered too. A missing or circular dependency throws                                 |

The instance keys (`handler`, `api`, `put`, `context`, `getPlugin`,
`$ERROR_CODES`, `$Infer`) and the core path segments (`presign`, `file`,
`routes`, `delete`) are reserved ids.

### hooks

| Prop            | Type                      | Default | Description                                                                                          |
| --------------- | ------------------------- | ------- | ---------------------------------------------------------------------------------------------------- |
| `guard`         | `Guard<GuardContext>`     | —       | Runs before every operation, before the user's instance guard                                        |
| `ticketSubject` | `TicketSubject`           | —       | Binds upload tickets when the config sets none                                                       |
| `upload`        | `Pick<UploadConfig, …>`   | —       | `guard`, `onStart`, `confirmGuard`, `onConfirmed`, `onRejected`, and `multipart: { guard, onAbort }` |
| `download`      | `Pick<DownloadConfig, …>` | —       | `guard` and `onPresigned`                                                                            |
| `delete`        | `Pick<DeleteConfig, …>`   | —       | `guard` and `onDeleted`                                                                              |

### init environment

`PluginInitEnv<Id>`, the argument of `init`.

| Property       | Type                                 | Description                                                                                                                            |
| -------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `routes`       | `Record<string, PluginRoute>`        | Every route as `dimahS3()` resolved it, keyed by name. Read-only                                                                       |
| `routeOptions` | `(route) => T \| false \| undefined` | This plugin's options for a route, typed by your augmentation. `false`: turned off. `undefined`: nothing set                           |
| `runOperation` | `(target, call, run) => Promise<T>`  | Runs an in-process call behind the guards. See [Calls from the server](#calls-from-the-server)                                         |
| `download`     | `PluginDownloads`                    | `presign(input)` and `serve(input, request)` for an object you authorized. See [Serving objects](#serving-objects-a-plugin-authorized) |
| `tokens`       | `(purpose) => PluginTokens`          | `sign(payload, { expiresIn })` and `verify(token)`. See [Signed tokens](#signed-tokens)                                                |
| `url`          | `(path) => string`                   | The URL of an API path, under `baseURL` when set, else `basePath`                                                                      |
| `config`       | `Readonly<DimahS3Config>`            | The user config, with routes already validated                                                                                         |
| `getPlugin`    | `(id) => DimahS3Plugin \| undefined` | Looks up a registered plugin                                                                                                           |
| `logger`       | `DimahS3Logger`                      | The instance logger                                                                                                                    |

### PluginRoute

One entry of `env.routes`.

| Property    | Type                                                                           | Description                                                                                                      |
| ----------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `name`      | `string`                                                                       | The route name                                                                                                   |
| `client`    | `S3Client`                                                                     | The route's client, or the instance one                                                                          |
| `bucket`    | `string`                                                                       | The route's bucket, or the instance one                                                                          |
| `keyPrefix` | `string \| false`                                                              | The key namespace. `false`: keys are not namespace-checked                                                       |
| `options`   | `T \| false \| undefined`                                                      | This plugin's options for the route                                                                              |
| `upload`    | `{ enabled: false } \| { enabled: true; fileTypes?; maxFileSize?; multipart }` | Whether uploads are on, and their file limits                                                                    |
| `download`  | `{ enabled: false } \| { enabled: true; mode; disposition; maxExpiresIn }`     | Whether downloads are on, `"presign"` or `"proxy"`, the default disposition, and the URL lifetime cap in seconds |
| `delete`    | `{ enabled: boolean }`                                                         | Whether deletes are on                                                                                           |

### runOperation()

`env.runOperation(target, call, run)`.

| Prop            | Type                               | Default  | Description                                                                         |
| --------------- | ---------------------------------- | -------- | ----------------------------------------------------------------------------------- |
| `target.action` | `string`                           | required | What the call does. Guards see it as `plugin.action`                                |
| `target.route`  | `string`                           | —        | The route the call is about. Its guard runs, and a missing one is `ROUTE_NOT_FOUND` |
| `call`          | `S3ServerCallOptions \| undefined` | —        | `headers`, `request`, `signal`, and trusted `locals`, as for `s3.api`               |
| `run`           | `(context) => Promise<T>`          | required | Runs after the guards with their context: `request`, `locals`, `route`              |

### download

`env.download.presign(input)` and `env.download.serve(input, request)`.
Both throw `ROUTE_NOT_FOUND`, `FEATURE_DISABLED` when the route's download
is off, `KEY_INVALID`, and `OBJECT_NOT_FOUND`.

| Prop           | Type                       | Default                       | Description                                                   |
| -------------- | -------------------------- | ----------------------------- | ------------------------------------------------------------- |
| `route`        | `string`                   | required                      | The object's route                                            |
| `key`          | `string`                   | required                      | The object key, inside the route namespace                    |
| `name`         | `string`                   | the stored name, else the key | File name the browser saves                                   |
| `disposition`  | `"inline" \| "attachment"` | the route's `disposition`     | `inline` is kept only for a type on the route's `inlineTypes` |
| `expiresIn`    | `number`                   | the route's `maxExpiresIn`    | `presign` only. URL lifetime in seconds, capped by the route  |
| `signal`       | `AbortSignal`              | —                             | `presign` only. Aborts the HeadObject                         |
| `cacheControl` | `string`                   | `"private, no-cache"`         | `serve` only                                                  |

`presign` resolves to `{ url, disposition, expiresIn }`. `serve` resolves
to the `Response`, and throws the `/file` errors with its hardening headers.

### createS3Endpoint()

`createS3Endpoint(path, options, handler)`. Options also accept the other
better-call endpoint options.

| Prop     | Type                                              | Default  | Description                                       |
| -------- | ------------------------------------------------- | -------- | ------------------------------------------------- |
| `method` | `"GET" \| "POST" \| "PUT" \| "PATCH" \| "DELETE"` | required | HTTP method                                       |
| `query`  | Standard Schema                                   | —        | Query schema                                      |
| `body`   | Standard Schema                                   | —        | JSON body schema. `POST`, `PUT`, and `PATCH` only |
| `use`    | `Middleware[]`                                    | —        | Middlewares, such as from `createS3Middleware`    |

The handler reads `ctx.context` (`S3EndpointContext`):

| Property  | Type                      | Description                       |
| --------- | ------------------------- | --------------------------------- |
| `config`  | `Readonly<DimahS3Config>` | The config passed to `dimahS3()`  |
| `request` | `Request`                 | The incoming request              |
| `locals`  | `DimahS3Locals`           | What the instance guards returned |

`S3Endpoint`, `S3EndpointMethod`, and `S3EndpointOptions` type what
`createS3Endpoint` takes and returns. `PluginContextMap<Plugins>` maps a
plugin list to the contexts on `s3.context`, and `PluginErrorCodes<Plugins>`
to their merged codes.

### defineClientPlugin()

`defineClientPlugin(plugin)` from `@dimah-s3/core`.

| Prop                 | Type                  | Default  | Description                                                                  |
| -------------------- | --------------------- | -------- | ---------------------------------------------------------------------------- |
| `id`                 | `string`              | required | Equal to the server plugin's id. The methods land on `api[id]`               |
| `getActions`         | `($fetch) => methods` | required | Builds the methods. `$fetch` is typed by the server plugin when it is named  |
| `$InferServerPlugin` | type only             | —        | `{} as ReturnType<typeof yourPlugin>`. Never read at runtime                 |
| `$ERROR_CODES`       | `S3ErrorCatalog`      | —        | Codes built with `defineErrorCodes`, merged into the client's `$ERROR_CODES` |

### Helpers

| Export                                                                    | Description                                                                                                                                                             |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pluginPath(id, path)`                                                    | `"/{id}/{path}"`, typed as a literal so a typed `$fetch` matches it. From `@dimah-s3/core`                                                                              |
| `assertStoredKey(key, keyPrefix)`                                         | The normalized key when it is inside the route namespace, else `KEY_INVALID`                                                                                            |
| `readUploadMarker(metadata)`                                              | The `uploadToken` an object was written with, from HeadObject `Metadata`. The same token your hooks receive                                                             |
| `readObjectMetadata(metadata)`                                            | Splits HeadObject `Metadata` into decoded user `metadata`, `uploadToken`, and `previousKey`                                                                             |
| `deleteObjectIfMatch(client, { bucket, key, eTag })`                      | Deletes with `If-Match`. Returns `false` when a newer object is at the key. Falls back to a plain delete on providers without conditional deletes. Other failures throw |
| `isAwsNotFound(error)`                                                    | True for a missing object or multipart upload, by error name, `Code`, or HTTP status                                                                                    |
| `assertFileConstraints({ fileTypes, maxFileSize }, { name, size, type })` | Throws the `FILE_TYPE_NOT_ALLOWED`, `FILE_EMPTY`, or `FILE_TOO_LARGE` an upload would get. For objects your plugin takes in another way, as `s3.db.record` does         |
| `isFeatureOn(toggle)`                                                     | True for `true` or an options object, the way route features are turned on                                                                                              |
| `chainHooks(...hooks)`                                                    | Runs hooks in order in one slot. From `@dimah-s3/server`                                                                                                                |

## Frequently asked questions

<Accordions>

<Accordion title="How do I combine several guards in one slot?">

Use `chainHooks`. It runs each hook in order and stops at the first throw.
Each `{ locals }` result is merged before the next hook runs, so chained
guards behave like separate ones:

```ts
import { chainHooks } from "@dimah-s3/server";

upload: {
  guard: chainHooks(requireUser, checkQuota), // [!code ++]
},
```

</Accordion>

<Accordion title="Why is my endpoint's client result typed as a Date?">

The client's types are the handler's return type, and JSON turns a `Date`
into a string. Return `date.toISOString()` from the handler, and the client
type and the value agree.

</Accordion>

<Accordion title="Can a plugin add database tables?">

Not through `db()`. Keep your own storage behind an interface the app
provides, as `examples/plugin-audit` does with its store.

</Accordion>

</Accordions>
