[`@dimah-s3/server`](https://www.npmjs.com/package/@dimah-s3/server) is the
backend half of dimah-s3. It holds your S3 credentials, signs short-lived URLs
for the browser, and runs your guards and hooks around every file operation.

```ts title="lib/s3.ts"
import { dimahS3, route } from "@dimah-s3/server";

export const s3 = dimahS3({
  client: awsS3, // your S3Client
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      upload: { fileTypes: ["image/*"], maxFileSize: 2 * 1024 * 1024 },
      download: true,
      delete: true,
    }),
  },
});
```

```ts title="app/api/s3/[...s3]/route.ts"
import { toNextJsHandler } from "@dimah-s3/server/next";
import { s3 } from "@/lib/s3";

export const { GET, POST, PUT, PATCH, DELETE } = toNextJsHandler(s3);
```

## How it works

- **Direct transfers.** Uploads, and by default downloads, go straight between
  the browser and the bucket through signed URLs. Deletes run on the server.
- **Server-owned keys.** The browser sends a route name. The server builds the
  object key and signs it into an upload ticket.
- **Verified objects.** Confirm reads the stored size and type from S3, not
  from the browser.
- **Guards and hooks.** Guards authorize each call. Lifecycle hooks record
  what happened.
- **One instance.** `dimahS3()` returns an HTTP `handler` for Next.js, Hono,
  Express, Fastify, SvelteKit, Elysia, Node, or any Fetch runtime, an
  in-process `api`, and `put` for server-side uploads.
