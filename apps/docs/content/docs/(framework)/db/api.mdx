## Server store

After `db()` is registered, the store is available as `s3.db` (also `s3.context.db`):

```ts
s3.db.objects.listByScope({ scope, limit: 50, offset: 0 });
```

You can also build a store without the HTTP plugin: `createStorageObjectStore(dimahS3Db)`.

| Method                                             | Purpose                                      |
| -------------------------------------------------- | -------------------------------------------- |
| `listByScope({ scope, status?, limit?, offset? })` | list objects (skips `deleted` by default)    |
| `countByScope({ scope, status? })`                 | count with the same default as list          |
| `find` / `findActive`                              | load one row                                 |
| `findPendingMultipart({ bucket, key, fileSize })`  | source for multipart resume                  |
| `getScopeUsage(scope)`                             | sum of `size ?? declaredSize` + object count |
| `softDelete` / `hardDelete`                        | mark `deleted` vs remove the DB row          |

<Callout type="info">
  `softDelete` / `hardDelete` only touch the **database**. The normal delete API
  already removes the S3 object first, then applies `deleteMode` (default soft)
  in `onDeleted` — see [Delete behavior](/docs/db/setup#delete-behavior).
</Callout>

## Browser listing (`dbClient`)

The server plugin mounts `GET /api/s3/plugins/db/objects`. On the client, add `dbClient()` to `createS3Client` — no custom app route:

```ts
import { createS3Client } from "@dimah-s3/react";
import { dbClient } from "@dimah-s3/db/client";

export const { api, S3Provider, useApi } = createS3Client({
  basePath: "/api/s3",
  plugins: [dbClient()],
});

await api.db.listObjects({ limit: 50, offset: 0 });

// inside a client component
const client = useApi();
const { scope, usage, objects } = await client.db.listObjects({ limit: 50 });
```

`listObjects({ status?, limit?, offset? })` returns `{ scope, usage, objects }` for the caller’s resolved scope.

Each item is a `DbClientObject` (a safe subset of the DB row):

| Field          | Notes                                 |
| -------------- | ------------------------------------- |
| `id`           | row id                                |
| `bucket`       | pass to `api.download` / `api.delete` |
| `key`          | S3 object key                         |
| `filename`     | from Content-Disposition when known   |
| `contentType`  | MIME type                             |
| `size`         | verified size once active             |
| `declaredSize` | client-declared size while pending    |
| `status`       | `pending` \| `active` \| `deleted`    |
| `createdAt`    | ISO-8601 string                       |

```ts
const { objects } = await api.db.listObjects({ limit: 50 });
await api.download(objects[0].key, { bucket: objects[0].bucket });
```

## Quota

Quota is **app-owned**. The plugin enforces ownership first; put your limit on the feature config:

```ts
const s3 = dimahS3({
  plugins: [db({ client: dimahS3Db, resolveScope })],
  upload: {
    enabled: true,
    presignGuard: async ({ request, fileSize }) => {
      const scope = await resolveScope(request);
      const { totalBytes } = await s3.db.objects.getScopeUsage(scope!);
      if (totalBytes + (fileSize ?? 0) > MAX_BYTES) {
        throw forbidden("Quota exceeded");
      }
    },
  },
});
```

<Callout type="tip">
  Stack multiple guards with `chainHooks` from `@dimah-s3/server` when you need
  plugin ownership plus your own policy in one feature.
</Callout>

## Custom access

For download / delete rules beyond “same scope”, use `createObjectAccessGuard`:

```ts
createObjectAccessGuard({
  db: dimahS3Db,
  resolveScope,
  authorize: (object, { scope }) =>
    object.scope === scope || object.metadata?.visibility === "public",
});
```
