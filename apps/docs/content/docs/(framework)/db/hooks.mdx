title: Hooks
description: Guards and row updates the db plugin adds to each lifecycle step.
---

The [`db()`](/docs/db/setup) plugin attaches guards and database updates to
upload, multipart, download, and delete. Enable the feature, register the
plugin — you do not wire these hooks yourself.

Your own **guards** still run after the plugin. Lifecycle `on*` hooks run
**before** the plugin so a throw from `onConfirmed` can delete the S3 object
before `db()` marks the row active.

## Access rules

The plugin resolves the caller's scope (configured in
[Setup](/docs/db/setup)) and rejects:

| Situation                       | Response                   |
| ------------------------------- | -------------------------- |
| No scope (unauthenticated)      | `401` (`UNAUTHORIZED`)     |
| File owned by another scope     | `403` (`FORBIDDEN`)        |
| Expected row missing or deleted | `404` (`OBJECT_NOT_FOUND`) |

## By feature

| Feature        | Before                                                                                | After                                                                                       |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Upload         | Reject if a non-deleted row belongs to another scope (soft-deleted keys are reusable) | Row created or updated as `pending`                                                         |
| Upload confirm | Row must be `pending` (or owned when `upload.replace: "overwrite"`) | Promoted to `active` with HeadObject size (`declaredSize` is the client claim from presign) |
| Multipart      | Pending row + matching `uploadId` for part / list / abort / complete                  | `pending` on start, `active` on complete, pending row removed on abort                      |
| Download       | File must be `active` (confirmed) and owned                                           | —                                                                                           |
| Delete         | Row must be `pending` or `active` and owned                                           | Row updated per [`deleteMode`](/docs/db/setup#delete-behavior)                              |

Delete always removes the file from S3 through the normal
[`api.delete`](/docs/react) path. The plugin only updates the database row
afterward.

## Multipart resume

To resume a large upload after a refresh, load the pending row with
`s3.db.objects.findPendingMultipart`, map it with
`toPendingMultipartResume`, and return it from a custom
[`UploadStore`](/docs/react/upload-store) on the client.

See [API](/docs/db/api) for store methods.
