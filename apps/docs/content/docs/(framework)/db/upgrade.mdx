---
title: Upgrade the Schema
description: Move a 1.x or earlier 2.x database to schema 2.3.0, the only one @dimah-s3/db reads, by creating new tables and recording your objects.
---

`@dimah-s3/db` reads and writes schema `2.3.0`, the only schema in the
package. It does not upgrade a database at another version, a 1.x database
or one created at an earlier `2.x` schema. Create the new tables, then
record the objects already in your bucket. For the code changes in every
package, see the [2.0 upgrade guide](/docs/migration-2-0).

### Create the tables on a new database [step]

Follow [Setup](/docs/db/setup#create-the-tables-step): generate the Drizzle
tables or the Prisma models with `runCli`, or call `migrate(client)` with
Kysely. Point those tools at a new database.

Do not diff the old database into the new schema. An ORM diff against a
database at another version can drop columns, and it cannot fill the
columns the new schema requires for rows already there. `migrate(client)`
does nothing on a database already at `2.3.0`, and throws on one at another
version.

### Create the folders [step]

Create each folder with `s3.db.folders.create(scope, { parentId, name })`,
parents before children, and keep the ids it returns. A folder is its id,
and an object stores `folderId`.

### Record the objects [step]

The objects stay where they are in the bucket: only the rows are new. Read
your old rows with your own query, then write each object into the new
database with [`s3.db.record`](/docs/db/api#recording-an-object). It reads
the size, type, and ETag from HeadObject, so the new row describes what is
really in the bucket.

```ts title="scripts/import.ts"
// `oldRows` is your own query on the old database.
for (const row of oldRows) {
  const locals = { userId: row.userId }; // what your guards and resolveScope read
  await s3.db.record(
    {
      route: row.route,
      key: row.key, // must sit inside the route's keyPrefix
      name: row.fileName,
      folderId: folderIds.get(row.folderPath) ?? null,
    },
    { locals },
  );
}
```

- `record` runs your guards, `resolveScope`, `authorize`, the route's
  `fileTypes` and `maxFileSize`, and the quota. Pass the `locals` (or a
  `request`) that resolve to the owner of each object.
- An object whose key is outside the route's `keyPrefix` is `KEY_INVALID`.
  Record it through a route whose namespace holds it.
- Calling `record` again for the same bytes returns the same row, so the
  script can run again after a failure.
- Leave out rows that were pending or deleted in the old database: they
  describe no object worth keeping.
- When the plugin has an `attributes.schema`, set app data with
  `s3.db.objects.update(ref, { attributes })`.

### Check the schema [step]

Call `checkSchema` at startup:

```ts
await s3.db.checkSchema();
```

It throws unless the database is at `2.3.0` and both tables can be read.
The first query runs the same check, so a database at another version, or
one the generated schema was never applied to, is never read with the wrong
columns.

## Code that reads the tables

`s3.db.objects` and `s3.db.folders` return plain rows, with numbers for
sizes. Code that queries the tables itself sees the generated types:

- The display name of an object is `name` (column `name`), and the ETag
  column is `etag`.
- `size` and `declaredSize` are `bigint` in JavaScript, not `number`.
  `JSON.stringify` throws on a `bigint`, and so does arithmetic with a
  `number`. Convert with `Number(row.size)`.
- `status` is a `string`, and `s3Metadata` is `unknown`.
- `id` has no default. The plugin generates ids, so a row you insert
  yourself needs one.
- `searchName` is the name folded for search and the name sort. The plugin
  sets it whenever it writes an object or folder `name`. A rename you write
  through the ORM leaves search and the name sort on the old name: rename
  through `s3.db.objects.update` or `s3.db.folders.update`.
- `storage_folder.path` caches the names from the root down. The plugin
  rewrites it when a folder is renamed or moved. Do not write it yourself.
- The Prisma models are `storageObject` and `storageFolder`.
