[`@dimah-s3/db`](https://www.npmjs.com/package/@dimah-s3/db) is an optional
plugin for [`dimahS3()`](/docs/server/setup). It keeps one database row per
S3 object, so the server knows who owns each file, which folder holds it,
and how much a user stores.

```ts title="lib/s3.ts"
import { db } from "@dimah-s3/db";
import { dimahS3 } from "@dimah-s3/server";

export const s3 = dimahS3({
  // client, bucket, routes…
  plugins: [
    db({
      client: dimahS3Db, // DimahS3Db.client(adapter), see Setup
      getSession,
      resolveScope: ({ session }) =>
        session ? `user:${session.userId}` : null,
    }),
  ],
});
```

## Do you need it?

dimah-s3 works without a database. Without `db()`, the server checks that a
key sits in its route's namespace, and your own `download.guard` and
`delete.guard` decide who may touch it. With `db()`, that check stays, and
the plugin adds:

- **Ownership.** Each object belongs to a scope you define, such as
  `user:123`. Upload tickets are bound to it, and download and delete reach
  only the caller's own objects.
- **Listings.** Pages of objects by folder, with search and sort, on the
  server and in the browser ([`ObjectList`](/docs/ui/components/object-list)).
- **Folders.** Logical folders you can rename and move. They never change
  the S3 key.
- **Quotas.** Caps on bytes, files, and folders per scope.
- **Lifecycle.** A row from upload start to delete, and a
  [purge job](/docs/db/purge) for uploads that never confirmed.

Authentication, quota values, and business rules stay in your app.

## Object lifecycle

Each row moves through these statuses:

| Status    | Meaning                                               |
| --------- | ----------------------------------------------------- |
| `pending` | Upload started, not confirmed                         |
| `active`  | Confirmed in S3, with the verified size stored        |
| `deleted` | Removed from S3, row kept (soft delete)               |
| `purging` | Expired before confirm, and being cleaned up by purge |

The usual path is `pending` → `active` → `deleted`. A `pending` row expires
with its upload ticket, and [purge](/docs/db/purge) removes it.

## Supported databases

The plugin runs on SQLite, PostgreSQL, and MySQL through one of three
adapters:

| Adapter | Peer dependency                        | Tables come from                                |
| ------- | -------------------------------------- | ----------------------------------------------- |
| Drizzle | `drizzle-orm` 1.x (`1.0.0-rc.5` or up) | `runCli` → `generate`, then `drizzle-kit`       |
| Prisma  | `@prisma/client` 6 or 7                | `runCli` → `generate`, then Prisma Migrate      |
| Kysely  | `kysely` 0.29 (`0.29.8` or up)         | `migrate(client)`, or the SQL `generate` writes |
