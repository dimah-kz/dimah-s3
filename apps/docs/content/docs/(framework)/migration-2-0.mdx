---

The 2.0 beta changes the wire protocol, the hook contracts, and the components
of every `@dimah-s3/*` package. Upgrade them together: `@dimah-s3/ui` and
`@dimah-s3/db` pin their `@dimah-s3/*` peers to the same version, and a 1.7
client does not work against a 2.0 beta server.

This line is `2.0.0-beta`. A new beta ships every few days, and it can include
breaking changes until `2.0.0`. Install with the `beta` dist-tag. `@latest`
stays on 1.x. Each package's changelog lists every change; this page covers
what most apps need.

## Install

```npm
npm i @dimah-s3/server@beta @dimah-s3/core@beta @dimah-s3/react@beta @dimah-s3/ui@beta @fuma-translate/react
```

- `@dimah-s3/react` and `@dimah-s3/ui` need React 19.2 or later, as
  `@fuma-translate/react` does.
- `@dimah-s3/core` and `@fuma-translate/react` are peer dependencies of
  `@dimah-s3/react`. Install both yourself, with `@dimah-s3/core` on the same
  version as `@dimah-s3/react`. React no longer re-exports core.
- Node.js 22 or newer is required. In the browser, the hooks need Chrome 119,
  Firefox 124, Safari 17.4, or newer.
- With `db()`, add `@dimah-s3/db@beta` and follow
  [Database](#database) below.

## Server

### Set the upload secret

Presign and multipart init now return a signed
[upload ticket](/docs/server/upload-tickets), and confirm accepts only a
ticket the server signed. Set a secret of at least 32 characters, the same on
every instance:

```dotenv title=".env"
# openssl rand -base64 32
DIMAH_S3_SECRET="your-generated-secret"
```

`dimahS3()` reads `DIMAH_S3_SECRET` on the first upload. Pass `secret` to
read it from somewhere else, or an array to rotate: the first value signs,
and every value verifies. An empty `secret` counts as not set.

```ts title="lib/s3.ts"
export const s3 = dimahS3({
  // ...
  secret: [process.env.DIMAH_S3_SECRET!, process.env.DIMAH_S3_SECRET_OLD!], // [!code ++]
});
```

Without a secret, uploads return `500` unless `NODE_ENV` is `development` or
`test`, where a random secret is used with a warning.

### Configure the `S3Client` checksums

The AWS SDK default (`WHEN_SUPPORTED`) breaks presigned uploads. Every
`S3Client` you pass must set:

```ts title="lib/s3.ts"
export const awsS3 = new S3Client({
  // ...
  requestChecksumCalculation: "WHEN_REQUIRED", // [!code ++]
});
```

With the SDK default, the first presign logs the problem and returns `500`.

### Update the route config

- `upload.method` defaults to `"PUT"`, which AWS, R2, and MinIO support.
  Set `method: "POST"` to keep presigned POST, or for a provider that
  rejects presigned PUT, such as [ArvanCloud](/docs/providers/arvancloud).
- `download.expiresIn` is now `download.maxExpiresIn`.
- `upload.replace` is now the db route option
  `plugins: { db: { replace: "overwrite" } }`.
- In `upload.object`, `folder` is now `keyFolder`.
- Downloads open inline only for raster images, PDF (presign mode), audio,
  video, and plain text. Set `download.inlineTypes` to change the list.
- `upload.expiresIn`, `upload.confirmWindow`, `upload.maxFileSize`,
  `upload.multipart.partSize`, `upload.multipart.ticketExpiresIn`, and
  `download.maxExpiresIn` must be positive integers. A fractional value now
  throws at `dimahS3()`.
- `/file` serves only routes with `download.mode: "proxy"`. A presign-mode
  route returns `404 FEATURE_DISABLED` there.
- Routes on different buckets may share a `keyPrefix`; on one bucket they
  still may not overlap.
- A zero-byte file is rejected with `FILE_EMPTY`.
- S3 user metadata from `upload.object` is limited to 2 KB in total, keys and
  values together. Non-ASCII values are RFC 2047-encoded when written and
  decoded when read, so `object.metadata` returns what you set.
- `download.resolve` must return `expiresIn` as a positive integer. Anything
  else is a config error and returns `500`.

### Rewrite guards and errors

The `errors` export is removed. Replace `throw errors.unauthorized()` and the
other helpers with `throw s3Error("UNAUTHORIZED")` and another catalog code. A plain
`Error` thrown from a hook returns `500 INTERNAL_ERROR` and is logged.

A guard returns nothing to allow, or `{ locals }` to allow and pass values to
later hooks in the same call. Any other return value, such as `true`, is a
config error.

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";

declare module "@dimah-s3/server" {
  interface DimahS3Locals {
    userId?: string;
  }
}

export const s3 = dimahS3({
  // ...
  guard: async ({ request }) => {
    const session = await getSession(request);
    if (!session) throw s3Error("UNAUTHORIZED"); // [!code highlight]
    return { locals: { userId: session.userId } }; // [!code highlight]
  },
  routes: {
    avatar: route({
      upload: {
        object: ({ locals }) => ({ keyFolder: locals.userId }),
      },
    }),
  },
});
```

Lifecycle `on*` hooks now run plugin hooks first, then yours, the same as
guards. `onError` is called as `onError(error, { request, operation })`.
Every hook context has `operation` and `locals`.

### Rename the upload hooks

| 1.7                                                                            | 2.0 beta                                                          |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| `upload.onPresigned`                                                           | `upload.onStart` (`kind` is `presignedPost` or `presignedPut`)    |
| `upload.multipart.onInit`                                                      | `upload.onStart` (`kind` is `multipart`)                          |
| `upload.multipart.onList`                                                      | Removed                                                           |
| `StoredObjectContext`                                                          | `ObjectContext`                                                   |
| `ObjectFile`                                                                   | `UploadFile` (declared file) and `VerifiedObject` (stored object) |
| `UploadOnPresignedContext`, `MultipartOnInitContext`, `MultipartOnListContext` | `UploadOnStartContext`                                            |
| `file: { fileName, ... }`                                                      | `file: { name, size, type }`                                      |
| `onDeleted({ existed })`                                                       | `onDeleted` without `existed`                                     |
| `RouteFeature`, `RouteOperation`                                               | `operation: S3Operation` on every context                         |

`upload.onStart({ kind, uploadToken, uploadId, url, urlExpiresAt, expiresAt })`
also runs for `s3.put`, with `kind: "server"`.

`upload.multipart.guard` runs for sign part, list parts, complete, and abort.
Narrow on `operation` (`"multipart.signPart"`, `"multipart.listParts"`,
`"multipart.complete"`, `"multipart.abort"`); the sign-part context also has
`partNumber` and `size`.

What the browser sends with an upload is `clientMetadata` in every upload
hook. It is never written to S3 unless `upload.object` copies it into
`metadata`.

`upload.onConfirmed` runs **at least once** per upload. A retried confirm
calls it again with the same `uploadToken`, so make its writes idempotent:

```ts title="lib/s3.ts"
avatar: route({
  upload: {
    onConfirmed: async ({ key, uploadToken, object, locals }) => {
      await db.avatar.upsert({
        where: { uploadToken },
        create: { uploadToken, key, size: object.size, userId: locals.userId },
        update: {},
      });
    },
  },
}),
```

A throw from `onConfirmed`, including an `APIError`, returns `500` and keeps
the object. To reject a file after upload, throw from `upload.confirmGuard`
instead: that deletes the object.

`upload.onRejected` is new. It runs after confirm, multipart complete, or
`s3.put` refused an upload and deleted its object, so you can undo what
`onStart` recorded. See
[Upload Hooks](/docs/server/hooks/upload#when-an-upload-is-rejected).

### Update server calls

`s3.api` has the browser client's shape. Each method takes the browser
payload, then `{ headers, request, locals }` for the hooks:

```ts title="app/invoices/[key]/page.tsx"
import { headers } from "next/headers";
import { s3 } from "@/lib/s3";

const { url } = await s3.api.download(
  { route: "invoices", key },
  { headers: await headers() }, // [!code highlight]
);
```

The aliases `deleteBatch`, `multipart*`, and `file` are removed. Use
`deleteMany` and `multipart.*`. Plugin endpoints, such as the `db()` list,
are HTTP only and no longer on `s3.api`; a plugin's server API is on the
instance (`s3.db`).

`s3.put` takes `name` and `type` in place of `fileName` and `contentType`,
and moves `headers` to the second argument. `metadata` is written to S3, and
`clientMetadata` only reaches the hooks:

```ts
await s3.put({
  route: "avatar",
  name: "avatar.png", // [!code highlight]
  type: "image/png", // [!code highlight]
  body: bytes,
});
```

`putObject`, `PutObjectInput`, and the `Resolved*`, `Opened*`, `Enabled*`,
and `Disabled*` types are no longer exported.

### Update plugins

If you wrote a server plugin:

- `definePlugin`, `createS3Endpoint`, `createS3Middleware`, `isFeatureOn`, and
  the plugin types (`DimahS3Plugin`, `DimahS3PluginHooks`, `PluginContextMap`,
  `PluginInitEnv`, `S3EndpointContext`) are exported from
  `@dimah-s3/server/plugins` only. Config and hook-context types, and
  `chainHooks`, come from `@dimah-s3/server` only. The `@dimah-s3/server/api`
  entry is gone.
- `init` must be synchronous. A returned promise throws at `dimahS3()`.
- `createS3Endpoint(path, options, handler)` always takes a path, and throws
  for a core path. `method` is `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`;
  body endpoints accept JSON only.
- Endpoints are HTTP only. Expose server-side functions through `context`.
  `DimahS3Plugin` has no endpoint type parameter, and `PluginEndpointMap` is
  removed.
- Only a rejection (a `4xx` `APIError`) from a plugin `onConfirmed` deletes
  the object. Any other throw keeps it and returns `500`, so the client can
  retry. Add `upload.onRejected` to undo what your `onStart` wrote.
- Reserved plugin ids are the instance keys: `handler`, `api`, `put`,
  `context`, `getPlugin`, `$ERROR_CODES`, and `$Infer`.
- A switch on `operation` needs cases for `"plugin"` (plugin endpoints) and
  `"record"` (`s3.db.record`).

### Check custom proxies and CORS

- Body endpoints accept `application/json` only and return
  `415 UNSUPPORTED_MEDIA_TYPE` otherwise.
- Request bodies are capped by `maxRequestBodySize` (1 MiB by default).
- `/file` URLs are relative to the API base path unless you set `baseURL`.
  See [File proxy](/docs/server/file-proxy).
- Node adapters ignore `X-Forwarded-*` unless you pass `{ trustProxy: true }`.

## React

### Move imports

The root entry holds hooks, `S3Provider`, `createS3Client`, the `useFormat*`
hooks, and types. Protocol names come from `@dimah-s3/core`, and plain
functions from `@dimah-s3/react/engine`:

```ts
import { useUpload } from "@dimah-s3/react";
import { APIError, isS3ErrorCode } from "@dimah-s3/core"; // [!code ++]
import { createLocalStorageUploadStore } from "@dimah-s3/react/engine"; // [!code ++]
```

`@dimah-s3/react/engine` has no `"use client"` directive and no React
import, so you can use it in shared and server modules. The display
formatters `formatFileSize` and `truncateFileName` live there too; they are
not in `@dimah-s3/core`. `formatSpeed` and `formatUploadProgress` are
removed: use `useFormatSpeed()` and `useFormatFileSize()`, which follow the
`S3Provider` locale and translations.

### Update `useUpload`

Callbacks now run per file, and `handleFiles` resolves a result object.
`onSuccess` gets one result instead of an array:

```tsx
const upload = useUpload({
  route: "avatar",
  onSuccess: (result) => setValue("avatarKey", result.key), // [!code highlight]
});

const { uploaded, failed, rejected, blocked, aborted } =
  await upload.handleFiles(files);
```

- `onFileSuccess`, `onFileError`, `onFileProgress`, and `onCancel` are
  removed. Use `onSuccess(result, file)`, `onError(error, file)`,
  `onProgress(progress, file)`, and `onSettled(result)`.
- `files[].status` is now `phase`, and `isUploading` is now `isPending`.
- `getUploadOptions` is merged into `uploadOptions`, which can be a function
  of the file. Its `metadata` field is now `clientMetadata`, the name the
  server hooks use.
- The upload result (`UploadResult`) uses `name`, `size`, and `type`. Its
  `metadata` is the S3 user metadata the server wrote.
- The `checksum` options and `multipartPartSize` are removed. The server's
  route config decides both.
- An invalid file no longer stops the batch: it is in the result's
  `rejected`. `cancel(ids?)` and `reset(ids?)` take one id or several. Pass
  `append: true` to add new files to the queue instead of replacing it.
- `retry(ids?)` sends failed files again in place: one id, several, or every
  failed file. A test stub that builds a whole `UseUploadReturn` must add
  `retry` and `disabled`.
- File ids are short strings such as `upload-1`, not UUIDs.
- `retry: { baseDelay }` is now `retry: { baseDelayMs }`. Requests are also
  retried when your API answers 408, 429, or 500 and above, and a stored
  multipart upload is kept after such a failure.
- `onPartUpload` receives `{ partNumber, partCount }`; `totalParts` is now
  `partCount`.
- The types `DropzoneRootProps` and `DropzoneInputProps` are now
  `UploadRootProps` and `UploadInputProps`.
- `uploadStore: false` is removed; leave the option out. `createMemoryStore`
  and `createLocalStorageStore` are now `createMemoryUploadStore` and
  `createLocalStorageUploadStore`. A custom `UploadStore` implements
  `get(resumeKey, fileSize)`, `set(upload)`, and `delete(resumeKey)`, and a
  `StoredUpload` holds the upload ticket and the server's part layout. Resume
  records from 1.7 are ignored.
- `FileUploadConfig` is removed. Use `UseUploadOptions` for the hook and
  `UploadFileOptions` for `uploadFile`.

### Split fetch downloads

`useDownload({ mode: "fetch" })` is now its own hook:

```ts
import { useFetchDownload } from "@dimah-s3/react";

const download = useFetchDownload({ route: "invoices" });
```

`onInitiated` is now `onSuccess(data, key)`, and `isFetchDownload` is
removed: narrow on `download.kind` (`"navigate"` or `"fetch"`).
`download(key, { fileName })` and `presign(key, options)` return an outcome.
A cancelled call settles with an `aborted` outcome instead of `onCancel`.

`useFetchDownload` has no `disposition` option, since it always saves the
file, and its result is `{ fileName, fileSize }`. `UseNavigateDownloadOptions`
and `UseNavigateDownloadReturn` are now `UseDownloadOptions` and
`UseDownloadReturn`.

### Move the delete confirmation

`useDelete` keeps no confirm state. `requestDelete`, `confirmDelete`,
`cancelDelete`, and `isConfirming` are removed. Call `remove(key)` directly,
or let the ui `Delete` root show the dialog. Callbacks are
`onSuccess(data, key)`, `onError(error, key)`, and `onSettled(result)`, and
`removeMany(items)` returns `{ deleted, failed, blocked }`. `reset()` removes
settled operations only; it no longer cancels a delete that is running.

### Read per-key state

`useDelete`, `useDownload`, and `useFetchDownload` keep state per key:
`operations`, `get(key)`, and `pendingKeys`. A second call for a key that is
already running joins that call.

### Rename error helpers

| 1.7                          | 2.0 beta                                |
| ---------------------------- | --------------------------------------- |
| `S3UploadError`              | `APIError` with a catalog `code`        |
| `useFormatValidateFileError` | `useFormatError`                        |
| `formatEta`                  | `useFormatEta`                          |
| `UploadProgress`             | `TransferProgress`                      |
| `FetchDownloadProgress`      | `TransferProgress`                      |
| `useObjectUrl().expiresIn`   | `useObjectUrl().expiresAt` (epoch ms)   |
| `uploadFiles(...)`           | `uploadFile(api, file, { route, ... })` |
| `useApi()`                   | `useS3Api()`, or `s3Client.useApi()`    |

An aborted upload rejects with an `AbortError` `DOMException`. Use
`getUploadAbortKind` from `@dimah-s3/react/engine` to tell a cancel from a
detach.

Translation keys changed. `satisfies Partial<Translations>` flags each key
that no longer exists. See [Internationalization](/docs/i18n).

## UI

### Replace the preset components

Each control is now a root that takes the hook return, plus parts inside it.
Components no longer toast: mount one toast component per hook and one
`<Toaster />` in your layout.

```tsx title="components/avatar-upload.tsx"
"use client";

import { useUpload } from "@dimah-s3/react";
import {
  Upload,
  UploadStatus,
  UploadToasts,
  UploadTrigger,
} from "@dimah-s3/ui";

export function AvatarUploader() {
  const upload = useUpload({ route: "avatar" });

  return (
    <>
      <Upload upload={upload}>
        <UploadTrigger />
        <UploadStatus />
      </Upload>
      <UploadToasts upload={upload} />
    </>
  );
}
```

| 1.7                                   | 2.0 beta                                                         |
| ------------------------------------- | ---------------------------------------------------------------- |
| `UploadButton`                        | `<Upload upload><UploadTrigger /><UploadStatus /></Upload>`      |
| `UploadDropzone upload={...}`         | `<Upload upload><UploadDropzone /></Upload>`                     |
| `MultiUploadStatus`                   | `UploadStatus`                                                   |
| `UploadFileStatus`                    | `UploadFileItem` or `UploadFileList`                             |
| `DownloadButton`                      | `<Download download><DownloadTrigger objectKey /></Download>`    |
| `ProgressDownloadButton`              | `useFetchDownload` with `DownloadTrigger` and `DownloadProgress` |
| `DeleteButton`                        | `<Delete delete><DeleteTrigger objectKey /></Delete>`            |
| `confirmTitle` / `confirmDescription` | `<Delete dialog={<DeleteConfirmDialog title description />}>`    |
| `toast` props, `use*Toast` hooks      | `UploadToasts`, `DownloadToasts`, `DeleteToasts`                 |

```tsx title="components/invoice-actions.tsx"
"use client";

import { useDelete, useDownload } from "@dimah-s3/react";
import {
  Delete,
  DeleteToasts,
  DeleteTrigger,
  Download,
  DownloadToasts,
  DownloadTrigger,
} from "@dimah-s3/ui";

export function InvoiceActions({ objectKey }: { objectKey: string }) {
  const download = useDownload({ route: "invoices" });
  const del = useDelete({ route: "invoices" });

  return (
    <>
      <Download download={download}>
        <DownloadTrigger objectKey={objectKey} />
      </Download>
      <Delete delete={del}>
        <DeleteTrigger objectKey={objectKey} />
      </Delete>
      <DownloadToasts download={download} />
      <DeleteToasts delete={del} />
    </>
  );
}
```

`UploadDropzone` still shows the status inside it. For `status={false}`,
give it only its trigger, and render `UploadStatus` where a `status`
function used to put it:

```tsx
<UploadDropzone>
  <UploadDropzoneTrigger />
</UploadDropzone>
<UploadStatus />
```

Control props such as `buttonClassName` are now plain `Button` props on the
trigger, and tooltips are opt-in through `tooltip`. `FileAttachment` drops
`size` and `orientation`; size it with `className`. See
[Upload](/docs/react/ui/components/upload),
[Download](/docs/react/ui/components/download), and
[Delete](/docs/react/ui/components/delete).

With the shadcn registry, the items `upload-button`, `upload-dropzone`,
`download-button`, `progress-download-button`, and `delete-button` are
replaced by `upload`, `download`, and `delete`. The items need a shadcn
project on a Base UI style.

`AvatarUpload` `onChange` is now `onUploaded`. An icon-size `UploadTrigger`,
`DownloadTrigger`, or `DeleteTrigger` keeps its label for screen readers, so
it needs no `aria-label` of its own.

### Rename theme overrides

Override the `--dimah-s3-*` tokens instead of `--color-dimah-s3-*`, on
`:root` or on any container:

```css title="app/globals.css"
:root {
  --dimah-s3-primary: oklch(0.65 0.15 150);
}
```

The `secondary`, `secondary-foreground`, `accent`, `accent-foreground`, and
`primary-foreground` tokens are removed, with their utilities. Other Tailwind
utilities such as `bg-dimah-s3-card` are unchanged. See
[Theming](/docs/react/ui/customization/theming).

### Update `ObjectList`

- `usageLimits` is removed. Limits come from the source's `usage`.
- The `ObjectListUsage` type from `@dimah-s3/react` is now
  `ObjectListUsageData`. `ObjectListUsage` is the ui component that shows it.
- The context field `remove` is now `delete`, and `onDeleted` receives
  react's `DeleteResult`.
- `useObjectListContext()` returns the list, the selection, the hooks, the
  view, `rootLabel` (was `label`), and the commands `startNewFolder()`,
  `startRename(key)`, and `revealEntry(entry)`. Layout props such as
  `pagination`, `empty`, and the `render*` functions are no longer on it:
  read them from the props you pass to `ObjectList`.
- `ObjectListItemMenu` is now `ObjectListEntryMenu`
  (`ObjectListEntryMenuProps`, `ObjectListEntryMenuAction`). It no longer
  takes `download`, `delete`, or `onDeleted`, and extra rows are
  `ObjectListEntryMenuItem` children. Its button is named after the entry,
  such as "Actions for report.pdf".
- The type `ObjectListPagination` is now `ObjectListPaginationMode`, and
  `ObjectListSearch` `delay` is now `debounceMs`.
- Built-in toasts step aside for your own `UploadToasts`, `DownloadToasts`, or
  `DeleteToasts`. Pass `toasts={false}` to turn them off.
- The entries are one tab stop. An entry's checkbox and menu leave the tab
  order: reach them with Tab from the entry, or with ArrowLeft and
  ArrowRight in the list view. Update tests that tab through the rows.
- `getId` and `getFile` run once per item object. To change what a row
  shows, replace the item with `setItems` or reload.
- `ObjectListRow` and `ObjectListTile` are memoized. A `render*` function
  that reads your own state must change with it, as one from `useCallback`
  does.

## Errors

`S3_ERROR_CODES` is the one error catalog. Every `APIError` has a `code`, a
`statusCode`, and typed `params`. Read details from `error.params`, not from
the message. The `APIError` constructor requires a `code`.

| 1.7                                 | 2.0 beta                                            |
| ----------------------------------- | --------------------------------------------------- |
| `PAYLOAD_TOO_LARGE`                 | `FILE_TOO_LARGE` with `{ size, maxFileSize }`       |
| `INVALID_KEY`                       | `KEY_INVALID`                                       |
| `UNKNOWN_ROUTE`                     | `ROUTE_NOT_FOUND`                                   |
| `QUOTA_EXCEEDED`                    | `QUOTA_EXCEEDED` (403) with `{ limit }`             |
| `APIError.fromStatus(...)`          | `s3Error(code, params)` or `APIError.from`          |
| `DELETE_BATCH_MAX_KEYS`             | `DELETE_MANY_MAX_KEYS`                              |
| `S3_MAX_OBJECT_KEY_LENGTH`          | `S3_MAX_OBJECT_KEY_BYTES` (1024 UTF-8 bytes)        |
| `S3_API_ROUTES.uploadConfirm`       | `S3_API_ROUTES.confirm`                             |
| `S3_API_ROUTES.deleteBatch`         | `S3_API_ROUTES.deleteMany`                          |
| `S3_API_ROUTES.multipartPart`       | `S3_API_ROUTES.multipartSignPart`                   |
| `sha256File`                        | `sha256Blob`                                        |
| `sanitizeFileName`                  | `fitFileName`                                       |
| `buildPublicObjectUrl({ baseUrl })` | `buildPublicObjectUrl({ baseURL })`                 |
| `S3ApiHeaders`                      | Per-call `{ signal, headers }` (`S3RequestOptions`) |

`validateFile` returns `APIError | null`. `isAPIError` and
`isS3ErrorCode(error, code)` match only real `APIError`s, whose `code` and
`params` are set, and `isS3ErrorCode` narrows `params` to that code. The
new `OBJECT_EXISTS` and `FOLDER_EXISTS` (409) replace `CONFLICT` for a key
or folder that is taken; `CONFLICT` now means a concurrent change won. The
full list is on [Errors](/docs/server/errors).

## Custom backends and transports

If you call the HTTP API yourself or wrote an `UploadTransport`:

- File fields are `name`, `size`, and `type` on the wire. The download and
  `/file` query parameter `fileName` is now `name`. The upload and multipart
  init bodies carry the client's extras as `clientMetadata`, not `metadata`.
- `confirm`, `multipart.signPart`, `multipart.listParts`,
  `multipart.complete`, and `multipart.abort` take `{ ticket }`. `listParts`
  is a POST, and `complete` takes no `parts`.
- Multipart init takes no `partSize`. It returns `partSize`, `partCount`, and
  `checksum`, and `signPart` returns the part `size` and the `headers` to send.
- A presigned PUT signs every header it returns. Send `headers` exactly.
- Every `S3Api` method takes `(payload, { signal, headers })`.
- Responses changed shape. Confirm and multipart complete return
  `{ key, bucket, name, size, type, eTag, versionId, lastModified, metadata, acl }`.
  `delete` returns `{ key, bucket }` with no `existed`. `deleteMany` returns
  `{ deleted, failed: { key, error }[] }`. `multipart.abort` returns
  `{ key, bucket, uploadId }`. `download` is a union on `mode`: `expiresIn`
  is set in `"presign"` mode and absent in `"proxy"` mode.
- The route catalog (`catalog()`) has no `upload.replace`, its
  `download.expiresIn` is now `maxExpiresIn`, and `checksum`, `disposition`,
  `inlineTypes`, and `mode` are always present.
- The hooks retry a request whose error has status 408, 429, or 500 and
  above, so `confirm` and `multipart.complete` must be safe to call twice.
- In `@dimah-s3/core`, `DeleteBatchPayload` and `DeleteBatchResponse` are now
  `DeleteManyPayload` and `DeleteManyResponse`. Confirm, listParts, complete, and
  abort all take one `TicketPayload` (`{ ticket }`), validated by
  `ticketBodySchema`.
- The Zod schemas moved to `@dimah-s3/core/schema`, so the browser entry
  ships without Zod. Import `uploadBodySchema` and the others from there.
  `deleteBatchBodySchema` is now `deleteManyBodySchema`.

See [Custom backend](/docs/react/custom-backend).

## Database

`@dimah-s3/db` reads schema `2.3.0` only: folders are rows with ids, an
object stores `folderId` and its `name`, and each row has typed
`attributes`, an upload token, and its name folded for search and for the
name sort. It does not upgrade a database at any other version, 1.x
included. Create the tables on a new database before you deploy. Any other
version throws.

- Create the tables from [Setup](/docs/db/setup). With Kysely, call
  `migrate(client)` from `@dimah-s3/db` on an empty database.
- Remove `fumadb` and the `fumadb/cuid` path alias from your app.
  Generate the Drizzle tables or Prisma models with `runCli` from
  `@dimah-s3/db/cli`, build the client with `DimahS3Db.client(adapter)`,
  and import adapters from `@dimah-s3/db/adapters/<orm>`.
- Install `@aws-sdk/client-s3` next to `@dimah-s3/db`: it is a required
  peer.
- A row's file name is `name` (`StorageObject.name`, `DbClientObject.name`,
  `PATCH /db/object` `{ name }`, and the sort field `"name"`).
- With Drizzle, upgrade `drizzle-orm` to `1.0.0-rc.5` or later first.
  0.44 and 0.45 are no longer supported. See [Setup](/docs/db/setup).
- `createObjectAccessGuard` and `createQuotaGuard` are replaced by the
  `authorize` and `quota` options.
- `purgeStalePendingObjects` is replaced by `s3.db.purgeStale()` and
  `s3.db.pruneDeleted()`.
- `dbObjectQuery` and `dbObjectListAccessors` are replaced by
  `dbObjectSource(api.db, { route })`.
- `resolveScope` receives only the caller (`request`, `session`, `locals`,
  `operation`, `route`). Move checks on `key`, `folder`, or
  `clientMetadata` into `authorize`, which also gets the stored row.
- In `authorize`, `folder` and `folderId` are where the target is now, for
  every operation on a stored object. A move or a rename reports the new
  place in `destination`. A listing without `folderId` asks for the whole
  scope (`recursive: true`).
- The folder endpoints run with the operations `"folder.create"`,
  `"folder.update"`, and `"folder.delete"`. `"update"` is `PATCH /db/object`
  only, and `s3.db.record` runs with `"record"`.
- Uploads do not create folders: send `clientMetadata.folderId` for a
  folder that already exists.
- `s3.db.objects` keeps `find`, `list(scope, filter)`,
  `count(scope, filter)`, `usage(scope)`, and `update`. Delete files
  through `s3.api.delete`, and prune with `s3.db.pruneDeleted`.
- A scope, a folder name, and a file name may not start or end with
  whitespace.
- `purgeStale` returns `{ purged, failed, skipped, more }`.

[Upgrade the database](/docs/db/upgrade) says what happens to an existing
database.
