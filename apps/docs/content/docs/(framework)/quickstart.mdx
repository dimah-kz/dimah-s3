Scaffold a new app with the CLI, or add dimah-s3 to an existing React app by
hand. Either way you end with an avatar upload that goes straight from the
browser to your bucket.

## Create a new project

```npm
npx @dimah-s3/cli@beta create
```

The CLI asks for the project name, the starter, and whether to install
dependencies and initialize git. It writes a generated `DIMAH_S3_SECRET` to
`.env`. Then fill the `S3_*` values in `.env` and allow your app's origin in
the bucket CORS rules ([provider guides](/docs/providers)).

Flags answer the questions up front, and `--yes` takes the defaults for the
rest:

```bash
npx @dimah-s3/cli@beta create my-app --template vite --no-git --yes
```

| Flag                         | Default                      | Description                                                                                                     |
| ---------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `[dir]`                      | prompt                       | Project directory and package name. `.` uses the current directory. Required with `--yes` or without a terminal |
| `-t, --template <id>`        | `nextjs`                     | `nextjs`, `vite` (React SPA with a Hono API), or `hono` (Hono API that serves a Vite React app)                 |
| `--package-manager <pm>`     | The one that ran the command | `pnpm`, `npm`, `yarn`, or `bun`                                                                                 |
| `--install` / `--no-install` | `--install`                  | Install dependencies                                                                                            |
| `--git` / `--no-git`         | `--git`                      | Initialize a repository with a first commit                                                                     |
| `--src` / `--no-src`         | `--src`                      | Next.js only: keep app code under `src/`, or flatten it to the root                                             |
| `--overwrite`                | off                          | Replace the contents of a non-empty directory. `.git` and `.env` are kept                                       |
| `-y, --yes`                  | off                          | Skip the prompts and use the defaults                                                                           |

The CLI needs Node.js 22 or newer.

## Manual installation

<Callout title="Before you start">
  These steps add dimah-s3 to an existing React 19.2 app on Node.js 22 or newer.
  The server steps work in any framework. The client steps show Next.js App
  Router paths. The UI step also needs Tailwind CSS v4 and a project initialized
  with `shadcn init`, because the components read the shadcn theme variables.
</Callout>

### Install the packages [step]

```npm
npm i @dimah-s3/server@beta @dimah-s3/core@beta @dimah-s3/react@beta @fuma-translate/react @aws-sdk/client-s3
```

Keep every `@dimah-s3/*` package on the same version.

### Configure S3 and a route [step]

```dotenv title=".env"
S3_ENDPOINT="https://your-endpoint.example.com"
S3_REGION="auto"
S3_ACCESS_KEY_ID="your-access-key-id"
S3_SECRET_ACCESS_KEY="your-secret-access-key"
S3_BUCKET="your-bucket-name"

# Signs upload tickets. Generate one with: openssl rand -base64 32
DIMAH_S3_SECRET="your-generated-secret"
```

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  region: process.env.S3_REGION,
  endpoint: process.env.S3_ENDPOINT,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
  },
  // The SDK default (WHEN_SUPPORTED) breaks presigned uploads.
  requestChecksumCalculation: "WHEN_REQUIRED",
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024, // 2MB
      },
      download: true,
    }),
  },
});
```

<Callout title="Upload secret">
  `dimahS3()` reads `DIMAH_S3_SECRET` to sign [upload
  tickets](/docs/server/upload-tickets). Use at least 32 characters and the same
  value on every server instance, or pass `secret` yourself. When it is missing,
  `development` and `test` fall back to a random secret with a warning; anywhere
  else, uploads return `500`.
</Callout>

### Allow your origin in bucket CORS [step]

The browser uploads straight to the bucket, so the bucket must allow your
app's origin and the upload method. Follow your provider's guide:
[Amazon S3](/docs/providers/aws-s3),
[Cloudflare R2](/docs/providers/cloudflare-r2),
[MinIO](/docs/providers/minio), or
[ArvanCloud](/docs/providers/arvancloud).

### Mount the route handler [step]

<Tabs items={["Next.js", "Vite", "Express", "Hono", "SvelteKit"]}>

<Tab value="Next.js">

```ts title="app/api/s3/[...s3]/route.ts"
import { toNextJsHandler } from "@dimah-s3/server/next";
import { s3 } from "@/lib/s3";

export const { GET, POST, PUT, PATCH, DELETE } = toNextJsHandler(s3);
```

<Callout title="Cache Components">
  Next.js 16.4 enables Cache Components on new apps. This handler reads the
  request, so it runs on each request. Keep the handler as written. [Server
  Setup](/docs/server/setup) explains why it must stay uncached.
</Callout>

</Tab>

<Tab value="Vite">

Vite serves the page only, so the handler runs in a small API server next to
it. This one uses Hono:

```ts title="server/index.ts"
import { Hono } from "hono";
import { toHonoHandler } from "@dimah-s3/server/hono";
import { s3 } from "./s3";

const app = new Hono();
app.on(
  ["GET", "POST", "PUT", "PATCH", "DELETE"],
  "/api/s3/*",
  toHonoHandler(s3),
);
```

The client calls `/api/s3` on the page's own origin. In development, proxy
that path from the Vite dev server to the API server:

```ts title="vite.config.ts"
export default defineConfig({
  server: {
    proxy: {
      "/api": { target: "http://127.0.0.1:8787", changeOrigin: true }, // [!code ++]
    },
  },
});
```

</Tab>

<Tab value="Express">

```ts title="server.ts"
import express from "express";
import { toExpressHandler } from "@dimah-s3/server/express";
import { s3 } from "./s3";

const app = express();
// The adapter reads the raw stream, so mount it before JSON middleware.
app.use("/api/s3", toExpressHandler(s3));
app.use(express.json());
```

</Tab>

### Add an upload button [step]

      </Upload>

Pick a file: the server presigns it, the browser uploads it to your bucket,
and the server confirms it. `UploadToasts` reports progress, success, and
errors for this hook. [Upload](/docs/ui/components/upload) adds a dropzone and
status parts.

### Type your route names [step]

Optional. Declare the server's routes once, and every hook and component
checks and completes `route`:

```ts title="lib/s3-routes.ts"
import type { InferS3Routes } from "@dimah-s3/core";
import type { s3 } from "@/lib/s3";

declare module "@dimah-s3/core" {
  interface DimahS3Routes extends Record<InferS3Routes<typeof s3>, true> {}
}
```

## Frequently asked questions

<Accordions>

<Accordion title="How do I restrict uploads to signed-in users?">

Add a `guard` to the route, or to the instance for every route. Throw
`s3Error("UNAUTHORIZED")` or `s3Error("FORBIDDEN")` to refuse the call:

```ts title="lib/s3.ts"
import { dimahS3, route, s3Error } from "@dimah-s3/server";

export const s3 = dimahS3({
  // ...
  routes: {
    avatar: route({
      guard: async ({ request }) => {
        const session = await getSession(request);
        if (!session) throw s3Error("UNAUTHORIZED");
      },
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
      },
    }),
  },
});
```

See [Global guard](/docs/server/hooks/global-guard).

</Accordion>

<Accordion title="How do I save the uploaded key to my database?">

On the server, use `onConfirmed`. It runs after `HeadObject` verified the
stored object. It can run more than once for one upload, so make the write
idempotent:

```ts title="lib/s3.ts"
avatar: route({
  upload: {
    fileTypes: ["image/*"],
    maxFileSize: 2 * 1024 * 1024,
    onConfirmed: async ({ key, request }) => {
      const session = await getSession(request);
      if (!session) return;
      await db.user.update({
        where: { id: session.userId },
        data: { avatarKey: key },
      });
    },
  },
}),
```

In a form, `onSuccess` runs once per confirmed file. Put the key in form state
and submit it to your own API:

```tsx
const upload = useUpload({
  route: "avatar",
  onSuccess: (result) => setValue("avatarKey", result.key),
});
```

</Accordion>

<Accordion title="How do I show the uploaded image?">

The route needs `download: true`. [`useObjectUrl`](/docs/react/hooks/object-url)
signs a short-lived URL that opens inline. For a public bucket or a CDN, build
the URL with `buildPublicObjectUrl` from [`@dimah-s3/core`](/docs/core#helpers)
instead.

```tsx title="components/avatar-preview.tsx"
"use client";

import { useObjectUrl } from "@dimah-s3/react";

export function AvatarPreview({ avatarKey }: { avatarKey: string }) {
  const { url } = useObjectUrl({ route: "avatar", objectKey: avatarKey });

  if (!url) return null;
  return (
    <img
      src={url}
      alt="User avatar"
      className="size-16 rounded-full object-cover"
    />
  );
}
```

</Accordion>

</Accordions>
