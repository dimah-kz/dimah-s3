title: Migration
description: Breaking changes from 0.x to 1.0.
icon: ArrowRightLeft
---

1.0 is a **major** for consumer DX. The presign protocol is the same. Package
boundaries (`core` ← `server` | `react` ← `ui`) are the same.

## Server config

| 0.x                                             | 1.0                                               |
| ----------------------------------------------- | ------------------------------------------------- |
| `s3: awsClient`                                 | `client: s3Sdk`                                   |
| `defaultBucket`                                 | `bucket` (still the default; see below)           |
| `upload: { enabled: true }`                     | `upload: true` or `upload: { prefix: "uploads" }` |
| `upload.presignGuard` / `download.presignGuard` | `upload.guard` / `download.guard`                 |
| Disabled feature → generic `NOT_FOUND`          | `FEATURE_DISABLED` (still HTTP 404)               |
| Client `bucket` always accepted                 | Ignored unless `allowClientBucket` or `buckets`   |

Multipart is on whenever `upload` is on, unless you set `multipart: false`.

Env in starters: `S3_DEFAULT_BUCKET` → `S3_BUCKET`. Keep the AWS SDK instance
as `export const s3Sdk` and pass `client: s3Sdk` — `s3Client` is the React
browser client. `bucket` is the default bucket: hooks may send `bucket`, but
the server ignores it unless you set `allowClientBucket` or `buckets`.

Key policy:

```ts
export const s3Sdk = new S3Client({/* env */});

export const s3 = dimahS3({
  client: s3Sdk,
  bucket: process.env.S3_BUCKET!,
  upload: {
    prefix: "uploads",
    // or resolveKey: ({ key, request }) => `user/${id}/${key}`,
    guard: async ({ key }) => {
      /* auth / quota */
    },
  },
});
```

A plain `Error` in `guard` → **403**. The same throw in `on*` → **500**.

`s3.api.multipart.init` is an alias of `s3.api.multipartInit`. Plugin-author
helpers (`chainHooks`, hook context types) live on
`@dimah-s3/server/plugins`.

Keep plugins **inline** or `as const` so `s3.db` stays typed.

## React client

```ts
// 0.x
export const { api, S3Provider, useApi } = createS3Client();
<S3Provider>{children}</S3Provider>
api.download(key)

// 1.0
export const s3Client = createS3Client();
s3Client.download(key)
// Vite / Hono: <s3Client.Provider>
// Next.js App Router: export const S3Provider = s3Client.Provider
```

`createS3Client` comes from `@dimah-s3/react` (not `@dimah-s3/server`).
`@dimah-s3/react` re-exports `DimahS3Error`, `isS3ErrorCode`, helpers, and
`S3Api`.

- `objectKey` is optional — default `` `${uuid}/${file.name}` ``
- `useFetchDownload` → `useDownload({ mode: "fetch" })` (default `"navigate"`)
- Hook `error` is `DimahS3Error | null` (use `error.message` or
  `useFormatDimahError(error)`)
- `S3Context` is no longer a public export
- Cross-origin: `createS3Client({ baseURL })`

Templates no longer wrap the provider in `S3ClientProvider`.
