dimah-s3 is a modular, full-stack S3 toolkit for React and Node.js. It
provides typed server routes, headless React hooks, optional shadcn UI, and a
database plugin for object tracking when your application needs it.

<Callout title="Upgrading from 1.x?">
  Follow [Upgrade to 2.0](/docs/migration-2-0). 1.x is no longer maintained, and
  its docs stay at [v1.s3.dimah.dev](https://v1.s3.dimah.dev/docs).
</Callout>

## Architecture flow

<Flow

The server signs a short-lived URL, the browser talks to your bucket, and S3
credentials never leave the server. Downloads use a signed URL, or pass
through your server as a [file proxy](/docs/server/file-proxy).

## What you get

- **Fast setup** — a working upload in minutes, or a starter from the [CLI](/docs/cli)
- **Full stack** — server, client, and optional shadcn UI
- **Full lifecycle** — upload, download, and delete, including multipart
- **Server hooks** — auth, quotas, confirm, and cleanup on the server
- **Optional database** — ownership, folders, and listings when you need them

It is not an S3 SDK wrapper. List, copy, tagging, and other operations stay
in your own code with the
[AWS SDK](https://www.npmjs.com/package/@aws-sdk/client-s3). Server-side
uploads (`s3.put`) and the file proxy are the exceptions.

Keep every `@dimah-s3/*` package on the same version.

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-s3?">

When you own the S3-compatible bucket and need more than an upload picker:
server-owned keys, verified confirmation, private downloads, guarded
deletion, multipart resume, or optional database tracking.

If you are choosing between managed storage, an upload-focused toolkit, or a
client uploader, use the [comparison guide](/docs/comparison).

</Accordion>

<Accordion title="Does dimah-s3 replace the AWS SDK?">

No. dimah-s3 covers presign upload, download, and delete, plus server-side
uploads (`s3.put`) and the download proxy. Use the AWS SDK for everything
else — list, copy, retention, tagging, and similar work.

</Accordion>

<Accordion title="Can I use dimah-s3 with Cloudflare R2, MinIO, or ArvanCloud?">

Yes. Pass an AWS SDK `S3Client` configured for the provider. Uploads use
presigned PUT by default, which R2 and MinIO support. MinIO on a host and
port needs `forcePathStyle: true`. ArvanCloud needs `upload.method: "POST"`.
The [provider guides](/docs/providers) cover endpoints and CORS.

</Accordion>

<Accordion title="How does dimah-s3 keep S3 credentials secure?">

The browser sends a route name. It never sends an object key or a credential.
The server runs its guards, chooses a key inside that route's namespace, and
returns a short-lived signed URL with a signed
[upload ticket](/docs/server/upload-tickets). On confirm, the server checks
the stored object with `HeadObject` before your
[`onConfirmed`](/docs/server/hooks/upload) hook runs.

</Accordion>

<Accordion title="Does dimah-s3 support resumable multipart uploads?">

Yes. Turn on `upload.multipart` on the route. The server picks the part
layout, and the client uploads parts in parallel with retries, cancellation,
and per-part SHA-256 checks when the route asks for them. Add a persistent
[`UploadStore`](/docs/react/upload-store); after a reload, the user reselects
the same local file and the client resumes.

</Accordion>

</Accordions>
