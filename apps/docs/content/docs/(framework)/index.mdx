dimah-s3 is a modular, full-stack S3 toolkit for React and Node.js runtimes.
It provides typed server handlers, headless React hooks, optional shadcn UI components,
and a database plugin for object tracking when your application needs it.

<Callout title="2.0 beta">
  This site documents the 2.0 beta. Install with the `beta` dist-tag. A new beta
  ships every few days and can include breaking changes until 2.0.0. Stable 1.x
  stays at [v1.s3.dimah.dev](https://v1.s3.dimah.dev/docs). Moving a 1.7 app: [Upgrade
  to 2.0 beta](/docs/migration-2-0).
</Callout>

The backend signs a short-lived URL, the browser talks to your bucket, and
AWS credentials never leave the server. Downloads can also pass through
your server as a proxy.

## What you get

- **Fast setup** — a working upload in minutes
- **Full stack** — server, client, and optional shadcn UI
- **Full lifecycle** — upload, download, and delete, including multipart
- **Server hooks** — auth, quotas, confirm, and cleanup on the server ([Better Auth](https://www.better-auth.com)-like)
- **Optional database** — ownership and listings when you need them

It is not an S3 SDK wrapper. List, copy, tagging, and other operations stay
in your own code with the
[AWS SDK](https://www.npmjs.com/package/@aws-sdk/client-s3).

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-s3?">

When you own the S3-compatible bucket and need more than an upload picker:
server-owned keys, verified confirmation, private downloads, guarded
deletion, multipart resume, or optional database tracking.

If you are choosing between managed storage, an upload-focused toolkit, or a
client uploader, use the [comparison guide](/docs/comparison).

</Accordion>

<Accordion title="Does dimah-s3 replace the AWS SDK?">

No. dimah-s3 covers presign upload, download, and delete. Use the AWS SDK
for everything else — list, copy, retention, tagging, and similar work.

</Accordion>

<Accordion title="Can I use dimah-s3 with Cloudflare R2 or MinIO?">

Yes. Configure an AWS SDK `S3Client` for the provider. Uploads use presigned
PUT by default, which R2 supports; MinIO commonly needs `forcePathStyle: true`.
See the [provider guides](/docs/providers) for endpoints and CORS.

</Accordion>

<Accordion title="How does dimah-s3 keep S3 credentials secure?">

The browser sends a route name. The server runs guards, chooses a key
inside that route's namespace, and returns a short-lived signed request with
a signed [upload ticket](/docs/server/upload-tickets). Confirm accepts only
uploads the server started, and credentials never leave the server.

</Accordion>

<Accordion title="Does dimah-s3 support resumable multipart uploads?">

Yes. The server picks the part layout, and the client uploads parts in
parallel with retries, cancellation, and per-part SHA-256 checks when the
route asks for them. Add a persistent `UploadStore`; after a reload, the user
reselects the same local file and the client resumes. See
[Upload Store](/docs/react/upload-store).

</Accordion>

</Accordions>
