dimah-s3 adds file upload, download, and delete to a React app, against an
S3-compatible bucket you own. Use it when files go straight from the browser
to the bucket and your server must stay in control of keys, permissions, and
verification.

<Callout title="2.0 beta">
  This site documents the 2.0 beta. Install with the `beta` dist-tag. A new beta
  ships every few days and can include breaking changes until 2.0.0. Stable 1.x
  stays at [v1.s3.dimah.dev](https://v1.s3.dimah.dev/docs). Moving a 1.7 app:

</Callout>

```ts title="lib/s3.ts"
import { dimahS3, route } from "@dimah-s3/server";

export const s3 = dimahS3({
  client: awsS3, // an AWS SDK S3Client
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      upload: { fileTypes: ["image/*"], maxFileSize: 2 * 1024 * 1024 },
      download: true,
    }),
  },
});
```

```tsx title="app/page.tsx"
"use client";

import { useUpload } from "@dimah-s3/react";
import { Upload, UploadToasts, UploadTrigger } from "@dimah-s3/ui";

export default function Page() {
  const upload = useUpload({ route: "avatar" });

  return (
    <>
      <Upload upload={upload}>
        <UploadTrigger />
      </Upload>
      <UploadToasts upload={upload} />
    </>
  );
}
```

## How it works

<Flow
  label="Presign-first architecture"
  steps={[
    { name: "Browser", kind: "client", note: "requests signed URL" },
    { name: "Server", kind: "server", note: "executes guards and signs URL" },
    { name: "S3 Bucket", kind: "s3", note: "receives the upload" },
  ]}
/>

1. The browser sends a route name and the file's name, size, and type. It
   never sends an object key or a credential.
2. Your server runs its guards, picks the key inside that route's namespace,
   and returns a short-lived signed URL with a signed
   [upload ticket](/docs/server/upload-tickets).
3. The browser uploads the bytes straight to the bucket.
4. The browser confirms with the ticket. The server checks the stored object
   with `HeadObject` before your `onConfirmed` hook runs.

S3 credentials never leave the server. Downloads use a signed URL, or stream
through your server with the [file proxy](/docs/server/file-proxy).

## Packages

| Package                            | Role                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| [`@dimah-s3/server`](/docs/server) | Routes, guards, lifecycle hooks, and framework adapters; signs URLs and verifies uploads |
| [`@dimah-s3/react`](/docs/react)   | Headless hooks for upload, download, delete, and object lists                            |
| [`@dimah-s3/ui`](/docs/ui)         | shadcn components on top of the hooks, as an npm package or registry items               |
| [`@dimah-s3/db`](/docs/db)         | Optional server plugin: object records, ownership, folders, listings, quotas             |
| [`@dimah-s3/core`](/docs/core)     | The protocol: fetch client, error catalog, limits, and shared helpers                    |
| [`@dimah-s3/cli`](/docs/cli)       | Scaffolds a Next.js, Vite, or Hono starter app                                           |

Keep every `@dimah-s3/*` package on the same version.

## What it is not

- **Not an S3 SDK wrapper.** It covers presign upload, download, and delete,
  plus server-side uploads (`s3.put`) and the download proxy. List, copy,
  tagging, retention, and other S3 operations stay in your code with the
  [AWS SDK](https://www.npmjs.com/package/@aws-sdk/client-s3).
- **Not a storage service.** You bring the bucket: Amazon S3, Cloudflare R2,
  MinIO, ArvanCloud, or another S3-compatible
  [provider](/docs/providers).
- **Not an auth library.** You check sessions and quotas in your own
  [guards](/docs/server/hooks/global-guard).

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-s3?">

When you own the bucket and need more than an upload picker: server-owned
keys, verified confirmation, private downloads, guarded deletion, multipart
resume, or database tracking. To weigh it against managed storage or a
client-only uploader, see the [comparison](/docs/comparison).

</Accordion>

<Accordion title="Can I use dimah-s3 with Cloudflare R2, MinIO, or ArvanCloud?">

Yes. Pass an AWS SDK `S3Client` configured for the provider. Uploads use
presigned PUT by default, which R2 and MinIO support. MinIO on a host and port
needs `forcePathStyle: true`. ArvanCloud needs `upload.method: "POST"`. The
[provider guides](/docs/providers) cover endpoints and CORS.

</Accordion>

<Accordion title="Does dimah-s3 support resumable multipart uploads?">

Yes. Turn on `upload.multipart` on the route. The server picks the part
layout, and the client uploads parts in parallel with retries, cancellation,
and per-part SHA-256 checks when the route asks for them. With a persistent
[`UploadStore`](/docs/react/upload-store), the user reselects the same file
after a reload and the upload resumes.

</Accordion>
