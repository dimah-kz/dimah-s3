**dimah-s3** is a modular, full-stack S3 toolkit for React and Node.js
runtimes. It provides typed server handlers, headless React hooks, optional
[shadcn](https://ui.shadcn.com) UI components, and database-backed object
tracking when your application needs it.

It is not a hosted file service or a general S3 SDK wrapper. You keep control
of the bucket and continue to use the
[AWS SDK](https://www.npmjs.com/package/@aws-sdk/client-s3) for operations
outside the upload, download, and delete lifecycle.

## Architecture flow

<Flow
  label="Presign-first architecture"
  steps={[

The backend generates short-lived signed requests. Uploads and, by default,
downloads transfer directly between the browser and S3-compatible storage;
downloads can also use a same-origin proxy. Credentials never leave your
server, while guards and lifecycle hooks keep authorization and trusted side
effects on the backend.

## What you get

- **Typed setup** — named routes connect server policy to React hooks
- **Complete lifecycle** — upload, verified confirmation, download, and delete
- **Large-file support** — multipart transfers, retries, cancellation, and resume
- **Application-owned policy** — auth, quotas, object keys, and cleanup in hooks
- **Optional layers** — shadcn UI and database tracking only when you need them

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-s3?">

Choose dimah-s3 when your application owns an S3-compatible bucket and needs
more than an upload picker: server-owned keys, verified confirmation, private
downloads, guarded deletion, multipart resume, or optional database tracking.

If you are choosing between managed storage, an upload-focused toolkit, or a
client uploader, use the [comparison guide](/docs/comparison).

</Accordion>

<Accordion title="Does dimah-s3 replace the AWS SDK?">

No. dimah-s3 owns presign upload, download, and delete flows. Use the AWS SDK
directly for application-specific operations such as list, copy, retention, or
arbitrary object tagging.

</Accordion>

<Accordion title="Can I use dimah-s3 with Cloudflare R2 or MinIO?">

Yes. Configure an AWS SDK `S3Client` for the provider. Cloudflare R2 upload
routes use `method: "PUT"`; MinIO commonly needs `forcePathStyle: true`.
See the [provider guides](/docs/providers) for endpoints and CORS.

</Accordion>

<Accordion title="How does dimah-s3 keep S3 credentials secure?">

Credentials never leave your server. The browser sends a route name, the
server runs guards and chooses a key inside that route's namespace, and the
browser receives only a short-lived signed request.

</Accordion>

<Accordion title="Does dimah-s3 support resumable multipart uploads?">

Yes. Multipart uploads support chunking, retries, cancellation, and part
reconciliation. Add a persistent `UploadStore`; after a reload, the user
reselects the same local file and the client resumes its stored upload. See
[Upload Store](/docs/react/upload-store).

</Accordion>

</Accordions>
