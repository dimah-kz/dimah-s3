English needs no setup. To localize `@dimah-s3/react` and `@dimah-s3/ui`,
pass a partial translation map and a `locale` to `S3Provider`.

```ts title="lib/translations-fa.ts"
import type { Translations } from "@dimah-s3/react";

export const fa = {
  "Upload failed(toast)": "آپلود ناموفق بود",
  "Cancel(dialog button)": "لغو",
  "MB(file size unit)": "مگابایت",
} satisfies Partial<Translations>; // [!code highlight]
```

```tsx title="app/layout.tsx"
import { S3Provider } from "@/lib/s3-client";
import { fa } from "@/lib/translations-fa"; // [!code ++]

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="fa" dir="rtl">
      <body>
        {/* [!code ++] */}
        <S3Provider translations={fa} locale="fa">
          {children}
        </S3Provider>
      </body>
    </html>
  );
}
```

`S3Provider` is the provider from
[React Setup](/docs/react/setup#1-create-the-client).

## Translate strings

- A key is the English text, then its context in parentheses:
  `"Upload failed(toast)"`. `Translations` lists every key in
  `@dimah-s3/react` and `@dimah-s3/ui`. Missing keys stay English.
- `satisfies Partial<Translations>` flags a key that does not exist, so a
  renamed key shows up as a type error when you upgrade.
- Keep placeholders such as `{name}` and `{count}` in your text. They are
  filled in when the string renders.
- `S3Provider` extends any `TranslationProvider` from `@fuma-translate/react`
  above it, and its own `translations` win.

## Format numbers, sizes, and dates

With `locale`, sizes, counts, progress, and dates use that locale's digits.
Without it, they use Latin digits and English dates, whatever the browser's
language.

- Unit labels are keys in the same map, such as `"MB(file size unit)"`. With
  the map above, sizes read `۱۲٫۴ مگابایت`.
- Accepted-type groups under a dropzone are keys too, such as
  `"Images(file type group)"` for `image/*`. Extensions and MIME types read as
  they are, such as `PDF`.
- Your own components get the same output from the `useFormat*` hooks, such as
  `useFormatFileSize()`. See [Helpers](/docs/react/helpers#formatter-hooks).

## API errors

The server always responds in English. Every error carries a catalog `code`
and its `params`, such as `{ size, maxFileSize }` for `FILE_TOO_LARGE`, so the
client builds its own message in the provider `locale`.

- `@dimah-s3/ui` localizes errors with the same `translations` map.
- Headless hooks expose the original `APIError`. Pass it to
  [`useFormatError`](/docs/react/helpers#errors) before you render it:

```tsx title="components/upload-error.tsx"
"use client";

import { useFormatError, type UseUploadReturn } from "@dimah-s3/react";

export function UploadError({ upload }: { upload: UseUploadReturn }) {
  const formatError = useFormatError();
  if (!upload.error) return null;
  return <p role="alert">{formatError(upload.error)}</p>;
}
```
