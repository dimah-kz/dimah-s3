---
title: Cloudflare R2
description: PUT uploads, endpoint, and CORS for Cloudflare R2.
---

R2 speaks enough of the S3 API to work with dimah-s3, but it is not a
drop-in Amazon S3. Two gaps matter for uploads: no Presigned POST, and no
object ACL.

Start from the [Quickstart](/docs/quickstart) client, then apply the
settings below.

## Upload method

R2 rejects Presigned POST. Set `method: "PUT"`:

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({/* env */});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    uploads: route({
      upload: {
        method: "PUT", // R2 does not accept Presigned POST
      },
      download: true,
      delete: true,
    }),
  },
});
```

<Callout type="warn" title="Leaving the default POST">
  This is the most common R2 failure with dimah-s3. The presign succeeds; the
  browser upload does not.
</Callout>

## Endpoint

Fill the Quickstart env vars with R2 values:

- `S3_REGION=auto`
- `S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`

Create an API token with Object Read & Write in the Cloudflare dashboard.

## CORS

A valid presigned URL is not enough. Without a CORS policy on the bucket,
the browser still blocks the upload:

```json
[
  {
    "AllowedOrigins": ["https://your-app.example"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "Content-Type"],
    "MaxAgeSeconds": 3000
  }
]
```

Headers on the real request must match what was signed. A mismatched
`Content-Type` often shows up as a 403.

## Public access

R2 ignores object ACL. To serve files publicly, turn on bucket public
access or attach a custom domain / `*.r2.dev` URL. Otherwise keep the
bucket private and use presigned download. Leave `resolveObjectAcl` off.

See Cloudflare's [R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)
for the full compatibility matrix.
