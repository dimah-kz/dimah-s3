ArvanCloud Object Storage works with dimah-s3 end to end: upload, confirm,
download, and delete. Two things differ from Amazon S3: uploads must use
presigned POST, and the host the SDK talks to is not the host that serves
public files.

<Callout title="Tested">
  This setup ran against a live ArvanCloud bucket in a real dimah-s3 2.0 beta
  app: presigned POST uploads (private and `public-read`), HeadObject confirm,
  presigned downloads, and delete.
</Callout>

## Settings

| Setting                      | Value                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| `region`                     | `"auto"`                                                                                   |
| `endpoint`                   | The region's API host that accepts POST, such as `https://hot.ir-central1.arvanstorage.ir` |
| `forcePathStyle`             | `true`                                                                                     |
| `followRegionRedirects`      | `true`                                                                                     |
| `requestChecksumCalculation` | `"WHEN_REQUIRED"`                                                                          |
| `upload.method`              | `"POST"` on every upload route                                                             |

## Server configuration

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  region: "auto",
  endpoint: process.env.ARVAN_ENDPOINT, // https://hot.ir-central1.arvanstorage.ir
  forcePathStyle: true, // [!code ++]
  followRegionRedirects: true,
  credentials: {
    accessKeyId: process.env.ARVAN_ACCESS_KEY_ID!,
    secretAccessKey: process.env.ARVAN_SECRET_ACCESS_KEY!,
  },
  requestChecksumCalculation: "WHEN_REQUIRED", // [!code ++]
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.ARVAN_BUCKET!,
  routes: {
    avatar: route({
      upload: {
        method: "POST", // [!code ++]
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
      },
    }),
  },
});
```

## Bucket CORS

The browser posts the file straight to ArvanCloud, so the bucket must allow
your origin and `POST`. Add the rule in the bucket's CORS settings in the
ArvanCloud panel, or send it with `PutBucketCors`:

```json title="cors.json"
{
  "CORSRules": [
    {
      "AllowedOrigins": ["https://your-app.example"],
      "AllowedMethods": ["GET", "POST", "HEAD"],
      "AllowedHeaders": ["*"],
      "ExposeHeaders": ["Content-Disposition", "Content-Encoding"],
      "MaxAgeSeconds": 3000
    }
  ]
}
```

```bash
aws s3api put-bucket-cors \
  --endpoint-url https://hot.ir-central1.arvanstorage.ir \
  --bucket your-bucket \
  --cors-configuration file://cors.json
```

Add `http://localhost:3000` on a development bucket only.

## Provider notes

### Uploads use POST

ArvanCloud rejects presigned PUT uploads, and `upload.method` defaults to
`"PUT"`. A route without `method: "POST"` presigns fine, then fails in the
browser. Hooks and `@dimah-s3/ui` read the method from the presign response,
so the client needs no change.

### Use the API host that does not redirect

In `ir-central1`, `s3.ir-central1.arvanstorage.ir` answers a POST with a `301`
to `hot.ir-central1.arvanstorage.ir`. A browser form upload cannot follow that
redirect, so the upload fails. Set `endpoint` to the host that accepts the
POST directly.

### Public URLs

The `S3Client` `endpoint` is the API host, used path-style. Presigned
downloads come from the `S3Client`, so they use it on their own. Public reads
use the bucket's `.s3.` virtual host, or your custom domain or CDN.

For files anyone may read, set `upload: { method: "POST", acl: "public-read" }`
on the route, or make the bucket public. Then build URLs from the public base
and the server-issued key:

```bash title=".env"
ARVAN_ENDPOINT=https://hot.ir-central1.arvanstorage.ir
ARVAN_PUBLIC_BASE_URL=https://your-bucket.s3.ir-central1.arvanstorage.ir
```

[`buildPublicObjectUrl`](/docs/core#helpers) joins that base and the key and
encodes the key. A custom domain or CDN in front of the bucket goes in the
same variable.

Do not serve files from `your-bucket.hot.ir-central1.arvanstorage.ir`. That
host redirects in a loop, and the Next.js image optimizer returns `508`.

### Multipart uploads

Multipart parts are presigned PUT requests, and the tested setup covers single
uploads only. Leave `upload.multipart` off on ArvanCloud routes, or test a
multipart upload against your bucket before you turn it on. One presigned POST
takes up to 5 GiB.

## Troubleshooting

<Accordions>

<Accordion title="Presign succeeds, then the upload fails">

- The route must set `upload.method: "POST"`. ArvanCloud rejects the default
  PUT.
- `endpoint` must be the API host that accepts the POST, not one that
  redirects it. The browser cannot follow a `301` on a form upload, so the
  request ends as a network error.
- The bucket CORS rule must allow your origin and `POST`. A missing rule also
  shows up as a network error.

</Accordion>

<Accordion title="Public images return 508 in Next.js">

The URL uses the `hot.` host, which redirects in a loop. Build public URLs
from the bucket's `.s3.` virtual host or your own domain, as
[Public URLs](#public-urls) shows.

</Accordion>

</Accordions>

More symptoms: [Troubleshooting](/docs/providers#troubleshooting).
