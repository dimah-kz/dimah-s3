---
title: Amazon S3
description: Connect dimah-s3 to an Amazon S3 bucket, allow browser uploads in bucket CORS, and serve public files.
---

Amazon S3 supports everything dimah-s3 uses: presigned PUT and POST, object
ACLs, SHA-256 checksums, and multipart uploads. Set the region and
credentials, then allow your app's origin in bucket CORS.

## Settings

| Setting                      | Value                                    |
| ---------------------------- | ---------------------------------------- |
| `region`                     | The bucket's region, such as `us-east-1` |
| `endpoint`                   | Leave unset                              |
| `forcePathStyle`             | Leave unset                              |
| `requestChecksumCalculation` | `"WHEN_REQUIRED"`                        |
| `upload.method`              | `"PUT"` (default) or `"POST"`            |

## Server configuration

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  region: process.env.S3_REGION!,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
  },
  requestChecksumCalculation: "WHEN_REQUIRED", // [!code ++]
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      upload: {
        fileTypes: ["image/*"],
        maxFileSize: 2 * 1024 * 1024,
      },
    }),
  },
});
```

AWS SDK versions from 3.729 default to `"WHEN_SUPPORTED"`, and dimah-s3
refuses to presign with such a client. See
[Set the checksum mode](/docs/providers#set-the-checksum-mode).

## Bucket CORS

In the S3 console, open the bucket's **Permissions** tab and edit
**Cross-origin resource sharing (CORS)**:

```json
[
  {
    "AllowedOrigins": ["https://your-app.example", "http://localhost:3000"],
    "AllowedMethods": ["GET", "PUT", "POST", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["Content-Disposition", "Content-Encoding"],
    "MaxAgeSeconds": 3000
  }
]
```

`PUT` covers the default upload method and multipart parts. `POST` is needed
only on routes with `upload.method: "POST"`.
[Allow your origin in bucket CORS](/docs/providers#allow-your-origin-in-bucket-cors)
explains each field.

## Provider notes

### Public files

If the bucket allows object ACLs, set `acl: "public-read"` on the route:

```ts
avatar: route({
  upload: {
    acl: "public-read", // [!code ++]
    fileTypes: ["image/*"],
    maxFileSize: 2 * 1024 * 1024,
  },
}),
```

New S3 buckets commonly use **Bucket owner enforced** Object Ownership, which
disables ACLs. For those buckets, keep uploads private and grant public reads
through a bucket policy or a CDN. Build the URLs with
[`buildPublicObjectUrl`](/docs/core#helpers).

## Troubleshooting

<Accordions>

<Accordion title="The upload fails with a 403 or a CORS error">

- `AllowedOrigins` must match the browser origin exactly, including the scheme
  and the development port.
- `AllowedMethods` must include the upload method: `PUT`, or `POST` on a
  `method: "POST"` route.
- A presigned PUT sends metadata, checksum, and tag headers, so
  `AllowedHeaders: ["*"]` is the simplest rule.
- `403` with `SignatureDoesNotMatch` means the client changed or dropped a
  header. A custom client must send exactly the `headers` from the presign
  response.

</Accordion>
