dimah-s3 talks to storage through the AWS SDK `S3Client`, so it works with any
service that speaks enough of the S3 API. The browser sends files straight to
the bucket, so the bucket's CORS rules and the upload method must match what
the provider supports.

```ts title="lib/s3.ts"
import { S3Client } from "@aws-sdk/client-s3";
import { dimahS3, route } from "@dimah-s3/server";

export const awsS3 = new S3Client({
  // region, endpoint, credentials: see your provider's guide
  requestChecksumCalculation: "WHEN_REQUIRED", // [!code ++]
});

export const s3 = dimahS3({
  client: awsS3,
  bucket: process.env.S3_BUCKET!,
  routes: {
    avatar: route({
      // Only for a provider without presigned PUT, such as ArvanCloud
      upload: { method: "POST" },
    }),
  },
});
```

## Compare providers

|                   | [Amazon S3](/docs/providers/aws-s3) | [Cloudflare R2](/docs/providers/cloudflare-r2) | [MinIO](/docs/providers/minio) | [ArvanCloud](/docs/providers/arvancloud) |
| ----------------- | ----------------------------------- | ---------------------------------------------- | ------------------------------ | ---------------------------------------- |
| Presigned PUT     | Yes (default)                       | Yes (default)                                  | Yes (default)                  | No                                       |
| Presigned POST    | Yes                                 | No                                             | Yes                            | Yes (required)                           |
| Object ACL        | Yes, off on new buckets             | Ignored                                        | Use bucket policies            | Yes                                      |
| `endpoint`        | Optional                            | Required                                       | Required                       | Required                                 |
| `forcePathStyle`  | Usually off                         | Off                                            | On for a host-and-port URL     | On                                       |
| Where to set CORS | Bucket CORS configuration           | R2 dashboard                                   | `MINIO_API_CORS_ALLOW_ORIGIN`  | Bucket CORS settings or `PutBucketCors`  |

For another S3-compatible service, start from the closest guide and check each
row against the provider's docs.

## Set the checksum mode

Every `S3Client` you pass to dimah-s3 must set
`requestChecksumCalculation: "WHEN_REQUIRED"`. From AWS SDK 3.729 the default
is `"WHEN_SUPPORTED"`, which signs a checksum of an empty body into the
presigned URL, so every upload fails at the bucket.

The server checks each client before its first presign. Any other value is
logged as a config error, and the request returns `500 INTERNAL_ERROR`.

## Allow your origin in bucket CORS

Every provider's CORS rule needs the same four parts:

| Field           | Value                                     | Why                                                                                                                  |
| --------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Allowed origins | Your app's exact origin                   | Scheme, host, and port must match. Allow `http://localhost:3000` on a development bucket only                        |
| Allowed methods | `PUT` or `POST`, plus `GET` and `HEAD`    | Uploads use the route's `upload.method`. Multipart parts are always `PUT`. `GET` lets `useFetchDownload` read a file |
| Allowed headers | `*`                                       | A presigned PUT signs type, disposition, metadata, ACL, tag, storage class, and checksum headers                     |
| Exposed headers | `Content-Disposition`, `Content-Encoding` | `useFetchDownload` reads the saved file name and whether the body is encoded                                         |

The bucket never needs `DELETE`, since delete runs on your server. Uploads read
no response header, so `ETag` need not be exposed.

## Choose the upload method

`upload.method` sets the presign verb per route, `"PUT"` by default. Set
`method: "POST"` for a provider that rejects presigned PUT, such as
[ArvanCloud](/docs/providers/arvancloud). Never set it on Cloudflare R2.

Change it on the server only. Hooks and `@dimah-s3/ui` read the method from
the presign response.

## Make files public

Uploads are private unless the route's `acl` or `upload.object` sets
`"public-read"`, which works only on a provider with object ACLs. Otherwise,
make reads public with a bucket policy, a public bucket, or a CDN. Then build
each URL from that public base and the server-issued key:

```ts
import { buildPublicObjectUrl } from "@dimah-s3/core";

const url = buildPublicObjectUrl({
  baseURL: process.env.S3_PUBLIC_BASE_URL!, // your provider's guide has it
  key: result.key, // from the upload result or onConfirmed
});
```

[`buildPublicObjectUrl`](/docs/core#helpers) encodes the key. The `acl` in the
confirm result comes from the route, not from the bucket: on a provider that
ignores ACLs, it can read `public-read` for a private object.

## Troubleshooting

| Symptom                                                    | Fix                                                                                                              |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| The first presign returns `500` and logs the checksum mode | Set `requestChecksumCalculation: "WHEN_REQUIRED"` on the `S3Client`                                              |
| The upload fails with a CORS or network error              | Allow the exact origin and the upload method in bucket CORS                                                      |
| Presign succeeds, then the bucket rejects the upload       | Use a method the provider supports: `PUT` on R2, `POST` on ArvanCloud                                            |
| `403` with `SignatureDoesNotMatch`                         | A custom client changed or dropped a header. Send the presign `headers` exactly. `ExposeHeaders` does not fix it |
| A fetched download is named after its key                  | Expose `Content-Disposition` in bucket CORS                                                                      |
