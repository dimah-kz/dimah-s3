dimah-s3 lets a browser upload straight to the bucket without ever seeing credentials. The signed URL is the permission.

## A route, not a key

The client does not send an object key. It sends a **route name**. The server maps that name to a key — `avatar/{uuid}/{fileName}`, or whatever `object` returns — and signs only that destination.

Auth, quotas, and key layout stay in your hooks. The library does not grow a second place to put them.

## What a signature allows

A presign is a narrow, expiring grant: this method, this key, this content type, until the clock runs out. It is not a session, and it is not a bucket policy. When it expires, the client asks again.

Downloads and deletes follow the same rule. The browser asks your server, your server decides, and storage does the transfer.

## Where the credentials stay

The AWS SDK client lives on the server. A `NEXT_PUBLIC_` access key in the bundle is a leak, not a shortcut. If a value would be dangerous in the page source, it does not belong in the client.

The reference for this model is [Security](/docs/server/security).
